# الهوية والعزل والتفويض

حالة: الصلاحيات المؤسسية معتمدة ضمن الإطلاق في D-18؛ اختير Keycloak وOIDC والجلسات الخادمية وفق D-12. تفاصيل الكتالوج أدناه عقد تصميم قابل للاستكمال قبل التنفيذ.

## مسار التفويض

Authentication→Membership→Tenant Scope→Property Scope→Permission→Resource→Business State. لا تثق بtenant_id من المتصفح أو Webhook. لا استنتاج صلاحية من اسم Role. الأدوار قوالب قابلة للتعديل، والصلاحية granular. العضوية الملغاة تؤثر على الطلبات والوظائف المقبلة؛ الجلسات تحتاج سياسة إبطال.

| الإجراء | صلاحية مقترحة | قيود المورد |
|---|---|---|
| حجز/تعديل/إلغاء | reservation.create/modify/cancel | Property وبنود الحجز |
| تخصيص/نقل | assignment.manage/stay.move | الأصل والبديل والالتزام |
| تركيب | composition.manage | الموارد والتأثير المستقبلي |
| إغلاق مخطط/طارئ | inventory.block/maintenance.emergency | سبب ونطاق وفترة |
| تحصيل/استرداد/تعديل | payment.create/refund، folio.adjust | حدود مبلغ وفصل اعتماد حسب السياسة |
| تقارير وتصدير | report.operational/financial.view/export | فلاتر نطاق إلزامية |
| ملفات حساسة | guest.document.view | حاجة العمل ونطاق الضيف |
| ربط قناة وإعادة معالجة | channel.manage/reprocess | اتصال Property |
| قراءة/رد/تعيين محادثة | communication.read/reply/assign | Property وConnection وConversation وقدرة القناة |
| إدارة قالب أو جدولة | communication.template.manage/schedule | Property وغرض معتمد وحالة الحجز والمستلم |
| إدارة دور | role.manage | منع منح صلاحية أعلى من المخول |

## طبقات الحماية

RLS دفاع إضافي مع تفويض التطبيق. دور التطبيق لا يتجاوز RLS ولا يملك صلاحيات مهاجرات. سياق Tenant/Property يطبق ضمن معاملة وينظف عند إعادة الاتصال إلى pool؛ اختبار يعيد استعمال نفس الاتصال بين عميلين. العلاقات نفسها مقيدة بالنطاق لمنع إدخال مرجع إلى عميل آخر ولو حمت قراءة الصفوف.

Jobs تحمل سياقاً موثوقاً وهوية عملية وصلاحيات خدمة محدودة. Cache key يشمل Tenant/Property والنسخة اللازمة، ولا يتشارك نزلاء عبر العملاء. Search وفهارس التقارير والتصديرات تحترم النطاق. لا أسرار أو مستندات هوية أو تفاصيل دفع خام أو محتوى مراسلات كامل في Logs. صلاحية قراءة الحجز لا تمنح تلقائياً قراءة المحادثة أو الرد عليها.

ملفات خاصة، URLs قصيرة العمر وفق سياسة، وفحص نوع وحجم ومحتوى Upload قبل إتاحته. التحقق عند إنشاء رابط الملف وعند إصدار رابط جديد؛ سحب العضوية لا يضمن إبطال رابط سبق إصداره قبل انتهاء عمره، لذلك تضبط المدة وتستخدم proxy وصول إن لزم الإبطال الفوري.

Sessions/MFA/CSRF/CORS/Rate Limits/Secure Headers/Secrets لها مواصفة حسب Stack المختار. MFA إلزامي للإدارة والمالية وإدارة الاتصالات وفق D-18؛ تحدد سياسات الاستعادة. Auth وWebhook ومزوّد الدفع يعالجان التوقيع/nonce/replay وفق العقد الفعلي. لا تخزن بيانات بطاقات كاملة لمجرد وصولها من قناة؛ مسار التعامل يحدد مع المزود ونطاق الامتثال قبل الاتصال.

## الصلاحيات المؤسسية للإطلاق

RBAC بأدوار قابلة للتهيئة مع شروط النطاق والمورد والحالة. المنع هو الافتراضي. العضوية تربط المستخدم بعميل؛ منح دور يربط الصلاحيات بمنشآت محددة. عند تعدد الأدوار لا تجمع نطاق دور مالي محدود مع صلاحية دور تشغيلي أوسع لتكوين صلاحية جديدة. الرفض الصريح يسبق السماح؛ الوصول لمجموعة منشآت لا يتجاوز Tenant.

| القالب | نطاق العمل الافتراضي | الحدود |
|---|---|---|
| إدارة المنصة | اشتراكات وصحة الخدمات | لا وصول افتراضي لبيانات النزلاء أو المال |
| مالك العميل ومدير المؤسسة | العضويات والأدوار والمنشآت المصرح بها | لا تجاوز ثوابت المخزون أو تعديل مال منشور |
| مدير المجموعة/المنشأة | منشآت محددة أو منشأة واحدة | لا توريث تلقائي لبقية منشآت العميل |
| مدير القنوات والإيرادات | الأسعار وStop Sell والاتصالات | فصل channel.connection.manage وchannel.sale.manage وrate.manage؛ لا استرداد مالي تلقائي |
| موظف الاستقبال | حجز وتخصيص ووصول ومغادرة | حدود الخصم والتعديل والحقول الحساسة وفق الدور |
| المحصل/المحاسب/المدقق | تحصيل أو ترحيل أو تدقيق بحسب الدور | فصل طلب الاسترداد واعتماده؛ المدقق قراءة فقط |
| مشرف التدبير/الصيانة والموظف | موارد ومهام محددة | لا وثائق هوية أو بيانات مالية غير لازمة |

هذه قوالب بدء؛ أسماء الأدوار لا تستخدم شرطاً برمجياً. تعرض شاشة الإدارة مصفوفة الإجراءات والنطاق والصلاحيات الفعلية ومصدر كل منح. التصدير والقراءة الحساسة وإدارة الاتصال والإغلاق الشامل صلاحيات منفصلة. channel.manage القديمة حزمة توافق لصلاحيات محددة وليست تفويضاً شاملاً ضمنياً.

| القاعدة | العقد | القبول غير المنفذ |
|---|---|---|
| SEC-002 | منع تصعيد الصلاحيات | AT-S01: مدير منشأة يحاول منح دور أو نطاق خارج ما يحق له تفويضه؛ رفض في API وتدقيق المحاولة |
| SEC-003 | فصل الطالب والمعتمد | AT-S02: طالب استرداد أو تغيير حساس خاضع لاعتماد يحاول اعتماد طلبه بدور آخر؛ رفض، والموافقة مرتبطة بنسخة الطلب |
| SEC-004 | إبطال فعال | AT-S03: إلغاء العضوية أو سحب الدور يمنع الطلب التالي وJob لم يبدأ؛ لا انتظار لانتهاء JWT قديم |
| SEC-005 | اتحاد أدوار مضبوط | AT-S04: مستخدم مالي في A وتشغيلي في B لا يصل لمال B؛ رفض صريح في A لا يلغيه دور ثانٍ |
| SEC-006 | وصول دعم مؤقت | AT-S05: دعم المنصة بلا منحة لا يقرأ بيانات Tenant؛ منحة مبررة محددة الصلاحيات والمدة تتوقف بانتهائها وتدقق |
| SEC-007 | MFA وإدارة دورة المستخدم | AT-S06: إجراء إداري أو مالي حساس بلا MFA صالح يرفض؛ دعوة منتهية أو مستخدم موقوف لا يدخل |

MFA إلزامي للإدارة والمالية وإدارة الاتصالات. الدعوات محددة النطاق والمدة وقابلة للإلغاء. يمنع تعطيل آخر مسؤول مؤهل دون نقل مسؤولية موثق، وتدقق الاستعادة والتفويض والإبطال. اعتماد مستقل للأفعال الحساسة المدخلة في سياسة المؤسسة، مثل منح إدارة الأدوار والاستردادات فوق الحد والإغلاق الجماعي؛ الحد المالي بالقيمة والعملة ويحدد قبل تشغيل المالية. هذه ضوابط موظفي المؤسسة ولا تضيف موافقات محادثة جديدة للمستخدم.

SSO المؤسسي مدعوم في التصميم عبر Keycloak، لكن تفعيل موفر مؤسسة بعينها يحتاج تهيئة واختباراً. SCIM provisioning ليس شرط الإطلاق الحالي. يحفظ التطبيق نسخ سياسات الوصول؛ Workers تعيد التحقق من المنح عند التنفيذ، بينما تكامل استقبال حجوزات القنوات يستخدم هوية خدمة مستقلة محددة الاتصال ولا يتوقف بفقد عضوية موظف أنشأ الاتصال.

## اختبار إلزامي

رفض Cross-Tenant/Cross-Property في read/write/bulk/export/files/search/jobs/cache؛ تبديل اتصال pooled؛ منع role escalation؛ إبطال جلسة/عضوية؛ تنظيف السجلات؛ حدود الاسترداد والصلاحية؛ Webhook مزور ومكرر؛ Upload خبيث. الوصول الاستثنائي للدعم إن اعتمد يكون مؤقتاً ومبرراً ومراقباً، لا bypass دائم.
