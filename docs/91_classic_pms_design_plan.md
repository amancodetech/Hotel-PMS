# خطة تحسين تجربة وتصميم HOTEL PMS

التاريخ: 19 سبتمبر 2026. الحالة: **نُفذ نظام التصميم وتجربة التنقل في 20 سبتمبر 2026**؛ التفاصيل والأدلة في [92](92_classic_pms_design_implementation.md). توسعة عقد قائمة الحجوزات بالاسم والفترة لم تُنفذ لأنها تغيير API وظيفي مستقل، وبقيت مسجلة أدناه دون طلب N+1 من الواجهة.
طلب المستخدم: تشغيل التحقق المحلي، ثم إعداد خطة شاملة لتصميم احترافي وكلاسيكي مميز للنظام، وترتيب الصفحات والأزرار والجداول وتسلسل الاستخدام.

مرجع نتائج التشغيل: [90 — التحقق المحلي](90_local_verification_2026_09_19.md).
هذه حزم تحسين واجهة UXR وليست مراحل منتج جديدة؛ لا تغيّر P01..P14 أو G-13 أو قرارات D أو النموذج المالي والعزل. تنفيذ التصميم لاحق لطلب الخطة الحالي. لا تبدأ CAP-17 أو حجزاً عاماً أو اتصالاً حياً.

## 1. تشخيص الوضع الحالي

المراجعة مبنية على ملفات الواجهة الفعلية ولقطات محلية محفوظة، وتستكمل بأدلة التشغيل المؤرخة في تقرير 90. اللقطات القديمة مرجع بصري وليست إثبات تشغيل جديد.

## 2. الاتجاه البصري المقترح

الهوية: **دفتر استقبال فندقي كلاسيكي**؛ كحلي حِبري، سطح عاجي خفيف، أبيض للجداول، ونحاس داكن للتأكيد المحدود. شخصية النظام تأتي من سياق المنشأة ويوم العمل وتنظيم الوصول والمغادرة وحالات الغرف، مع خطوط دقيقة وأرقام مقروءة. لا صور زخرفية كبيرة ولا تأثيرات زجاجية في مساحة التشغيل.

| العنصر             | القيمة المقترحة                   | الاستخدام                                            |
| ------------------ | --------------------------------- | ---------------------------------------------------- |
| الحبر الأساسي      | `#182C3A`                         | نص أساسي وزر رئيسي بخط أبيض                          |
| الخلفية            | `#F6F3ED`                         | مساحة العمل                                          |
| السطح              | `#FFFFFF`                         | جداول ونماذج                                         |
| النحاس الداكن      | `#76562D`                         | تأكيد محدود وعناوين مجموعات                          |
| النص الثانوي       | `#52616B`                         | شرح وبيانات مساعدة                                   |
| الحدود             | `#D8D2C8`                         | فصل بصري؛ حدود الإدخال تختبر منفصلة للتباين          |
| نجاح / تحذير / خطر | `#246447` / `#7A5100` / `#A12B34` | نص وأيقونة مع اللون، ولا تعتمد الحالة على اللون وحده |

تُقاس أزواج الألوان الفعلية قبل القبول، بما فيها hover وfocus وdisabled؛ اختيار HEX وحده لا يثبت الإتاحة. هدف النص العادي 4.5:1 والعناصر الرسومية اللازمة 3:1، وفق [مرجع W3C](https://www.w3.org/WAI/WCAG22/quickref/). لا ادعاء امتثال قبل الاختبار.

حساب أولي لهذه الألوان بصيغة luminance لـsRGB: الحبر على الأبيض 14.38:1، وعلى العاجي 12.99:1؛ النحاس على الأبيض 6.69:1؛ النص الثانوي 6.40:1؛ النجاح 7.03:1 والتحذير 6.99:1 والخطر 7.22:1 على الأبيض. الحدود الفاتحة 1.50:1 فقط، لذلك تستخدم للفصل الزخرفي، وتستخدم `#52616B` لحد إدخال لازم لتمييزه أو مؤشر focus. هذه حسابات ألوان مقترحة وليست فحصاً لواجهة منفذة.

الخط الحالي Arial/Tahoma يبقى أساساً متاحاً بلا تنزيل. تُعرض عينة اختيارية لـNoto Sans Arabic مع خط لاتيني متوافق، محلي الاستضافة بعد فحص الترخيص والحجم؛ لا ضرورة لاعتمادية جديدة. عناوين 28/22/18px، متن 14–16px، مساعدة 12–13px، line-height عربي 1.6. الأرقام المالية tabular-nums، والمعرفات مع عزل اتجاه النص. لا خط زخرفي في الجداول.

شبكة مسافات 4، 8، 12، 16، 24، 32px؛ زوايا 6–8px؛ ظل محدود للنوافذ واللوحات العائمة؛ حركة 120–180ms مع احترام reduced-motion. النمط الفاتح هو تسليم البداية، والنمط الداكن ليس شرطاً لهذه الجولة.

## 4. الهيكل والقياسات ومكان الأزرار

رأس الصفحة واحد: breadcrumb صغير، عنوان ووصف قصير في inline-start، وزر المهمة الأساسية في inline-end؛ أي أعلى اليسار بالعربية وأعلى اليمين بالإنجليزية. يلي ذلك تبويبات قليلة ثم شريط البحث والفلاتر ثم المحتوى ثم الترقيم. لا تُكرر أزرار الإنشاء أعلى وأسفل جدول قصير.

زر رئيسي واحد لكل سياق (إنشاء حجز، تسجيل وصول، تحصيل)، وأزرار ثانوية outlined/text. الإجراءات النادرة في قائمة «المزيد». الأفعال الخطرة منفصلة بلون خطر ونافذة توضح الأثر والمبلغ/العملة أو الفترة؛ السبب إلزامي حيث يطلبه المجال. الحفظ داخل النموذج في شريط إجراءات عند نهايته، وثابت فقط في النماذج الطويلة مع حجز مساحة كي لا يحجب الحقول أو focus. ترتيب tab يتبع القراءة؛ Enter لا يؤكد استرداداً أو إغلاقاً خطراً عرضاً.

حالات كل مكون: عادي، hover، focus، مختار، معطل بسبب مفهوم، إرسال، نجاح، فشل، فارغ، ممنوع، بيانات قديمة. التعطيل وحده ليس تفويضاً؛ API يبقى الحاكم. تعرض أخطاء 409/412 إجراء تحديث ومقارنة، ولا إعادة تنفيذ حساسة تلقائية بمفتاح جديد.

## 5. الجداول وحجمها

DataTable مشترك فوق MUI الموجود: عنوان واضح، فلاتر، أعمدة معنونة، فرز مدعوم خادمياً، ترتيب ثابت، loading/empty/error/retry، واستعادة موضع المستخدم. لا تبديل مكتبة أو تثبيت Grid مدفوعة لمجرد التنسيق.

الكثافة العادية: رأس 44px وصف 48–52px، padding أفقي 16px. الكثافة المضغوطة اختيار desktop: رأس 40px وصف 40px؛ تبقى أهداف اللمس 44px عند الإدخال باللمس. نص 14px، ولا تصغير الخط لحشر الأعمدة. الارتفاع حسب عدد الصفوف؛ عند قوائم طويلة مساحة تمرير تقريبية 480–640px تتكيف مع النافذة، ورأس sticky لا يحجب focus. لا صفوف وهمية لاستكمال الارتفاع.

الأعمدة قابلة للنمو وليست عقود بكسل جامدة. المبالغ بمحاذاة رقمية موحدة؛ لا تُقص العملة أو الإشارة. المرجع يمكن نسخه مع الاسم المقروء وعدم عرض UUID كاملاً افتراضياً. الاسم يلتف إلى سطرين أو يظهر كاملاً في التفاصيل؛ tooltip ليس الطريق الوحيد للقراءة. «فتح التفاصيل» رابط أو زر واضح، ولا يعتمد الوصول على نقر الصف فقط.

25 صفاً افتراضياً و50/100 عند دعم الخادم. يجب فحص pagination الفعلية لكل endpoint قبل بناء التحكم؛ لا يُعرض total وهمي ولا فرز محلي مضلل لصفحة من إجمالي أكبر. حالة الفلاتر/التبويب في URL دون بيانات شخصية، وتفضيلات الأعمدة مقيدة بسياق المستخدم والمنشأة.

عند 320–639px: الحجز/المهمة بطاقة ملخص بثلاثة أو أربعة حقول وإجراء واحد؛ المالية والجداول التي تتطلب مقارنة تبقى semantic table داخل منطقة تمرير مسماة، مع تثبيت عمود الهوية إن لم يحجب الباقي. لا تختفي حقول حاسمة بلا طريق واضح لها. اختبار بيانات 0/1/25/100 صف واسم عربي طويل وحجز متعدد العناصر وIDR/USD.

## 6. تسلسل العمل الصحيح

### حجز محلي

اختيار منشأة → تواريخ ونوع/مورد وعدد النزلاء → طلب توفر واقتباس → مراجعة السعر والعملة والسياسات → ربط نزيل بالحد الأدنى من البيانات → إنشاء المسودة والحجز المؤقت وفق العمليات الفعلية → مراجعة → تأكيد ذري → شاشة النتيجة والتفاصيل. العداد يعكس انتهاء Hold من الخادم؛ لا يعد نجاح الواجهة تأكيد مخزون. عند انتهاء Hold يُعاد التحقق. لا عرض ضمني للفيلا وأجزائها كحصة مستقلة متزامنة.

### الوصول والإقامة والمغادرة

قائمة وصول اليوم → تفاصيل الحجز → مراجعة النزلاء والتخصيص وجاهزية الغرفة → تسجيل الوصول. أثناء الإقامة: نقل غرفة وتمديد وتغيير تخصيص كأوامر مجال مستقلة مفسرة. المغادرة: مراجعة الرسوم والتحصيل/الذمة والصلاحية → تأكيد المغادرة → إنشاء مهمة تجهيز عبر السلوك الموجود. حالتا «غادر» و«سدد» منفصلتان دائماً، والخروج بذمة يتبع D-13.

### التحصيل والتصحيح

حجز/حساب → دافع وعملة ورصيد → وسيلة ومبلغ ومرجع → مراجعة → إرسال مرة واحدة → إيصال أو حالة قيد المطابقة. UNKNOWN يقود إلى المطابقة ولا يعرض «ادفع مجدداً». Refund/Reversal/Credit Note أوامر مختلفة مع اعتماد حيث يلزم؛ لا تعديل مباشر لقيد منشور، ولا جمع IDR مع USD.

### القنوات والمخزون

اختيار الاتصال → قراءة الأهلية والحالة → mapping → نطاق الموارد والفترة → فحص Whole/Parts → مراجعة الحصة → إرسال → انتظار الدليل/المطابقة. طلب السحب يبقى معلقاً حتى الإثبات؛ Stop Sell ليس دليلاً وحده على تحرير المورد. توضيح «محاكي محلي / غير مختبر حياً» لكل قناة بحسب الحقيقة. عرض موانع EX للمخولين دون أزرار تفعيل زائفة.

### التدبير والصيانة والتدقيق الليلي

مهمة → تعيين → تنفيذ → فحص → جاهزية؛ الصيانة OOO/OOS منفصلة عن النظافة والإشغال. نهاية اليوم: يوم العمل وتوقيته → قائمة موانع → إصلاح كل مانع في صفحته والعودة → مراجعة الملخص → إغلاق مصرح → نتيجة وتقرير؛ لا إعادة فتح يوم مغلق. صفحة التقارير تعرض أساس المؤشر وفترة التقرير ووقت اللقطة والعملة وعدم خلط الوحدات المركبة.

لا تنشئ الخطة معرفات AT بديلة ولا تغلق بوابات المنتج. مع التنفيذ يُحدّث ربط كل UXR بمعرفات BR/INV/CMP وAT الدقيقة من مصفوفة التتبع قبل تغيير السلوك.

قبول التصميم يتطلب: العربية والإنجليزية والإندونيسية؛ 320/390/768/1024/1440/1920px؛ تكبير 200%؛ keyboard وترتيب focus وإعادته بعد إغلاق النافذة؛ قارئ شاشة للنماذج والجداول والتنبيهات؛ تباين فعلي؛ حالات منع/فراغ/خطأ/تحميل/تعارض/انتهاء جلسة؛ لا تمرير أفقي للصفحة، مع استثناء جداول مقارنة داخل حاوية واضحة. تُراجع أعمدة RTL مع أرقام ومراجع LTR.

تُعاد الأطقم المتأثرة بعد كل حزمة؛ في النهاية `pnpm check` وproperty/identity/distribution وفحوص visual القائمة. لا يُعد نجاح visual الآلي حكماً على جمال الواجهة أو شهادة WCAG. تستكمل السيناريوهات اليدوية بموظف تجريبي: العثور على وصول اليوم، إنشاء حجز اصطناعي، معالجة غرفة غير جاهزة، تسجيل تحصيل، مغادرة بذمة مصرح بها، واستيعاب مانع إغلاق. يقاس عدد الخطوات والأخطاء قبل/بعد، ولا تُعلن نسبة تحسن دون قياس.

التسليم: لقطات قبل/بعد، tokens، مكونات وحالاتها، خريطة تنقل، قائمة تغييرات العقود إن وجدت، نتائج اختبارات، سجل عيوب وحدود معلنة. الرجوع يكون لكل حزمة صغيرة مع حفظ عقود API والمهاجرات الحالية؛ لا إعادة كتابة المشروع.
