# دليل الوصول إلى الربط الحي والتوسع

التاريخ: 13 سبتمبر 2026. خطة المرحلة 13؛ كل اختبار حي حالياً NOT_TESTED وكل اتصال NOT_AUTHORIZED. لا حسابات أو مراسلات أو حجوزات حقيقية أنشئت لإعداد هذه الوثيقة.

المرجع الحاكم [G/EX/AT-C](27_readiness_gates.md)، مع [D-19 وأدلة الاتصال](22_connectivity_evidence.md) و[عقد التوسع](33_channel_extension_contract.md). نجاح الخادم المحلي أو اعتماد PMS لدى المزود لا يغلق قبول كل قناة.

## نقاط يجب إثباتها مع المزود

هذه قائمة أسئلة معدة ولم ترسل. الأجوبة تتحول إلى capability evidence واختبارات لكل اتصال:

1. هل يمكن فصل التوفر وStop Sell للحصة بين القنوات، بما في ذلك كل rate/derived/occupancy/meal variation؟ كيف لا ينعكس تحديث منتج إلى قنوات لم تخصص له الحصة؟
2. كيف يثبت تطبيق إغلاق القناة فعلياً، وما cutoff ودلالة وصول revisions المتأخرة قبل تحرير Exposure؟ قبول المزود وحده غير كافٍ.
3. كيف يضبط auto decrease وauto replenishment على new/modified/cancelled، وهل توجد إعدادات OTA أخرى قد تعيد فتح البيع؟
4. هل تمثيل المورد الثابت لليالي المتصلة والفيلا/الأجزاء والأسرة ممكن بهذا Mapping؟ ما القيود التي يجب فرضها؟
5. ما نطاق تفرد revision/booking IDs ومعنى الترتيب وpagination/retention وACK، وكيف تعاد الحجوزات القائمة والمفقودة بعد انقطاع أو restore؟
6. ما نموذج المبلغ والعملة والضريبة والعمولة والوجبة والإشغال لكل قناة/حساب؟ ما دقة IDR وحدود السعر والأفق والتقييد؟
7. ما سقف rate limits لكل حساب/منشأة/عملية، وكيف تكتشف partial والفشل المتأخر، ومن مسؤول تصعيد الانقطاع؟

لا تغير D-20 بسبب جواب سلبي. يقدم الفريق خيار معالجة محدود ومراجعة قرار إن لزم، ويظل نوع/اتصال غير مؤهل مغلقاً حتى دليل قابل للتحقق. manual proof لا يعني انتظار دقائق ثم افتراض النجاح؛ يتضمن فحص القناة والمراجعة التاريخية والطلبات العالقة ومسؤولاً مسمى.

## حزمة أدلة كل اتصال

أنشئ عند التنفيذ سجلاً `docs/execution/channels/<synthetic-or-safe-connection-ref>.md` بلا بيانات ضيف، مع:

- tenant/property reference آمنة، channel/provider/environment وadapter/profile version ونسخة التطبيق.
- authorization reference ونطاقها وتاريخها، secret_ref فقط، source writer والمسؤول البديل.
- Mapping version وأكواد المنتج/الخطة والعملة والإشغال والوجبات ونوع المورد وWHOLE/PARTS وحدود الأفق.
- CapabilityEvidence مؤرخة وtest-run IDs وحدودها، وخاصة حصرية القناة والسحب والاسترجاع.
- نتائج AT-C وتوقيت المحاولة وrequest/task references المنقاة ودليل تطبيق القناة، وأثر DB والـinventory_version.
- الاستيراد/cutoff والمقارنة، والاستثناءات ومالكها، حدود pilot وموعد/شرط تقييمه، وخطة pause/recovery.

المراجع الحساسة والتفاصيل التشغيلية الكاملة في مستودع أدلة خاص مخول خارج Git، لا raw screenshots لحسابات وضيوف. سجل Git يلخص ويشير إلى دليل مخول فقط. عند الحاجة لإثبات شاشة الإنتاج تنقى النسخة المصدرة دون فقد مرجع أصلها المحمي.

## مصفوفة قبول الخمس

NT = NOT_TESTED. كل خلية تسجل لاحقاً النتيجة ومرجع الاختبار، ولا يكفي وضع علامة صح. PASS بلا connection/environment/profile/test_run لا يقبل. ليس كل نوع مورد مطلوباً على كل قناة، لكن كل نوع معلن عليها يحتاج دليل إضافي.

| الاختبار | tiket | Booking | Agoda | Traveloka | Trip |
|---|---|---|---|---|---|
| AT-C01 حساب وMapping ونطاق | NT | NT | NT | NT | NT |
| AT-C02 جديد/تعديل/إلغاء وأثر واحد | NT | NT | NT | NT | NT |
| AT-C03 فتح/إغلاق ودليل قناة لكل خطة | NT | NT | NT | NT | NT |
| AT-C04 duplicate/out-of-order | NT | NT | NT | NT | NT |
| AT-C05 timeout/429/partial | NT | NT | NT | NT | NT |
| AT-C06 استيراد أولي وتداخل مصادر | NT | NT | NT | NT | NT |
| AT-C07 تداخل/whole-parts/أسرة حسب النطاق | NT | NT | NT | NT | NT |
| AT-C08 استمرار مورد وتمثيل القيود | NT | NT | NT | NT | NT |
| AT-C09 restore ومطابقة قبل زيادة | NT | NT | NT | NT | NT |
| AT-C10 IDR/USD ومعاني المال | NT | NT | NT | NT | NT |

AT-C05/09 واختبارات الأعطال المنهجية تنفذ في بيئة المزود المصرح بها أو harness حدودها موثقة؛ لا تتسبب عمداً في 429 أو outage إنتاجي. الدليل يميز اختبار محاكاة API، واختبار staging حقيقي، والتحقق التشغيلي للقناة. عجز بيئة المزود عن سيناريو يظل فجوة موثقة مع بديل دليل يراجعه المخول؛ لا يستبدل الاختبار الحي سراً بمحاكاة.

تضاف مصفوفة موارد لكل اتصال: room/villa/apartment/bed/site/tent/cabin/house/composite مع حالة DECLARED_AND_TESTED أو NOT_DECLARED أو BLOCKED. يمنع NOT_DECLARED الإعلان والتفعيل لذلك النوع؛ لا يستخدم لإخفاء قناة كاملة لازمة لوعد الخمس. IDR/USD تختبران حسب المنتج والحساب، وتظهر أي قيود تحويل/عملة قبل البيع.

## Runbook تشغيل أول منشأة

1. راجع G-00..12 وEX، وعيّن مسؤول تنفيذ/منشأة/متابعة ومحدد go/no-go. سجل window وcutoff والموارد والقنوات المسموح نشرها.
2. في rehearsal استخدم نسخة منقاة/اصطناعية؛ تحقق من migration وrestore وتصدير خريطة الربط والاستيراد والفروقات، مع rollback للتطبيق المتوافق فقط.
3. قبل cutover فعلي، حدد writer واحداً. نسق وقف زيادات النظام القديم وإغلاق الحصص المنقولة، وتحقق في القنوات لكل خطة ذات صلة. سجل الطلبات العالقة ولا تفتح مخزوناً بالمؤقت.
4. استورد الحجوزات المستقبلية والتعديلات والإلغاءات ذات الصلة وBlocks وأرصدة البداية بمراجعها؛ dry-run ثم تطبيق مصرح. طابق IDs والبنود/الليالي والموارد والعملات والمبالغ، لا عدد السجلات فقط.
5. اسحب revisions في نافذة تداخل قبل cutoff وكرر المطابقة. alias يمنع ازدواج ملف/Feed/مزود قديم. احتفظ بمصدر ونتيجة كل استثناء، ولا تعلن اكتمال استيراد لا يملك دليل اكتمال.
6. خصص Exposure حصرياً لكل مورد/فترة وقناة، وتحقق WHOLE/PARTS والاستمرار وحدود المنتج والعملة. أي نقص mapping أو proof يبقي النطاق مغلقاً.
7. أرسل snapshot مشتقة بإصدار حديث، ثم راقب provider acceptance وأثبت channel state بصورة مستقلة. افتح نطاق pilot المحدد فقط بعد تحقق الشروط.
8. نفذ إنشاء/تعديل/إلغاء وفق برنامج الاختبار المصرح للقناة؛ وثق إغلاق الأجزاء المتعارضة وإعادة الاشتقاق والمال والأحداث. لا تنشئ حجز إنتاج وهمياً خارج الاتفاق.
9. راقب خلال نافذة ذات بداية/نهاية ومعايير محددة قبل فتحها: unresolved exceptions، sync lag، UNKNOWN، أقدم Outbox/Inbox، معالجة العامل وفشل السحب. مدة النافذة ليست قيمة ثابتة مخترعة؛ تعتمد مع المسؤول وفق حجم التشغيل ودورة التحديث الفعلية.
10. وسع تدريجياً بعد نجاح الأدلة وتدريب موظفي الوردية، ثم راجع كل القنوات الخمس والأنواع المعلنة قبل إغلاق G-13. لا تساوي سلامة health endpoint سلامة التوزيع.

## المراقبة والتوقف والاستعادة

| الإشارة | التصرف الأول | شرط الاستئناف |
|---|---|---|
| فقد عزل أو allocation متعارضة داخلياً | إيقاف الأفعال المتأثرة وتصعيد عاجل وحفظ الأدلة؛ تطبيق إغلاق محافظ ممكن | إصلاح مع اختبار سباق/عزل مستقل ومطابقة الالتزامات |
| مخزون نشر UNKNOWN أو stale writer | منع الزيادات المتأثرة؛ إبقاء الحصة محجوزة، استعلام المحاولة ومطابقة | حسم الطلبات العالقة ودليل حالة القناة ونسخة حديثة |
| مزود غير متاح أو lag تجاوز عتبة الاتصال المعتمدة | حفظ inbound/outbox وتقييد الزيادات؛ مسؤول المنشأة يتابع الإغلاق المباشر إن تعذر إيصاله | اتصال مستعاد وrevisions مطابقة قبل أي Open |
| revision مجهولة الربط أو EXTERNAL_CONFLICT | حفظها وتعيين مسؤول، إغلاق نطاق معروف عند الإمكان؛ لا إسقاط أو إيواء وهمي | حل موثق وعقد موارد صالح أو معالجة خارجية مصرح بها |
| فقد Redis/عامل | إعادة تشغيل وإعادة بناء المهام من PostgreSQL مع dedup | backlog معالج دون تكرار وlag ضمن الحد المقاس |
| restore قاعدة قديمة | RECOVERY يمنع زيادات، سحب revisions متداخلة ومطابقة الروابط والمال والحصص | تقرير اكتمال ومطابقة وwriter واحد؛ لا بث Outbox قديم مباشرة |

التنبيهات لها owner وrunbook وعتبة تقاس وتثبت قبل pilot. يقاس lag على ثلاث لحظات مستقلة: commit ثم قبول المزود ثم دليل القناة. الهدف الداخلي صفر تعارض موارد غير مسموح؛ المخاطر الخارجية تقاس بالعدد والعمر والسبب ولا يوعد بصفر مطلق.

الرجوع لا يعني إعادة تشغيل مزودين متنافسين أو down migration تمحو الحجوزات. يوقف فتح المخزون، يسحب مع إثبات، يطابق كل الحجوزات منذ cutoff، وينقل المسؤولية لكاتب سابق/بديل إن كان مخولاً ومتوافقاً. عند تعذر حسم الحالة تبقى الحصة غير قابلة لإعادة البيع وتدار المتابعة يدوياً بأثر موثق.

## معيار إغلاق G-13

G-00..12 مقبولة وEX مستوفاة، المصفوفة الأساسية للخمس مكتملة بالأدلة، الأنواع المعلنة مختبرة، الاختبارات الداخلية والمال والعزل والاستعادة ناجحة، Computer Use للشاشات المنفذة مكتمل، لا عيب حرج مفتوح، ودليل تشغيل وتدريب ومسؤول مناوبة وخطة معالجة واستعادة معروفون. يصدر تقرير release بنسخة ونطاق وحدود، لا عبارة عامة «يدعم كل المواقع وكل الأنواع».

إضافة قناة لاحقة تعيد تأهيل profile/adapter وفق docs/33 ثم هذا الدليل للاتصال الجديد مع اختبارات regression للقنوات القائمة. لا تعيد بناء PMS، ولا تتخطى التفويض/Mapping/cutover لأن اسم القناة أضيف إلى قائمة.
