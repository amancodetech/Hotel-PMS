1. **قبل الانطلاق**: تأكد من `G-11 = ACCEPTED` في [G-11](execution/G-11.md) وأنه لا finding
   مفتوحاً؛ وتأكد من حالة البيئة والمنافذ (api 4100 / web 5173 / worker 4101) وأوقف dev
   قبل الأطقم الرسمية.
2. **خلال P12**: حزمة واحدة لكل دورة، مع بطاقة أدلة، وعدم إنشاء أي كتابة على `journal` أو
   `business_day` أو `folio_charge` أو `night_audit_*` — اشتراك المنصة لا يمس دفتر الإقامة.
3. **عند G-12**: جهّز حزمة الأدلة (تقرير تنفيذ + أرقام خام + أثر قاعدة البيانات +
   حدود/تعليق/استئناف/دعم/عزل + بصريات لوحة المنصة). **المراجعة المستقلة ليست إلزامية
   لـG-12** وفق docs/34؛ إن طلب المستخدم تأكيداً مستقلاً تُكتب حزمة مراجعة بنمط

4. **الحدود**: لا تُفتح P13 (القنوات الحية) ولا أي بوابة أخرى؛ اعتماد P11 → P12 تم بقرار
   المستخدم على G-11، ولا يُعلن أي جاهزية إنتاج.

## حدود صريحة

- لا رسائل OTA ولا قنوات حية ولا مزود/حساب حقيقي؛ لا مال جديد ولا أي كتابة على سجلات
  منشورة ولا دفتر المنشأة بسبب SaaS.
- لا PAN/CVV ولا بيانات حقيقية؛ لا بوابة دفع مصطنعة؛ الفوترة الإدارية سجلات موثقة فقط.
- التعليق لا يضيع التزامات ولا يوقف استقبال قناة ما زالت تبيع؛ لا حذف بيانات بسبب انتهاء
  الاشتراك (AT-27).
- دعم المنصة بلا منحة مرفوض، والمنحة محددة الصلاحيات والمدة وتُدقق (SEC-006/AT-S05)؛
  ولوحة المنصة بحد أدنى من بيانات العميل.
- لا إعادة فتح يوم مغلق في V1 (D-13)؛ لا تغيير لترتيب المراحل أو نموذج Money أو حدود
  العزل أو Modular Monolith.
- P13 (القنوات الحية) محجوبة حتى قرار المستخدم على G-12.
