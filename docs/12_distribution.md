# تأسيس مدير القنوات

حالة: عقد داخلي محايد؛ D-16 يعتمد tiket.com وBooking.com وAgoda وTraveloka وTrip.com كاتصالات مستهدفة لأولوية الإطلاق، ولا يعد ذلك ادعاء بأن قناة منها مدعومة قبل تحقق رسمي وتنفيذ واختبار اتصالها.

Core PMS→Inventory/Rates→Distribution Orchestrator→Mapping→Sync→Adapter. الوارد Adapter→Normalize→Inbox/Idempotency→Reservations. لا وصول مباشر لقاعدة Core من القناة. القنوات لا تتشارك transaction ذرية مع PMS؛ لذلك لا ضمان 100% ضد التعارض الخارجي.

D-19 يختار Channex هدفاً تقنياً مشروطاً؛ الأدلة والمقارنة في docs/22_connectivity_evidence.md. D-20 يحدد حصص العرض المحمية في docs/24_inventory_design.md: لا ينشر نفس المورد والفترة بحصص متنافسة، ولا يكفي قبول المزود لتحرير حصة مسحوبة. بوابات القنوات والنقل والاستعادة في docs/27_readiness_gates.md. لا يفترض أن تحديث الحجز داخل PMS يسمح بتعديل عقد OTA؛ الطلب الخارجي ينتظر تأكيداً موثوقاً.

## القدرات والربط

مصفوفة لكل Connection توضح، كل قدرة على حدة، دعم availability/rates/restrictions/new/modify/cancel/no-show/meal plans/payment references، وكذلك message receive/reply/attachments/delivery status/conversation history إن أتاحها المزود، مع الإقرار/recovery وطريقة الطلب والصلاحيات المطلوبة. صلاحية الحجوزات لا تورث صلاحية المراسلات. غير المدعوم أو غير المصرح يظهر كقيد، لا قيمة مخترعة. Mapping حسب Property وExternal Property وProduct/Room Type وRate Plan وMeal Plan بنسخ وتاريخ تحقق؛ أسماء متشابهة لا تكفي.

قبل التفعيل الحي: اعتماد رسمي أو مزود متاح، صلاحية حساب، Mapping مكتمل، اختبارات sandbox عند توفره، مراقبة وأداة استثناءات، خطة بدء ومطابقة الحجوزات القائمة. لا استيراد أولي ثم إعادة استيراد كحجوزات جديدة.

## فتح وإغلاق البيع ومنع التعارض

PMS هو مصدر حقيقة المخزون. عند قبول حجز داخلي أو وارد من قناة، يثبت الالتزام مرة واحدة داخل معاملة النظام، ثم يعاد حساب التوفر لكل عرض متداخل، بما في ذلك الفيلا الكاملة وأجزاؤها، وتُنشأ نية مزامنة بالنسخة الأحدث لجميع الاتصالات المتأثرة. الإلغاء أو التقصير يحرر أثر الحجز وحده ثم يعيد الاشتقاق؛ لا يفتح البيع تلقائياً إذا بقي حجز أو صيانة أو Stop Sell أو مانع آخر.

Stop Sell وOpen مؤرخان حسب الاتصال والعرض أو النوع والفترة. Open يعني إزالة سبب إغلاق محدد وإرسال التوفر المشتق، وليس فرض التوفر أو تجاوز القيود. لوحة التشغيل تميز desired/sent/acknowledged/verified وتعرض التأخر أو الاختلاف حتى تتم المطابقة.

يضمن النظام عدم إنشاء التزامين داخليين متعارضين حتى مع طلبات متزامنة. لكنه لا يعد بمنع مطلق لتعارض خارجي وقع في نافذة تأخر بين قناتين مستقلتين؛ عند وروده يحفظ الحجز الخارجي كحقيقة، يمنع إسقاطه، يغلق النطاق المتأثر، وينشئ استثناءً عاجلاً للمطابقة والمعالجة.

## معالجة أحداث المزامنة

- Event مكرر: نفس نتيجة العملية. Modification قديم لا يعيد حالة ملغاة؛ عند غياب ترتيب موثوق اقرأ الحالة المرجعية عبر المزود إن دعمها أو أحل للمراجعة.
- حجز خارجي متعارض يحفظ حقيقة الالتزام الخارجي ويظهر Unresolved، دون التزام داخلي زائف أو إسقاط.
- Mapping ناقص: Inbox محفوظ وقائمة معالجة؛ لا تخمين نوع الغرفة.
- نجاح إرسال غير معروف: desired/sent/acknowledged/verified منفصلة؛ المطابقة أو retry حسب عقد المزود.
- الحالة الأحدث تفوز في نية المزامنة الداخلية؛ لا ترسل retry قديماً يعيد فتح توفر أغلق لاحقاً.
- Auto-replenishment أو تعديل خارج PMS يُكتشف بالمطابقة ويعالج بإعادة الحالة المطلوبة وتنبيه. السلوك الفعلي لكل مزود يتحقق في وثائقه.
- الإقرار باستلام الحدث ليس وعداً بقدرة الإسكان؛ دلالة ACK حسب العقد الرسمي.

رسائل الضيوف تمر عبر Adapter نفسه من حيث التوثيق والعزل، لكن يملكها نطاق Guest Communications ولا تعامل كحدث حجز. لا تعرض حالة Delivered إلا بدليل يوفره المزود؛ وإلا تبقى Sent أو Unknown. عند غياب قدرة الرد داخل النظام يظهر رابط متابعة آمن إلى القناة الأصلية إن وفر المزود ذلك. التنفيذ الحي لهذه القدرات مؤجل لما بعد الإطلاق الأولي وفق D-15 وموضح في docs/19_guest_communications.md.

## الرصد والتشغيل

آخر حدث/تحديث وإقرار وتحقق، lag، المحاولات، DLQ، اختلافات الحالة، حجوزات غير مربوطة، عمر الاستثناء ومالكه. تأخر قناة لا يغلق Tenants أخرى. إغلاق احترازي للموارد المتأثرة سياسة تجارية تحتاج اعتماداً، ولا يلغي الحجوزات القائمة.

Stage 2 ينتج عقوداً ومحاكيات/اختبارات عند تفويض الكود، لا تشغيل قناة على بيانات حقيقية قبل RLS. Stage 13 يفعّل الاتصالات المستهدفة تدريجياً بعد النواة؛ لا يلزم تشغيلها جميعاً دفعة واحدة، لكن لا يكتمل نطاق D-16 التجاري حتى تثبت الاتصالات المطلوبة أو يوثق بديل رسمي لها. راجع المصادر في references/03_research_sources.md ثم تحقق حديثاً من أي حد خاص بالمزود قبل اعتماده.
