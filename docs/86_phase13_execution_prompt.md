## كيف تُدار الجلسة

1. **قبل الانطلاق**: تأكد من `G-12 = ACCEPTED` في [G-12](execution/G-12.md) وحالة EX-01..05،
   ومن البيئة والمنافذ (api 4100 / web 5173 / worker 4101)؛ وأوقف dev قبل الأطقم الرسمية.
2. **خلال P13**: حزمة واحدة لكل دورة، وبطاقة أدلة مستقلة، وسجل EX صادق: أي بند بلا دليل
   خارجي يبقى `BLOCKED_EXTERNAL` ولا يُعبأ بمحاكي أو قناة أخرى.
3. **عند G-13**: **المراجعة المستقلة إلزامية** وفق docs/34؛ جهّز برومبت مراجعة بنمط
   docs/75/79 والحكم في ملف مستقل، ثم القبول قرار المستخدم حصراً. لا نشر ولا إنتاج.
4. **الحدود**: لا تُفتح P14 (المراسلات/التوسع، D-15) ولا أي جاهزية إنتاج، وكل فعل خارجي
   (حساب، شراء، اتصال، نشر، رسائل OTA) يحتاج رسالة تفويض منفصلة ومحددة.

## قائمة جاهزية تسليم G-13 (عند الاقتراب من البوابة)

- سجل EX-01..05 كامل: المالك، الحالة الفعلية، الدليل، والخطوة التالية لكل بند (وBLOCKED_EXTERNAL
  واضحة بلا تجميل).
- بطاقات `docs/execution/P13-0X.md` بأدلة تنفيذ فعلية وحزمة اعتماد مزود ونطاق pilot.
- إعداد staging/production مفصول (D-12) مع إثبات الفشل المغلق بلا أسرار، وتجربة build/migrate/
  restore محلية مقاسة، وlocal-only guards سليمة.
- conformance suite محلي أخضر، وrehearsal cutover بلا ازدواج وبحصة لا تتداخل، وrunbooks
  تشغيل/مراقبة/انقطاع/رجوع محدثة في docs/35.
- عقود Phase 13 (إن أُضيفت عمليات) مولّدة ومربوطة بـcontracts:check؛ وعدم كسر أي عقد سابق.
- الأرقام: `db:check`، `check`، `contracts:check`، `test:property` كاملاً، `test:identity`،
  `test:distribution`، البصريات (phase13 إن وُجدت واجهة، وإلا phase12..5 و`visual:check`)،
  `checksums` + `sha256sum -c`.
- برومبت المراجعة المستقلة الإلزامية جاهز، والحكم في ملف مستقل، والقبول للمستخدم.
