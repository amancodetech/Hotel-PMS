# PSR-08 — المراجعة المستقلة

4 أكتوبر2026 — المراجع GPT-6 Astra؛ المنفذ GPT-6.1 Sol. استُخدمت مهارة `agency-code-reviewer`. ملكية المراجع هذا التقرير واختباري `tests/property/psr08-independent.pg.test.mjs` و`tests/property/psr08-search-independent.pg.test.mjs` فقط؛ تشغيل البناء وPostgreSQL والمتصفح والخدمات بيد المنسق. لا قبول ذاتي ولا تعديل لقرارات D أو G-13 أو الهجرات المطبقة أو docs/86.

## الحكم النهائي المستقل

**PASS_LOCAL — نجاح مستقل ضمن النطاق الموثق لـPSR-08.** أُغلقت F-PSR08-R01 وR02 وR03 بأدلة الإصلاح المحددة أدناه؛ لا P0/P1 أو finding مفتوحة في المصدر المقروء. نجح check النهائي182/182، وراجعت مصفوفة37 حالة وعقود القراءة وجرد التوافق ودليل التشغيل وخريطة مصادر الحالات. الحكم لا يرفع PSR-01..04 من REVIEW_PENDING ولا يثبت UX01..08 البشرية أو قنوات حية أو قبولاً إنتاجياً؛ لا ACCEPTED_LOCAL ذاتي.

## نطاق القراءة والمراجعة

- README وAGENTS وdocs/01 و17 و18، ومواصفات docs/99 و100 و101 وضوابط docs/95، وسجل PSR وبطاقات01..04 و07..08 ومراجع07 المستقلة.
- عقود SET/phase4 وDTO الفعلي، مسارات المسودات والاقتراح v1→v2، وخطة التنفيذ والدفعات والإضافة، وصفحات الشجرة والوحدات، ومعالج v2 ومستهلكاته ومسارات legacy.

## فجوات الأدلة التي عالجتها المراجعة

1. **T25:** اختبار الدالة في `tests/psr-plan-v2.test.tsx` يرفض hourly والسعة غير المرقمة وفئة المركبات، لكنه لا يثبت HTTP. أُضيف تحقق مستقل للرفض عبر حفظ المسودة ومعاينة الإضافة مع snapshots scoped للمسودة والمكان والمورد والمنتج والتركيبة والالتزام والتخصيص ونسخة المنشأة وعدّاد تدقيق نجاح setup.
2. **T14:** أُضيف تحقق مستقل بأن قراءة مسودة v1 ناقصة لا تكتب أو تترجم تلقائياً، وأن استبدالها الصريح v2 يحتفظ بـnull/omitted/zero والجيل مع زيادة revision فقط، بلا كتابة مخزون. حماية completed لها اختبارات وتغطية قديمة منفصلة؛ لا يستبدل هذا الاختبار دليلها.
3. **P01:** الدليل التاريخي في03 يقيس1000 مكان وصفحات25، ولا يختبر تصفح500 مورد فعلياً رغم وجودها في fixture. أُضيف تحقق مستقل لتصفح75 مورداً بزمن PostgreSQL ذي microseconds متطابق، مقارنة بقائمة SQL المرجعية لإثبات عدم الفقد أو التكرار.
4. **P02:** واجهة قراءة الشجرة الحالية تدعم parent/limit/cursor وترتيباً ثابتاً؛ واجهة الوحدات limit/cursor. قياس pagination أو availability/search لا يثبت البحث عن وحدة بكودها أو اسمها. بعد إعادة قراءة docs/99 §7 وdocs/100، لا يوجد تأجيل موثق لهذه القدرة؛ سجلت كنقص مطلوب الإصلاح في F-PSR08-R01، لا N/A أو DEFERRED ضمني. الفرز الثابت المعلن ممكن؛ لا يشترط هذا الحكم ابتكار قائمة اختيار فرز لم تنص عليها المواصفة.
5. **E05/legacy:** يلزم متصفح فعلي لتأخير GET ثم تبديل المنشأة، وتحويل v2 من الرابط القديم مع حفظ نطاق المنشأة، وبقاء حفظ v1 وcompleted مقفلاً، وعدم بقاء رابط عام يقود للنموذج القديم. اختبار unit للرد المتأخر أو GET مصطنع وحده ليس رحلة حفظ واستئناف حقيقية.
6. **UX01..08:** تبقى NOT_TESTED بشرية عند غياب مشاركين، حتى لو نجحت الرحلات الآلية والتكبير ولوحة المفاتيح.

- **الأثر:** لا يمكن العثور على الوحدة المطلوبة بالكود أو الاسم عبر القائمة المرقمة، ولا يمكن إعطاء PASS لـP02 أو إغلاق PSR-08 باعتبار القدرة مؤجلة لمجرد غيابها. أولوية P1 تخص شرط اكتمال النطاق، وليست ادعاء تسرب أو فساد مخزون.

## تقييم أدلة PSR-01..04 والأثر اللاحق

- PSR-01 نموذج معزول لا يكتب. نجاحه القديم لا يثبت حفظ v2؛ التحويل الحالي لـ`/structure-preview` يقاس بالمتصفح. تبقى البطاقة REVIEW_PENDING؛ النموذج ليس بديلاً لاختبار المنتج.
- PSR-02: parser صارم يفصل omitted/null، ويمنع فئة الأجزاء والطرق المؤجلة. الحفظ يتحقق من property.manage ويقفل المنشأة ويحمي جيل المسودة والمكتمل قبل replay، ويعيد قراءة UUID ضمن النطاق. نواة upgrade اقتراح يحفظ الأصل ويرفض BEDS عبر غرف متعددة وSUITE المبهم؛ لا تحويل تلقائي في wrapper. إعادة اختبارات المسودات والمستقل تسد الفجوة الحالية دون نقل434/434 التاريخية إلى نسخة جديدة.
- PSR-03: readLocationTree يستخدم قفل SHARE ونسخة شجرة ومؤشر HMAC مربوطاً بالعميل والمنشأة والأب والنسخة. النقل يتحقق من المكان الفعال والدورات، وقاعدة البيانات تفرض FK بالنطاق وحارس الشجرة. الترقية والرجوع وmigrator وCSV أعيدت في location-1؛ لا استعادة لقاعدة المستخدم ولا تعديل للهجرة لتمرير الرجوع. P01 الجديد يقرأ الموارد بصفحات25 فعلياً مع دقة microseconds.
- PSR-04: تخطيط v2 مشترك بين preview/apply، والتنفيذ داخل المعاملة القائمة. بصمة المعاينة تشمل المواقع والحدود والمخزون. حزمتا psr-apply-v2 وpsr04-review نجحتا في الجولة1 للتراجع والسباق والصلاحيات والتكرار والحدود؛ بيانات T02/T05/T06/T07/T28 المحددة في08 تكمل الحالات السابقة الأصغر. لا يصبح الحكم المركز التاريخي قبولاً لكل البطاقة أو ACCEPTED_LOCAL.
- T17: بصمات06.1 ليست كلها MATCH بسبب أرشفة06.3. راجعت `updateResourceById`: الفرع الجديد مشروط بـpatch.state غير ACTIVE ومختلف؛ التسمية والنقل لا يدخلانه. الكتابة تحفظ ID/code ومراجع الالتزام والتدقيق ونسخة المخزون. location-1 تتضمن T17 للمصدر الحالي. لا ضرورة لإعادة حزمة06.1 المستقلة لهذا التغيير وحده؛ دليلها PRIOR_SCOPED مع تقييم أثر المصدر، وليس MATCH كاملاً.
