## حالات القبول المخططة (PG + API)

- **F1** الإعدادات: أقسام وعدادات وتغييرات مجدولة صحيحة، ولا زيادة `inventory_version` (قراءة فقط).
- **F2** سجل التغييرات: أحداث العقار فقط (لا تسرّب عقار آخر)، وترقيم مؤشر يعمل.
- **F3** أثر تعديل: ورقة مقترحة عليها التزام منتج آخر في نفس الفترة → `BLOCKED` مع تفاصيل، بلا كتابة.
- **F4** تنفيذ تعديل متعارض → `409 COMPOSITION_CHANGE_CONFLICT`، والنسخة القديمة كما هي.
- **F5** تعديل آمن مؤرخ: إغلاق القديمة عند `effective_from - 1`، نسخة جديدة ACTIVE بأوراق جديدة ونفس `effective_to`؛ حجز المنتج الآخر للورقة المحذوفة بعد تاريخ السريان ينجح؛ وبيع المنتج نفسه عبر حدّ التغيير يُرفض (لا نسخة تغطي النافذة كاملة).
- **F6** بصمة معاينة غير مطابقة → `412 PREVIEW_STALE` بلا كتابة.
- **F7** تاريخ سريان رجعي → `400 INVALID_REQUEST`.
- **F8** نافذة متداخلة لنسخة ACTIVE أخرى لنفس المنتج في مسار SET-06 → `409 COMPOSITION_WINDOW_CONFLICT` (فحص خدمي تحت قفل المنشأة؛ لا حارس قاعدة بيانات عام، انظر القرار 6).
- **F9** ترحيل معزول dry-run/apply: عدادات قبل/بعد متساوية للموارد والالتزامات، والموارد نفسها بنفس المعرفات، ولا تكرار عند الإعادة.
- **F10** مطابقة: `PASS` لحالة سليمة؛ `WARN` لموارد مشتركة بين منتجين؛ `WARN` لتداخل نوافذ ACTIVE إن وُجد (معلوماتي).
- **F11** عزل: قراءة/تنفيذ تركيبة عقار آخر → `404`؛ صلاحية مختلفة → `403`.

## القرارات المضغوطة (تُسجَّل للمراجعة)

1. `effective_to` في `composition_version` **شامل** (كما في استعلام الاستهلاك `>=`)، والنسخة الجديدة تبدأ `old.effective_to` نفسه افتراضياً.
2. الإغلاق: `old.effective_to = effective_from - 1`؛ وإن ساوى تاريخ السريان بداية القديمة تُتقاعد القديمة.
3. حجوزات HOLD النشطة غير منتهية على ورقة مقترحة = تعارض محافظ (المنتج غير معروف في الالتزام).
4. الالتزامات المستقبلية لمنتج آخر على **ورقة مقترحة** = تعارض؛ على **ورقة محذوفة** = معلومة (الالتزام محفوظ بقيد عدم التداخل).
5. التغييرات غير المدعومة (سعة/خصوصية/توقيت/عملة) لا تُعدَّل بصمت؛ تبقى خارج هذه الحزمة وتُرفض بـ`400`/`SETUP_MODE_UNSUPPORTED` عند الطلب.
6. **لا حارس قاعدة بيانات عام يمنع تعدد نوافذ ACTIVE لنفس المنتج**: التركيب متعدد المستويات يسمح بنسخ متداخلة لنفس المنتج (docs/04)، وأطقم `composition-api` و`adversarial` تعتمد ذلك. لذلك جُرّب الحارس العالمي في `Migration20260921160000` ثم أُلغي في `Migration20260921170000` (مع إعادة أي صف قُيّد)، وبقي الفرض الخدمي داخل مسارات SET-06 فقط تحت قفل المنشأة (المعاملات متسلسلة، فلا سباق).

## الحدود المعلنة

- لا واجهة لعمليات الترحيل المعزول/المطابقة سوى عرض فحوص المطابقة في تبويب الإعدادات؛ تنفيذ الترحيل عبر API وطقم PG (لا زر ترحيل بعد).

- SET-AT08/SET-AT16 مؤشران محليان من الطقم، وليستا معايير SET-AT محوّلة إلى PASS.
- لا تغيير لـG-13 أو القبول الإنتاجي أو بوابات القنوات.
