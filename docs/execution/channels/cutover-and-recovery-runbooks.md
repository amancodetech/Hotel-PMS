# Runbooks التدريب والانقطاع والرجوع (محلي، غير حي)

الحالة: قوالب تشغيلية محضّرة من [docs/35](../../35_live_channels_runbook.md). لا تحتوي بيانات
حية، وتُستخدم فقط عند تفويض pilot (EX-02) مع أسماء مسؤولين فعلية.

## 1. تدريب الوردية (checklist)

- [ ] تعريف writer الواحد وبديله وصلاحية stop-sell/فتح محدود.
- [ ] شرح شاشات اليوم والقنوات: desired/sent/acknowledged/verified ولقطة المراقبة.
- [ ] تمرين على STOP_SELL ثم OPEN مع إثبات `effective_open` وأسباب الإغلاق.
- [ ] تمرين على استثناء revision ومطابقة الحجز والتحرير بعد دليل مقبول.
- [ ] تدريب إيقاف/استئناف كاتب التوزيع وعدم إعادة فتح المخزون بلا مطابقة.
- [ ] توثيق أسئلة التصعيد والمهلة المتوقعة.

## 2. runbook انقطاع/استعادة

1. **عند lag/ACK مجهول**: منع زيادات التوفر المتأثرة، حفظ Outbox، إبقاء الحصص محجوزة، إشعار
   مسؤول المنشأة.
2. **مزود غير متاح**: لا ادعاء نجاح Stop Sell؛ يستكمل مسؤول المنشأة الإغلاق في القنوات الأصلية
   ويسجل الدليل؛ الحجوزات الواردة تُحفظ كاستثناءات قابلة للاستئناف.
3. **استعادة قاعدة**: وضع RECOVERY يمنع الزيادات، استرجاع revisions منذ ما قبل النسخة، مطابقة
   الدفع/Exposure/cutoffs/Outbox، ثم فتح محدود بعد تقرير اكتمال وwriter واحد.
   rehearsal P13-02 يثبت محلياً: التعليق يبقى محفوظاً بعد restore، والكتابة بعد بدء النسخة لا
   تُستعاد، ولا زيادة تُحرَّر بلا قبول.
4. **رجوع المزود/التطبيق**: لا down migration يمحو حجوزات ولا مزودان على نفس المخزون؛ تغيير
   المسار يحتاج سحباً ومطابقة وربطاً موثقاً (docs/33) ثم هذا الـrunbook.

## 3. runbook تصحيح وإعادة فحص وتوسيع

- كل استثناء: مالك + سبب + خطوة + دليل؛ الإغلاق بقرار لا بغياب شكوى.
- بعد كل تصحيح: إعادة الفحص العدائي على مسارات العزل/الالتزامات/الحصص حسب docs/32، ثم توسيع
  النطاق تدريجياً.
- توسيع القنوات/الأنواع: خلية خلية وفق docs/35 (AT-C01..10 + مصفوفة الموارد)، وقرار المستخدم.
