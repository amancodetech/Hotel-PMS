# حزمة اعتماد مزود الاتصال (Channex) — جاهزة للإرسال، غير مرسلة

الحالة: **LOCAL PACKAGE / NOT_SENT / NOT_AUTHORIZED**. التاريخ: 17 سبتمبر 2026.
النطاق: تحضير محلي فقط وفق [docs/22](../../22_connectivity_evidence.md) و[docs/33](../../33_channel_extension_contract.md)
و[docs/35](../../35_live_channels_runbook.md). لا مخاطبة مزود ولا شراء ولا حساب ولا بيانات اعتماد في هذا الملف.

## 1. الجهة والنطاق المطلوب

| البند | القيمة المحضّرة | الحالة |

| المنتج | Hotel PMS SaaS (متعدد المنشآت، Modular Monolith) | ثابت |
| المزود المستهدف | Channex White-label API كهدف التكامل الأول (D-19) | DECIDED DESIGN / CONDITIONAL ACTIVATION |

| نموذج التواصل المعتمد | بريد/بوابة المزود الرسمية بعد تفويض منفصل | NOT_AUTHORIZED |

## 2. ما سيُطلب صراحة (نطاق العرض)

1. تأكيد أهلية العقد الإندونيسي وwhite-label وتغطية القنوات الخمس المنتجة لحسابات منشآتنا.
2. تأكيد قدرات D-20 الأساسية لكل قناة: حصة بيع خارجية واحدة لكل مورد/فترة، فصل حصص القنوات،
   منع إعادة الزيادة الخارجية (auto replenishment)، ودليل سحب/إغلاق قابل للتحقق.
3. برنامج PMS certification وشروطه وإصدار Adapter المتوقع وبيئة الاختبار.
4. نموذج التسعير الفعلي لنوع منشآت pilot (فنادق وفيلات/وحدات مركبة) وحد الوحدات والضرائب.
5. حدود API (rate limits، أفق ARI، نافذة التاريخ، retention) وسياسة الدعم والتصعيد.
6. مسار فصل مفاتيح كل Tenant وsecret_ref وتدوير/إبطال الاعتماد.

## 3. أسئلة يجب أن يثبتها المزود قبل P13-03

هذه القائمة مصدرها [docs/35](../../35_live_channels_runbook.md) (نقاط يجب إثباتها مع المزود)، ولم تُرسل:

1. فصل التوفر وStop Sell للحصة بين القنوات، بما في ذلك كل rate/derived/occupancy/meal variation.
2. كيفية إثبات تطبيق إغلاق القناة فعلياً، وcutoff ودلالة revisions المتأخرة قبل تحرير Exposure.
3. إعداد auto decrease وauto replenishment على new/modified/cancelled، وأي إعدادات OTA أخرى
   قد تعيد فتح البيع.
4. إمكانية تمثيل مورد ثابت لليالي المتصلة والفيلا/الأجزاء والأسرة بهذا Mapping والقيود المطلوبة.
5. نطاق تفرد revision/booking IDs، معنى الترتيب، pagination/retention/ACK، واسترجاع الحجوزات
   القائمة والمفقودة بعد انقطاع أو restore.
6. نموذج المبلغ والعملة والضريبة والعمولة والوجبة والإشغال لكل قناة/حساب، ودقة IDR وحدود السعر.
7. سقف rate limits لكل حساب/منشأة/عملية، واكتشاف partial والفشل المتأخر، ومسؤول تصعيد الانقطاع.

أسئلة إضافية من [docs/22](../../22_connectivity_evidence.md#حزمة-بدء-الاتصال): تطبيق Stop Sell مختلف
لكل قناة دون إغلاق الجميع، حدود المعدل وأفق ARI ومدة الاحتفاظ، تصنيف وعدد الوحدات للفوترة،
SLA وحماية بيانات وتصدير عند الخروج.

## 4. نموذج الأدلة المطلوب لكل قدرة

يُسجَّل لكل قدرة على مستوى provider + adapter version + channel + environment + connection +
نوع مورد/نموذج سعر وفق [docs/33](../../33_channel_extension_contract.md#مصفوفة-قدرات-قابلة-للتدقيق):

- `capability_code` وحالة `DOCUMENTED / TESTED / UNSUPPORTED / UNKNOWN`.
- `authorization_status` مستقلة (لا ترفعها موافقة المزود العامة).
- `evidence_url` أو مرجع مستندي، `checked_at`، `test_run_id`، `limitations`، `owner`،
  `recheck_trigger`.
- القدرات الأساسية: new/modify/cancel inbound، Mapping، availability مطلقة، الأسعار،
  Open/Stop Sell، recovery، وتمثيل D-20 (فصل الحصص، منع إعادة الزيادة، دليل السحب).
- دليل السحب إلزامي لـD-20؛ إن تعذر آلياً يلزم إجراء تحقق بشري موثق ومطابقة وإلا بقيت الحصة
  `UNKNOWN`.

قاعدة الفحص المحلي المنفذة: أي خلية PASS بلا `connection/environment/profile/test_run`
أو بلا مرجع دليل ترفضها بوابة [P13-07](../../87_phase13_review_prompt.md) وبوابة الفاحص
`scripts/p13-ex-registry.mjs`. المحاكي لا يرفع أي خلية إلى `TESTED`.

## 5. إدارة الأسرار والبيئات

- لا تُحفظ credentials أو نسخ هويات أو توقيعات عقود في Git؛ `secret_ref` يشير إلى مخزن أسرار
  (D-12: AWS Secrets Manager عند النشر، ومحلياً `.env` للاختبار فقط).
- فصل staging/production: مخزون أسرار ومفاتيح مورد/عميل منفصلان، وتدوير وإبطال مختبران
  (يُنفذان ميدانياً بعد تفويض EX-05؛ الاختبار المحلي المحضّر في P13-02 validation فقط).
- فواصل مفاتيح كل Tenant تحفظ في التصميم ولا تنسخ في الوثائق.

## 6. حزمة التسعير (مؤشر منشور فقط)

منشور Channex وقت البحث [docs/22](../../22_connectivity_evidence.md): رسم منصة يبدأ من 130 USD
شهرياً، و7 USD للفندق المتصل أو 0.50 USD لوحدة Vacation Rental، دون VAT، والمراسلات إضافة منفصلة.
**لا نفترض** تصنيف الفيلا المركبة ولا الحد الأدنى النهائي ولا أي خصم؛ يلزم عرض مخصص لنوع منشآت
pilot. لا اشتراك ولا إنفاق تم.

## 7. المخرجات القابلة للمراجعة عند التنفيذ الخارجي

1. عرض سعر خطي + موافقة إنفاق (EX-05).
2. تأكيد أهلية وتعاقد + حالة authorization لكل قناة (EX-01).
3. نتيجة PMS certification مع test run IDs ونسخة Adapter.
4. مصفوفة capability evidence مؤرخة للقنوات الخمس.
5. نطاق pilot موقّع من المنشأة (EX-02) وملف الامتثال (EX-03).
6. تقرير أداء/استعادة staging ومراجعة مستقلة (EX-04).

هذه الحزمة جاهزة للإرسال فقط بعد رسالة تفويض خارجي منفصلة من المستخدم؛ وجودها لا يمنح تفويضاً.
