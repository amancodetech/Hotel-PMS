# PSR-08 — القبول النهائي والتسليم المحلي

4 أكتوبر 2026 — **PSR-08 ACCEPTED_LOCAL بقرار المستخدم الصريح «اقبل وما التالي»**، ضمن النطاق والحدود الموثقة والمراجعة المستقلة PASS_LOCAL. هذا القرار يخص08 وحدها؛ PSR-01..04 تبقى REVIEW_PENDING، و06/07 VERIFIED_LOCAL، وUX01..08 NOT_TESTED، وG-13 NOT ACCEPTED. لا قبول إنتاجي أو نشر أو اتصال حي.

إغلاق التحقق السابق: البصمات885/885، وfinal-http-2 أعاد HTTP200 للخدمات الثلاث، وفق `.local/verification/PSR-08/final-receipt.json`. هذا إيصال تاريخي قبل قرار القبول؛ إيصال تغييرات توثيق القبول سيكون `.local/verification/PSR-08/acceptance-receipt.json` بعد تجديد البصمات والتحقق منها.

التالي المقترح فقط: حسم فجوات مراجعات PSR-01..04 لكل بطاقة، وإجراء UX بمشاركين مستقلين؛ ثم مراجعة جاهزية P13 الحالية وEX دون اتصال حي. لم يبدأ هذا العمل.

4 أكتوبر 2026 — **ACCEPTED_LOCAL بقرار المستخدم؛ PASS_LOCAL مستقل**. المنفذ GPT-6.1 Sol، والمراجع المستقل GPT-6 Astra. التفويض هو طلب المستخدم إكمال PSR-08 محلياً وإصلاح العيوب المثبتة واستكمال الأدلة وإزالة المتكرر المثبت. لا قبول ذاتي أو نشر أو اتصال حي.

## PSR-08-L01 — الواجهات القديمة

[الجرد المفصل](PSR-08-legacy.md) يتتبع المسارين والروابط والمستهلكين والمسودات:

- `/structure-preview` نموذج بلا حفظ أوAPI. أزيل من routing وحول إلى المنشآت أو structure عند propertyId صالح. ملف النموذج واختباراته التاريخية محفوظان، ولا يدخلان واجهة المنتج.
- أزيل زر النموذج العام من صفحة المنشآت؛ إنشاء المنشأة يفتح المعالج الخادمي الحالي.
- `/setup-preview` يقرأ المسودة فعلياً بمفتاح tenant/property وصلاحية property.read، ويحول v2 إلى محررها الصحيح. v1 وlocalStorage محفوظتان لأن BEDS متعددة الغرف ليست متكافئة تلقائياً مع v2.
- legacyLink وPropertySetupPage محفوظان؛ الوظائف التشغيلية المطورة ليست واجهة مهجورة. المكتمل v1 للقراءة فقط، دون إعادة apply.
- browser-3 يثبت حفظ واستئناف v1 فعلياً، والتحويل v2، وحماية المكتمل، واستئناف localStorage. لا إزالة أخرى دون تكافؤ مثبت.

الملفات: LegacySetupEntryPage/App/PropertiesPage. الاستيراد lazy يبقي المعالج القديم خارج رحلة v2، والخطأ في GET يظهر مع retry ولا يعامل كمسودة فارغة.

## Findings والإصلاح

### F-PSR08-R01 — P1 لاكتمال البحث والفرز

أثبت Astra أن بحث الوحدات والمواقع بالكود أو الاسم أو الصفة غير مؤجل في docs/100؛ بحث خطة التوفر ليس بديلاً. أصلح Sol المصدر دون تضييق المواصفة:

- الموارد: q حرفي غير حساس لحالة الحروف في code/display_label/notes مع تهريب wildcards. الصفات القائمة فقط: type/min_capacity/bedrooms_count/bathrooms_count، دون نظام سمات ديناميكي.
- ترتيب صاعد code/label/capacity مع ID للفصل بين المتساوي؛ الاسم null يرجع إلى code. صفحات25 في الواجهة، وحد الطلب1..100.
- مؤشر HMAC مرتبط بالنطاق والبحث والصفات والترتيب وinventory_version. اختلاف النطاق أو المدخل400، وتغير البيانات412 تحت SHARE lock. القراءة القديمة بلا فلاتر تبقى created_at/id.
- الشجرة: q للكود والاسم داخل أطفال الأب المحدد، وkind القائمة، وترتيب display_order/code/name. المؤشر مرتبط بالأب والبحث والنوع والترتيب ونسخة الشجرة.
- UI/client/cache keys/DTO وعقد phase4 واللغات الثلاث محدثة. set.openapi لم يتغير لأن العمليات ملك phase4؛ generated من build فقط. لا هجرة أو رفع حدود.

الملفات: resource-search.ts جديد؛ resource-service؛ location-tree-service؛ resource.controller؛ عميل property؛ PropertySetupPage؛ LocationBrowser؛ phase4.openapi؛ locales الثلاث. PostgreSQL17/17 وlocation14/14 نجحا. متصفح البحث نجح26/26 في `search-browser-1791091615800`؛ أغلق Astra R01؛ check النهائي نجح182/182 في25 حزمة، exit0. عولج قص العناوين R03 في الواجهة فقط، دون تغيير المصدر الخادمي المختبر.

### F-PSR08-R02 — دليل390 غير صحيح

الجولة browser-3 كانت بعرض1440 لأن استئناف E02 تخطى ضبط viewport. الخام محفوظ ولا يستعمل لإثبات الهاتف. browser-locales-4 صرحت بعرض390 ونجحت14/14. Astra أغلق R02 بعد فحص الأبعاد والصور؛ لا تعديل تطبيق لهذا التصحيح.

### F-PSR08-R03 — P2 قص عناوين البحث

أثبتت صور البحث قص نوع المورد ونوع المكان والحقول العددية، خصوصاً بعرض390. جعل Sol الحقول بعرض كامل على الهاتف وبعرض220/360 على الشاشات الأوسع، مع عناوين ثابتة والتفاف صف البحث. لا تغيير API أو PostgreSQL. بروفة مستقلة `search-labels-1791091898962` نجحت109/109 في25.58s، باللغات الثلاث وعرض390 وتكبير200، أغلق Astra R03 بعد فحص المقاييس والصور الصحيحة بعرض390 والشاشة الواسعة. بعض لقطات form عند native200 التقطت رأس الصفحة بإحداثيات خاطئة؛ لا تثبت المظهر بصرياً. التكبير نفسه مثبت chrome zoom=2 وinnerWidth720 وdpr2، مع قياس العناوين واستجابة لوحة المفاتيح.

## حدود الحكم ونقطة الاستئناف

PSR-01..04 تبقى REVIEW_PENDING، و05 ACCEPTED_LOCAL بقرار سابق، و06/07 VERIFIED_LOCAL مع PASS مستقل. تغير resource-service بعد06.1 حصره Astra في حارس patch.state للأرشفة، ثم فرع القراءة في08؛ rename/move لم يتغيرا، وlocation الجديدة تثبتهما. لا ادعاء MATCH شامل للمصدر التاريخي.

PSR-UX01..08 كلها NOT_TESTED دون مشاركين بشريين مستقلين. E06 آلي ضمن الضوابط المقاسة وحدودها؛ لا WCAG أو قارئ شاشة أو ثلاث رحلات كاملة keyboard/200 دون دليل. القنوات الحية والترقية المتدرجة مع نسخة قديمة NOT_TESTED. D-20 وG-13 محفوظان، والتوسعات المؤجلة لا تنفذ.

ثبت PASS_LOCAL مستقل وcheck النهائي182/182 في25 حزمة، exit0، وزمن Jest22.175s. يسجل المنسق نتيجة تجديد البصمات والتحقق منها بعد آخر وثائق في `.local/verification/PSR-08/final-receipt.json`. القرار المتبقي هو قبول المستخدم للنطاق المحلي وحدوده. لا ACCEPTED_LOCAL ذاتي. docs/86 والهجرة المطبقة محفوظان؛ لا إعادة07 أوحزم القبول الناجحة دون أثر.

جاهزية التسليم المحلي 4 أكتوبر: `dev-start-final-4` و`final-http-2` exit0؛ API4100 وWorker4101 وWeb3000 أعادت HTTP200 بالفحص النهائي. لم يتغير التطبيق بعد check النهائي. نتيجة البصمات بعد آخر وثائق والتحقق منها في `.local/verification/PSR-08/final-receipt.json` مع السجلات الخام وأوامرها وexit.
