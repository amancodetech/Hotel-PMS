# P03-02: النموذج المؤسسي والصلاحيات والدعوات والاعتمادات

الحالة: IMPLEMENTED / VERIFIED محلياً. القبول النهائي ينتظر مراجعة G-03 المستقلة.

## النموذج المنفذ (13 جدولاً + كتالوج)

`app_user`, `auth_session`, `auth_flow`, `tenant`, `membership`, `permission`, `role`, `role_permission`, `role_grant`, `grant_property`, `invitation`, `approval_request`, `audit_event`.

- العضوية وحالتها منفصلتان عن هوية Keycloak؛ المستخدم الواحد يمكن أن ينتمي لعدة Tenants.
- `role_grant` يحمل `effect` (GRANT/DENY) و`scope_type` (TENANT/PROPERTIES) و`expires_at` و`revoked_at`، و`grant_property` لقائمة نطاق property المستقبلية. مراجع مركبة `(id, tenant_id)` تمنع ربط دور أو عضوية من Tenant آخر.
- كتالوج الصلاحيات ثابت في `domain/permissions.ts` (12 كوداً) ويُزرع في `permission`؛ الأدوار النظامية الأربعة: TENANT_OWNER / TENANT_ADMIN / AUDITOR / MEMBER. لا فحص على أسماء الأدوار في Controllers.
- الدعوات: هاش SHA-256 لتوكن عشوائي 256-bit، استخدام واحد، انتهاء صلاحية، مطابقة بريد الهوية الموثقة، وتُعرض مرة واحدة فقط محلياً بدون بريد خارجي.
- الاعتمادات: `approval_request` مرتبط بـaction وrequest_hash (JSON canonical) وresource_version/currency/amount عند الانطباق؛ الطالب لا يعتمد طلبه.
- `audit_event` للإضافة فقط بحقول `before_safe/after_safe` منقّاة.

## السلوكيات

- منع تصعيد الصلاحيات: لا يمكن إنشاء/تعديل دور يحمل صلاحية لا يملكها الفاعل، ولا منح دور يتجاوز صلاحيات المانح (`assertCanDelegate`).
- آخر مسؤول: `countActiveAdmins` تمنع تعليق/إلغاء آخر عضوية نشطة تحمل `role.grant`.
- إبطال فعّال: كل طلب وكل job يعيد قراءة العضوية من PostgreSQL؛ التعليق أو الإلغاء يمنع الطلب التالي فوراً.
- حماية إعادة الاستخدام: منع منح نشط مكرر (409)، ومنع معالجة اعتماد لطلب مختلف (404).
- لا mass assignment: الطلبات تُتحقق بمخططات zod صارمة والحقول الداخلية غير مقبولة.
