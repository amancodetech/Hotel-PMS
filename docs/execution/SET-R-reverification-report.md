## النتائج الجديدة

### SET-R2-01 — null للمعرّف والسعة في مجموعة الوحدات يُرفض 400 (P2، أُصلح داخلالجولة)

- المسار: `apps/api/src/property/setup.controller.ts` مخطط `unitGroup` (`id` و`capacity` كانتا `optional` بلا `nullable`).
- إعادة الإنتاج: حفظ مسودة مجموعة فيها `id:null` أو `capacity:null` → 400 `INVALID_REQUEST` بتفاصيل فارغة؛ وصدى الخادم لمسودة جزئية يحتوي `capacity:null` فيفشل أي حفظ لاحق من API أو من المتصفح بعد مسح سعة الوحدة. هذا هو الجزء المتبقي من R03 (docs/98: «الواجهة ترسل null للحقول الفارغة والسعة»).
- الدليل: `.local/verification/SET-R2/first-pass.log` (فشل `R2-R03` بدنه 400 في السطرين 9 و14) على بصمة المصادر `326e5cf2…`.
- الإصلاح: `.nullable()` لـ`id` و`capacity`؛ لم يُمس أي منطق آخر.
- إعادة التحقق: `.local/verification/SET-R2/final-pass.log` 13/13 على بصمة `a6e96140…`.
- **مطابقة العقد**: وُحّد `docs/contracts/set.openapi.json` مع السلوك (nullable لـ`property.name/timezone/base_currency` و`SetupUnitGroup.id/capacity`) وأُعيد توليد `packages/contracts/src/set.generated.ts`؛ `pnpm contracts:generate` ثم `pnpm contracts:check` ناجحان، وأُعيد تشغيل فحوص SET 25/25 بعد التوليد (`focused2.log`).

### ملاحظات P2 (سلوك مصمم، لا عيوب)

- **SET-R2-O1**: replay التنفيذ بعد أرشفة المنشأة يعيد `409 PROPERTY_ARCHIVED` وليس النتيجة المخزنة، لأن فحص الحالة يسبق فحص التكرار (فشل مغلق مقصود). replay قبل الأرشفة يعيد النتيجة الأصلية حرفياً حتى بعد تعديل المسودة (`R2-R04i`).
- **SET-R2-O2**: حفظ مجموعة وحدات يتطلب `rental_mode` صالحاً (`mode_invalid`)؛ مسودة بلا مجموعات تعمل كاملة. سلوك مقصود حتى SET-05 (توسيع الأوضاع).
- **SET-R2-O3**: قراءة المسودة لمنشأة مؤرشفة مرفوضة (`PROPERTY_ARCHIVED`)؛ مقصود ضمن R05.
- **تصحيح أدوات التحقق**: توقع الاختبار الأولي `INVALID_STATE_TRANSITION` كـ422 بينما mapping المشروع 409، و`rental_mode` إلزامي؛ صُحح الاختبار ولم يكونا عيب منتج.
