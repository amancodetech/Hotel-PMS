# P04-03 التركيبات المؤرخة وحالات الموارد

التاريخ: 14 سبتمبر 2026. المنفذ: opencode (deepseek-flash) بتفويض المرحلة 4.
النسخة: بلا commit؛ بصمات `CHECKSUMS.sha256` المرجع.
الحالة: IMPLEMENTED / VERIFIED محلياً (PASS)؛ المراجعة المستقلة للمخزون مطلوبة قبل G-05/G-06.

## السلوك المنفذ

- CompositionVersion مؤرخة لكل منتج: `version_number` متسلسل، فترة `[effective_from, effective_to)`
  مع قيد `effective_to > effective_from`، وحالة DRAFT→ACTIVE→RETIRED بلا رجوع.
- CompositionEdge يحمل إما مورداً أو نسخة تركيب فرعية، بقيد شكل صارم (هدف واحد فقط)، ومنع
  الإشارة الذاتية، وقيد مركب على المنشأة والـTenant يرفض الموارد والنسخ العابرة للمنشآت.
- التنشيط (`ActivateComposition`) يبني تسطيحاً ذرياً: child النشط فقط، فترته داخل فترة الأب،
  لا تكرار ورقة عبر المسارات، العمق ≤ `max_composition_depth` وعدد الأوراق ≤
  `max_leaves_per_product` من ملف PERF-01 للمنشأة، ثم يكتب `composition_leaf` ويحوّل الحالة
  في المعاملة نفسها مع Audit.
- النسخة المفعّلة غير قابلة للتعديل: لا API لتعديل الأطراف، وtrigger قاعدة بيانات يرفض أي
  إدخال/تحديث/حذف على edges/leaves لنسخة غير DRAFT (`23514`).
- تنشيط المنتج يقبل الآن مورداً أو Pool بعضوية نشطة أو تركيباً نشطاً.
- حالات مستقلة على المورد: `housekeeping_state` (CLEAN/DIRTY/INSPECTED) و`maintenance_state`
  (NONE/OOO/OOS) منفصلة عن `state` المخزني؛ إدارتها التشغيلية في P09.

- DB: RLS وleast privilege للجداول الثلاثة؛ رفض الإشارة الذاتية والشكل الخاطئ والعابر للمنشأة
  (23514/23503)؛ حظر تعديل النسخة المفعّلة؛ منع تكرار الورقة.
- API: MFA لـ`composition.manage`؛ إنشاء DRAFT وتنشيط بتسطيح depth 1 ثم depth 2؛ رفض الفترة
  خارج الأب؛ رفض child غير نشط؛ DUPLICATE_LEAF؛ مورد متقاعد؛ إعادة تفعيل مرفوضة؛ قراءة
  مقيّدة بـ`property.read`.
