# PSR-02 — عقد v2 والتوافق

الحالة: **REVIEW_PENDING — نطاق PSR-02 منفذ ومتحقق محلياً؛ لا قبول مستقل**. التبعيات: PSR-01.
مصدر التفويض الحالي: طلب المستخدم الصريح «حسنا قم بالتنفيذ بشكل صحيح واحترافي» (23 سبتمبر 2026). التنفيذ المحلي مفوض وفق التبعيات؛ لا نشر أو قنوات حية أو حذف بيانات مستخدمة.
المراجع: [المواصفة](../100_psr_implementation_spec.md)، [الاختبارات](../101_psr_acceptance_cases.md)، [التقدم](PSR-progress.md).

## PSR-02.1 — تحويل docs/100 §3–4 إلى OpenAPI وقائمة عمليات وصلاحيات دقيقة

- الحالة: VERIFIED_LOCAL — مخطط v2 واتحاد الإصدارات في مسار الحفظ؛ عقود شجرة المكان والإضافة بعد التفعيل مثبتة تصميمياً لمراحلها التالية.
- نقاط القراءة/التعديل المرشحة: docs/contracts/set.openapi.json وphase4.openapi.json؛ apps/api/src/property/. تحقق من المستهلكين؛ لا تعدل الملفات لمجرد ورود اسمها.
- النتيجة المطلوبة: الحقول والأنواع والأخطاء/If-Match/Idempotency/limits مثبتة؛ توليد الأنواع بلا تعديل يدوي.
- التحقق المطلوب: فحص عقود. حالات الاختبارات وتوقعاتها في docs/101.
- الدليل الفعلي: [تفصيل العقد](PSR-02-contract.md)، schemas V2 في set.openapi.json والأنواع المولدة، وفحص العقد يثبت اتحاد الإصدارات للحفظ وحدود DRAFT_STORAGE_ONLY؛ العقود المستقبلية معلنة DESIGN_ONLY.

## PSR-02.2 — مترجم مسودة v1/v2 بلا تنفيذ كيانات

- الحالة: VERIFIED_LOCAL — اقتراح تحويل محافظ، وحفظ/صدى v2 عبر API مع حماية v1 والمكتمل. لا ترقية تلقائية ولا مقارنة تنفيذ مخزون قبل PSR-04.
- نقاط القراءة/التعديل المرشحة: domain/setup.ts وخدمات المسودة وعميل setup. تحقق من المستهلكين؛ لا تعدل الملفات لمجرد ورود اسمها.
- النتيجة المطلوبة: صدى الحقول null/omitted صحيح؛ المكتمل محمي؛ النمط الملتبس يحتاج مراجعة.
- التحقق المطلوب: PSR-T14. حالات الاختبارات وتوقعاتها في docs/101.
- الدليل الفعلي: setup-upgrade.ts وsetup-v2.ts واختبارات الوحدة؛ صدى الحفظ الخادمي والترقية الصريحة وحماية المكتمل في psr-draft-v2.pg.test.mjs، 9/9 بعد آخر تعديل. يحفظ الأصل ويحجب التحويل الملتبس، ولا ينشئ كيانات.

## PSR-02.3 — ربط التحقق والنسخ والتكرار والصلاحيات للمسودة والعمليات الجديدة

- الحالة: VERIFIED_LOCAL — parser مشترك، فحص مراجع النطاق، منع downgrade والمكتمل، ETag/جيل/replay وصلاحيات المسار القائم.
- نقاط القراءة/التعديل المرشحة: apps/api/src/property/ وخدمات property وآلية idempotency الحالية. تحقق من المستهلكين؛ لا تعدل الملفات لمجرد ورود اسمها.
- النتيجة المطلوبة: رفض مباشر خارج الواجهة وgeneration قديم؛ replay لا يكرر الأثر.
- التحقق المطلوب: PSR-T10/T11/T15. حالات الاختبارات وتوقعاتها في docs/101.
- الدليل الفعلي: final-pg.log — 9/9، مع سباق الكاتبين والجيل القديم ومراجع منشأة أخرى ورفض القارئ وإعادة التكرار. Property كامل434/434؛ التفاصيل في التسليم النهائي أدناه.

## شروط تسليم البطاقة

1. كل مهمة لها دليل، وخريطة أثر docs/95 §5 مكتملة بـDONE أوN/A مبرر.
2. لا تعديل D/حدود العزل/المحاسبة أو الهجرات المطبقة، ولا تنفيذ امتداد مؤجل.
3. فشل تابع لمهمة سابقة يمنع إغلاق هذه البطاقة؛ لا mock لإخفاء API ناقص.
4. اختبارات التطبيق ليست مطلوبة لوثائق فقط؛ العقود والكود يحتاجان الفحوص الملائمة ثم check لإغلاق الكود.
5. الحالة النهائية لا تتجاوز الأدلة؛ ACCEPTED_LOCAL قرار المستخدم وفق سير العمل.

## سجل الدفعة الأولى — تاريخي، يليه التسليم الأحدث

التفويض: «اكمل التنفيذ». بقيت PSR-01 REVIEW_PENDING؛ استكمل العمل المستقل على العقد والتوافق وفق docs/100 §7 دون ادعاء قبول النموذج.

التغييرات: schemas V2 تصميمية، تصدير نوع SetComponents، مترجم اقتراح داخلي لا يُستدعى منHTTP، 11 اختباراً، وحارس عقد/وثيقة تشغيل. لا endpoint أو SQL أو هجرة أو تغيير بيانات.

النتائج المفتوحة: PSR-A01/A05 موثقتان في العقد؛ حل IDs للموقع والجناح محكوم بالنطاق لاحقاً. لا مقارنة لخطة الإنشاءv1/v2 في قاعدة فعلية بعد. لا قبول مستقل.

الخطوة التالية: إتمام02.1 بتوسعات phase4 وعقد إضافة الوحدات بعد التفعيل، ثم DTO/runtime لـv2 مع تخزين الإصدار وحماية المسودة المكتملة واختبارات T10/T14/T15. يجب تغيير حارس design-only في contracts.mjs مع أدلةHTTP/PG الفعلية عند الربط، لا قبله. Applyv2 يبقى مغلقاً حتى محركPSR-04؛ لا تمرر v2 إلى محركv1.

## متابعة التنفيذ بعد طلب «أكمل باقي المرحلة»

الحالة الأحدث تتقدم على سجل الدفعة الأولى أعلاه. أُكملت مهام02.1..02.3 ضمن نطاق المسودات والعقود؛ لا قبول مستقل بعد.

- Save/Get/Discard يدعم الإصدار2 على المسار نفسه. JSONB القائم يحمل الإصدار دون هجرة. المصدر setup-v2.ts وsetup-service.ts وsetup-repository.ts وsetup.controller.ts والأنواع المولدة.
- منع الحقول الخادمية والتناقضات والمراجع المفقودة أو الدائرية والأكواد المكررة، مع السماح بالحقول الناقصة. مراجع UUID تُقرأ داخل نطاق tenant/property.
- completed محمي من الحفظ والحذف، وv2 محمي من downgrade. محركv1 لا يستقبلv2؛ المعاينة والتنفيذ والجاهزية والتفعيل ترفضه حتىPSR-04.
- المعالج القديم يعرض حالة قراءة فقط للمكتمل وv2، بمفتاحين في اللغات الثلاث. لا ربط وهمي لنموذج الأربع خطوات.
- عقود المكان فيphase4 وعقد إضافة الوحدات المستقل فيSET تصميمية صريحة لمراحلها التالية؛ لا routes غير منفذة. التفاصيل في [وثيقة العقد](PSR-02-contract.md).
- تحديث خمسة اختباراتSET كان ضرورياً لأنها كانت تسمح بإعادة فتح المسودة المكتملة. لم تُحذف اختبارات الحصرية أو الأوراق؛ بُنيت fixtures مستقلة لها.

الأدلة:30/30 وحدة وتوافق؛60/60 PostgreSQL في خمس حزم مركزة؛434/434 في57 حزمةProperty كاملة، exit0 في `.local/verification/PSR-02/v2-property-final.log`. يتضمن ذلك9 اختباراتPSR جديدة. الفحص الكامل الأول429/434 أظهر الاختبارات الخمسة ذات الفرضية القديمة، وسجلهv2-property-full.log محفوظ.

خريطة الأثر الأحدث: DTO والخدمة والقراءة والمعاملة والتزامن والتكرار والإصدار والتوافق والعقود والواجهة والترجمة DONE ضمن نطاق المسودة. البيانات N/A لهجرة لأن JSONB يدعم الإصدار. حدث setup_draft.saved الحالي محفوظ. الهوية والتفويض يستخدمان مسار الخدمة الحالي. التشغيل والقنوات والمال N/A لعدم إنشاء مخزون. لا ادعاء قبول مستقل.

القبول: T10 وT14 وT15 مثبتة لنطاق مسوداتAPI. T11 الخاص بإنشاءv2 يبقىPSR-04؛ المثبت الآن Save replay ورفض التنفيذ غير المدعوم. لاAT قناة حية أو قبول جديد لـG-13.

الخطوة التالية بعد التسليم: PSR-03 لشجرة المكان والهجرة والقراءة المرتبة. PSR-04 لمحرك إنشاء المخزون؛PSR-05 لربط واجهة الأربع خطوات بالحفظ والمعاينة والتنفيذ. لا تتجاوز هذه التبعيات بادعاء أن حفظv2 ينشئ وحدات فعلية.
