# P02-04: Dispatcher وPoll/ACK وRetry/DLQ وCheckpoint

الحزمة / التاريخ / المنفذ: P02-04، 13 سبتمبر 2026، Asia/Makassar، نموذج التنفيذ المفوَّض.

الحالة: VERIFIED آلياً على PostgreSQL فعلي.

السلوك المنفذ وحدوده: سحب ذري (صفحة المحاكي ثم معاملة واحدة تخزن revisions وتقدم cursor تحت `pg_advisory_xact_lock` لكل اتصال/stream؛ cursor متغير أثناء الطلب يعطي `StaleCursorError` بلا أثر)، ACK مطبوع الحالة مع إعادة آمنة (تسجيل المحاولة قبل النداء ثم تحديث الحالة بعده؛ crash بعد الإرسال لا يمنع إعادة ACK بالمفتاح نفسه)، Dispatcher يعمل lease بـ`SKIP LOCKED` وينشئ Attempt لكل محاولة ويترجم النتائج: `CHANNEL_VERIFIED`/`ACKNOWLEDGED`/`PARTIAL`/UNKNOWN/REJECTED، retry بbackoff أسّي محدود وجيتر حتمي مشتق من معرف الحدث، و`Retry-After` يحترم عند 429، وDLQ + Exception عند الرفض الدائم أو استهلاك المحاولات، وإعادة DLQ تتطلب سبباً وفاعلاً وتحافظ على payload الأصلي. عزل السام: حدث معطوب لا يمنع بقية الاتصالات في الجولة نفسها. Runtime يجمع dispatch+ack، وscheduler يستخدم BullMQ عند توفر Redis ويرجع تلقائياً إلى interval عند فقده، مع interval احتياطي siempre (lease يمنع الازدواج). PostgreSQL مصدر العمل؛ BullMQ مجرد مؤقت. لا سحب تلقائي لاتصالات غير مهيأة تشغيلياً ولا شاشات.
