# إصلاح عيوب المراجعة المستقلة R1..R6

التاريخ: 13 سبتمبر 2026، Asia/Makassar. المنفذ: نموذج التنفيذ المفوَّض وفق [تكليف Phase 2/3](../38_deepseek_phase3_assignment.md). المرجع: [المراجعة المستقلة](../37_phase2_independent_review.md).

## الحالة

نتيجة المراجعة المستقلة اللاحقة: **PARTIALLY_REMEDIATED / CHANGES_REQUIRED**؛ بقيت F1..F3 ضمن R2/R5 في [مراجعة الإصلاح](../39_remediation_independent_review.md). الوصف التالي تقرير المنفذ قبل هذه المراجعة، وليس الحالة المقبولة الحالية. لا يبدأ P03 بعد.

**REMEDIATED / REVIEW_PENDING.** أُصلحت النتائج الست P1 مع اختبارات regression دائمة تعمل على PostgreSQL حقيقي أو خادم HTTP محلي. عالجت المراجعة المستقلة اللاحقة بقايا F1..F3 في [سجل الإكمال](P02-F1-F3.md)، والحالة النهائية للمنفذ REMEDIATED / REVIEW_PENDING بانتظار مراجعة مستقلة تالية؛ لا يبدأ P03.

## الإصلاحات

### R1: ملكية ذرية وfencing لنتائج Outbox

- السبب: تحديث نتيجة الحدث وزيادة العداد كانا يشترطان ID فقط، وlease الدفعة قد ينتهي أثناء انتظار الإرسال.
- الإصلاح: عمود `lease_token uuid` يتجدد عند كل حجز، وتجديد lease قبل الإرسال مباشرة، وكل كتابة نتيجة/زيادة محاولة/إعادة جدولة تشترط `lease_owner + lease_token + status='LEASED'`. فقدان الملكية يعيد `null` فلا تُكتب نتيجة عامل قديم ولا تُمسح ملكية الأحدث، ويسجل `DispatchSummary.lost`.
- الملفات: `persistence/outbox-repository.ts`، `application/dispatcher.ts`، `persistence/types.ts`، المهاجرة `Migration20260913130000_distribution_fencing_ack.ts`.
- الأدلة: `tests/distribution/integration/fencing.pg.test.mjs` — استرجاع الحدث بعد انتهاء lease، رفض كتابة المالك القديم، رفض زيادة العدّاد وتجديد lease، عاملان بحواجز تأخير، ودفعة انتظر فيها حدث حتى أُعيد حجزه فتُخطي ولم يُرسل.

### R2: حجز ACK دائم واستعادة آمنة

- السبب: قفل `SKIP LOCKED` ينتهي مع الcommit ويظل السجل قابلاً للحجز فوراً، فتُستنفد المحاولات دون إرسال.
- الإصلاح: حجز دائم بـ`ack_lease_owner/token/expires_at` وزيادة العداد عند الحجز، `ack_next_attempt_at` للـbackoff وRetry-After، `updateAckResult` مشروط بالتوكن، sweep للمحاولات المهجورة بعد انتهاء المهلة إلى استثناء `ACK_EXHAUSTED`، وإعادة معالجة مصرح بها (`requeueExhaustedAck`) تتطلب فاعلاً وسبباً.
- الملفات: `persistence/inbox-repository.ts`، `application/ack-service.ts`، `persistence/types.ts`، المهاجرة.
- الأدلة: `tests/distribution/integration/ack-recovery.pg.test.mjs` — عاملان وACK معلق، استرجاع بعد crash بعد الإرسال، استنفاد آخر محاولة مهجورة ثم requeue، واحترام `retry-after` قبل موعده.

### R3: يقين صحيح بعد الإرسال

- السبب: `ECONNRESET/EPIPE` صُنفا قبل الإرسال، وinvalid JSON/oversize بعد رد HTTP صُنفا `NOT_SENT`.
- الإصلاح: `NOT_SENT` فقط لأخطاء ما قبل الإرسال المثبتة (`ECONNREFUSED/ENOTFOUND/EAI_AGAIN/EHOSTUNREACH/ENETUNREACH`) ولرفض السياسة قبل الطلب؛ أخطاء القراءة بعد الرد والانقطاع الغامض والمهلة وredirect وinvalid JSON/oversize كلها `UNKNOWN`.
- الملفات: `adapters/channex/http-client.ts`، `adapters/channex/channex-adapter.ts`.
- الأدلة: `tests/distribution/safety.test.mjs` — خادم محلي استقبل POST ثم رد JSON تالفاً أو تجاوز الحد أو قطع الاتحاد؛ كلها `UNKNOWN` ولا شيء منها `NOT_SENT`، مع بقاء `ECONNREFUSED` ورفض السياسة قبل الشبكة `NOT_SENT` بلا أي استدعاء.

### R4: local-only افتراضي

- السبب: `live=false` كان يفرض TLS عند true فقط ولا يحصر الاتصال في loopback.
- الإصلاح: المضيف الخارجي مرفوض قبل الشبكة حتى لو كان allowlisted، ما لم يُفعَّل `live=true` و`allowExternal=true` معاً؛ TLS يبقى شرطاً للوضع الحي. لم يُفعَّل live في هذا التكليف.
- الملفات: `adapters/channex/http-client.ts`.
- الأدلة: `tests/distribution/safety.test.mjs` — صفر استدعاءات fetch لمضيف خارجي في الافتراضي و`allowExternal` وحده، ومنع HTTP الخارجي في وضع live، وقبول الخادم المحلي.

### R5: لا نص مزود حر في التخزين الآمن

- السبب: تحذيرات المزود الحرة كانت تُقص وتُحفظ في `SyncAttempt.response_safe`، و`provider_request_id` يُحفظ كما ورد.
- الإصلاح: `sanitizeWarningCodes` تحوّل أي نص لا يطابق رمزاً آمناً إلى `PROVIDER_WARNING` وتبقي الأكواد، و`sanitizeProviderRef` يقبل فقط المراجع المطابقة لنمط آمن؛ طُبق ذلك في Adapter عند الرد وفي Dispatcher قبل `response_safe` وoutbox.
- الملفات: `domain/safety.ts`، `adapters/channex/sanitize.ts`، `adapters/channex/channex-adapter.ts`، `application/dispatcher.ts`، `application/ack-service.ts`.
- الأدلة: `tests/distribution/safety.test.mjs` و`tests/distribution/integration/preparation.pg.test.mjs` — قيم canary بريد/PAN لا تظهر في نتيجة Adapter ولا في محاولة إرسال مخزنة، مع بقاء أكواد تشخيصية.

### R6: أخطاء التحضير الدائمة والمؤقتة

- السبب: فشل resolve/capability/parse قبل `startAttempt` كان يُبتلع في catch خارجي بلا محاولة أو سبب أو DLQ، فيُعاد للأبد.
- الإصلاح: مسار تحضير مستقل ينشئ محاولة ويسجلها؛ الدائم (`VALIDATION_FAILED/NOT_FOUND/UNSUPPORTED/CONFLICT/AUTH_FAILED`) إلى DLQ واستثناء `PREPARATION_FAILED`، والمؤقت يعاد بحد حتى `ATTEMPTS_EXHAUSTED`، مع احترام fencing وعدم الإبلاغ عن retry لم يُحفظ.
- الملفات: `application/dispatcher.ts`.
- الأدلة: `tests/distribution/integration/preparation.pg.test.mjs` — payload غير صالح، provider مفقود، فشل تحضير مؤقت محدود يعاد ثم ينجح، وأحداث سامة تتوقف بعد عزل التحضير ولا تجوّع اتصالاً سليماً.

## المهاجرة وسياسة اللقطات

- مهاجرة جديدة `Migration20260913130000_distribution_fencing_ack` تضيف `lease_token` و`ack_lease_*` و`ack_next_attempt_at` وفهرس due؛ لم تُعدل المهاجرة المطبقة السابقة، وطُبقت على قاعدة التطوير المحلية وعلى قاعدة جديدة وقاعدة ببيانات اصطناعية في `test:distribution`.
- وفق ملاحظة docs/37: تبقى اللقطة المرجعية `packages/backend/src/persistence/migrations/.snapshot-hotel.json` كمصدر لمهاجرات لاحقة، وتُستبعد لقطات قواعد الاختبار من الحزمة وتُحذف بعد التشغيل، وصُحح وصف سكربت البصمات.

## الحدود والمراجعة

- لا اتصال قنوات حي، ولا RLS (P03)، ولا AT-C، ولا ادعاء exactly-once خارجي؛ fencing يمنع كتابة عامل قديم ولا يمنع أثر طلب خارجي متأخر، وهذا يبقى ضمان P05/P13.
- الإصلاح لم يمر بمراجع مستقل بعد. الحالة النهائية **REVIEW_PENDING**؛ يلزم اعتماد المراجعة أو تغيير الشرط صراحة قبل بدء P03-01..06، و P03 لم تبدأ.
