# إعادة التحقق المستقلة لـ SET-05

التاريخ: 22 سبتمبر 2026  
النطاق: SET05-R01 وSET05-R02 وSET05-R03 وSET05-O01، سياسة `sharing_scope` المقيدة، معيار E3، وتعريف وتفرد سلوت الجناح.  
الحكم: **GO — قبول محلي مستقل لإغلاق SET-05**.

هذا الحكم محلي فقط. لا يغيّر G-13، ولا يثبت اتصال قناة حية أو قبول إنتاج أو امتثالاً خارجياً. نفذت هذه الجولة بعد تنفيذ الإصلاحات، ولم أعدّل كود التطبيق أو اختبارات القبول. التعديل الوحيد الذي طلبته أثناء الجولة كان إصلاح عنوان مسار `/setup-preview` بعدما أظهر الدليل الأول عبارة `Page not found`؛ أعاد المنفذ الجولة البصرية، ثم راجعت الدليل النهائي.

## الخلاصة

لم يبق عيب حاجز ضمن نطاق SET-05. علاقة الغرفة الأم بأسرتها أصبحت صريحة ومقيدة بالنطاق، ومسارات البيع والتركيبة تمنع استخدام الأب كورقة بيع. الحجب المخطط والطارئ وأمر الصيانة يغطون النسل، والمحاكاة تحسب التوفر الفعلي للأشقاء. قاعدة السعة تمنع إعلان سعة كاملة أعلى من مجموع الأجزاء المعلنة. كما أغلقت السياسة المقيدة بالفشل المغلق على طبقتي الإدخال والتوفر، وأصبح سلوت الجناح هوية منطقية فريدة داخل المنشأة مع اختبار قاعدة بيانات فعلي للتكرار.

## الفحوص المنفذة في هذه الجولة

- `pnpm test:property:fast -- --filter=setup-compositions --bail` → **16/16** في حزمة واحدة، مع قاعدة اختبار جديدة وهجرات حتى آخر إصدار.
- `pnpm check` النهائي → **99/99** في 14 حزمة، مع نجاح build وOpenAPI 9/9 SET وtypecheck وlint وPrettier.
- فحص SQL مضاد داخل `BEGIN/ROLLBACK` → الفهرس `product_setup_unit_slot_unique` موجود، والتكرار داخل المنشأة مرفوض بـ`23505` دون إبقاء أي تعديل.
- مراجعة تقرير Playwright النهائي واللقطة الأصلية → **34/34** و11 لقطة؛ فحص صريح يؤكد أن `/setup-preview` يحمل عنوان الإعداد ولا يعرض غلاف not-found.

الجولة الأولى من `pnpm check` كشفت أن تعديل E3 الجديد لم يكن منسقاً؛ أصلحه المنفذ، ثم نجحت الإعادة الكاملة. كذلك كشف الفحص البصري الأول عنوان `Page not found` على مسار صالح؛ أضيف المسار إلى خريطة العناوين وفحص انحدار، ثم نجحت إعادة E3. هاتان نتيجتان مصححتان وليستا حدوداً متبقية.

## قراءة الضوابط

- علاقة الاحتواء ذات FK مركب تمنع أباً من شركة أو منشأة أخرى، والفحص الذاتي يمنع `parent_resource_id = id`.
- مسار المرشح اليدوي ومسار التركيبة اليدوية يرفضان المورد الأب، فلا يقتصر الإصلاح على معالج SET.
- سلوت الجناح ليس مخزوناً مستقلاً؛ أوراق التركيبة وحدها تحمل الحصرية. بحث المحاكاة بالسلوت يحدث عندما لا يوجد مورد مادي بالكود، بينما preflight الخاص بالتطبيق يمنع تصادم كود SET مع مورد قائم.
- `FEMALE/MALE` يظلان مفهومين محفوظين في نموذج Phase 4 للبيانات القديمة، لكن لا يمكن إنشاء وعد بيع جديد بهما ولا حجز منتج قديم يحمل أحدهما حتى ينفذ SET-07 أهلية النزيل.

## حدود غير حاجزة

- فرض أهلية `FEMALE/MALE` فعلياً مؤجل إلى SET-07؛ السلوك الحالي المقصود هو الرفض الكامل، وقد ثبت.
- تعديل أوراق تركيبة عليها حجوزات مستقبلية بنسخة مؤرخة هو SET-06.
- تشغيل المكتب الأمامي متعدد المكونات ودخول/خروج/نقل الأجزاء والأسرة هو SET-07.
- مجلد وتسمية تقرير المتصفح ما زالا تحت `SET-01` لأن نفس رحلة المعالج أعيد استخدامها؛ أسماء فحوص E3 واللقطة تحدد دليل SET-05 بوضوح. هذه ملاحظة تنظيمية فقط.

## القرار

تُغلق SET-05 بحالة **VERIFIED_LOCAL (INDEPENDENT GO)**. الخطوة التالية وفق التبعيات هي SET-06، مع إبقاء الحدود أعلاه في حزمها وعدم تحويل هذا الحكم إلى قبول إنتاجي أو قبول G-13.
