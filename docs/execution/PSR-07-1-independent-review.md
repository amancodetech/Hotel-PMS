# مراجعة PSR-07.1 المستقلة

1 أكتوبر 2026 — المراجع GPT-6 Astra، والمنفذ GPT-6.1 Sol. استُخدمت مهارة `agency-code-reviewer`. النطاق T08/T22/T24 ودورة الأنماط المدعومة؛ لا PSR-07.2 أو PSR-08، ولا تغيير D-20 أو G-13.

## الحكم الحالي

**PASS لنطاق PSR-07.1 محلياً**: PostgreSQL المستقل والانحدار المرتبط8/8، والمتصفح المصحح7/7، بلا finding مانع مثبت مفتوح. يمكن متابعة PSR-07.2 وفق التفويض المتسلسل؛ لا يغلق هذا الحكم PSR-07 كاملة ولا يمنح ACCEPTED_LOCAL أو قبولاً إنتاجياً أو يغير G-13. لم يعدل المراجع التطبيق أو يشغل الخدمات أو الهجرات؛ المنسق نفذ الأوامر واختبارات المراجع.

## فحص المصدر

- projection المكان تقيد المورد والأب والمكان وكل أسلافهما بـtenant/property، وتختار أقرب مكان غير فارغ؛ مصفوفتا visited تمنعان الدوران. joins في الاستقبال والتدبير مقيدة بالنطاق. الاسم المعروض لا يغير ID الاختيار، ويحتفظ بكود داخلي يميز الأسماء المتكررة. حقول القراءة اختيارية للتوافق.
- خروج الإقامة المركبة يترجم `resource_ids` إلى مهمة لكل ورقة مع إزالة التكرار، داخل المعاملة القائمة. intake يبحث عن المكونات المفقودة ولا يعيد كتابة المهام السابقة، ويستعمل `vacate: false` فلا يعيد تلويث مورد نظفه موظف بعد الحدث التاريخي.
- هجرة `Migration20261001090000_ops_task_components` تغير الفهرس فقط: التفرد هو tenant/property/event/resource، مع NULLS NOT DISTINCT. up لا يعدل بيانات التاريخ؛ down يفحص التعدد قبل إسقاط الفهرس ويرفض الرجوع المدمر. التطبيق المحلي مع إيقاف الخدمة ثم ترقية وتشغيل النسخة الجديدة مناسب؛ لم تُثبت ترقية متدرجة تتعايش فيها نسخة تطبيق قديمة تعتمد conflict target القديم مع المخطط الجديد.
- حارس المشاركة في consumer يأتي قبل تحرير تخصيص الالتزام؛ الخطأ يخرج من المعاملة ويُسجل كاستثناء دائم في معاملة لاحقة. اختبار المنفذ يدعو `/inbox/:revision/reprocess` فعلياً، ويتحقق من بقاء ستة جداول؛ source=OTA وحده ليس دليل consumer.
- import وgroup لهما حراسان قائمان؛ طلبت ضم `set07-sharing` إلى التشغيل المستقل لاستكمال أدلة T08. v2 ينشئ MIXED فقط، وFEMALE fixture تاريخية اصطناعية عبر SQL، وليس خياراً مثبتاً في معالج v2.
- اختبارات الأنماط تمر عبر إنشاء v2 ثم عرض/تخصيص/دخول/تقارير/خروج/تدبير. التقرير يفصل display nights عن resource nights. T22 يختبر أن مجموع الليالي المتاحة في موارد مختلفة لا يحقق استمرارية غرفة واحدة.

## الاختبارات المستقلة

الملف `tests/property/psr07-1-independent.pg.test.mjs`؛ syntax وPrettier وESLint نجحت. نفذ المنسق:

```text
pnpm test:property:fast -- --filter='psr07-1-independent|set07-sharing' --bail
```

النتيجة المقروءة من السجل الخام: **8/8 في حزمتين، exit0، 8.326 ثانية**؛ أربع حالات مستقلة جديدة وأربع حالات set07-sharing. السجل `.local/verification/PSR-07.1-independent/postgres.log` وملف `postgres.exit`.

أربع حالات مستقلة جديدة:

1. حفظ كامل صف مهمة INSPECTED مع إنشاء المكون الناقص عبر ثلاثة intake متزامنة، ثم replay بلا أثر.
2. الحالة نفسها لمهمة CANCELLED، دون إحياء التاريخ أو تكراره.
3. تشغيل SQL الهجرة الحقيقي على schema اختبار مستقلة: حفظ التاريخ ذي المورد NULL، رفض تكراره، قبول مورد جديد للحدث نفسه، ورفض down مع حفظ الصفوف.
4. تشغيل projection SQL الحقيقي على schema مصطنعة: أولوية مكان BED، وراثة الأقرب، قطع علاقات tenant/property الأجنبية، ودورات الموارد والأماكن.

الحالتان الأخيرتان اختبار SQL معزول وليستا اختبار RLS بدور التشغيل أو ترقية قاعدة إنتاج. fixtures التاريخية للحالتين الأوليين تستخدم owner SQL؛ intake نفسه يستخدم ORM بدور API. لا يُدعى اختبار قناة حية أو حساب خارجي.
