# P05-02 مخطط الالتزام والتخصيص والحجب والحصص

التاريخ: 14 سبتمبر 2026. الحالة: IMPLEMENTED / VERIFIED محلياً.

## السلوك المنفذ وحدوده

- `commitment`: مصدر الالتزام HOLD/ITEM/GROUP مع حالة ACTIVE/RELEASED/EXPIRED/CONVERTED ومهلة
  `expires_at` و`inventory_version`؛ كل مورد مثبت داخلياً قبل أي وعد.
- `plan_allocation`: موارد الالتزام وفتراتها؛ قيد استبعاد GiST يمنع أي تداخل لتخصيصات ACTIVE
  على نفس المورد — دفاع قاعدة بيانات مستقل عن فحص الخدمة.
- `inventory_block` + `inventory_block_resource`: حجب مخططة/طارئة؛ الحجب المخطط لا يتقاطع مع
  تخصيص قائم (فحص تحت قفل Property)، والطارئ يحفظ الالتزام وينشئ `inventory_disruption`.
- `exposure` + `exposure_allocation`: حصة قناة محمية لكل مورد/فترة (DIST-007) بقيد استبعاد
  يمنع حصتين فعالتين على نفس المورد/الفترة؛ يستخدمها P05-05 (D-20) ويمنع التخصيص المحلي.
- `sale_restriction` و`exposure_preview`: تجهيز Open/Stop Sell ومعاينة بنسخة.
- كل الكتابات تمر بمسار الضمان: `lockTenantAuthz` عند تغيير السلطة ثم قفل صف `property`
  وقراءة الحالة بعده ثم الكتابة في المعاملة نفسها مع `inventory_version` وAudit.
- كل منشأة لها صف قفل مستقل؛ منشأتان لا تتشاركان قفلاً.
- PostgreSQL فقط للضمان: لا Redis lock ولا عدادات يومية.
