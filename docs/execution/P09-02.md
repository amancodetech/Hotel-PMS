## السلوك المنفذ وحدوده

- `ops_work_order`: دورة Open→Triaged→Assigned→In Progress→Resolved→Verified→Closed
  مع تعيين/إعادة تعيين آمنة، وملاحظة حل إلزامية عند Resolved.
- `impact` = NONE/OOS/OOO: الحالة الفعلية للمورد تُشتق من **الأوامر المفتوحة فقط** (`maxImpact`)،
  فإغلاق أمر لا يرفع سبباً آخر مفتوحاً (AT-O03)، وإعادة الفتح بسبب موثق لا تتجاوز سبباً أحدث.
- Emergency (OOO + فترة + `maintenance.emergency` MFA): تُنشئ Inventory عقدها
  (`createEmergencyMaintenanceBlock`) Block طارئاً وDisruption لكل تخصيص متعارض دون مساس
  بالحجز/الالتزام؛ إغلاق الأمر يحلّ Disruptions الخاصة ببلكه ولا يحرر أي Block
  (التحرير عبر `ReleaseBlock` فقط)، والحجز لا يُمحى.
- الكتابة للمخزون عبر عقد inventory فقط؛ صلاحيتان جديدتان `maintenance.read/manage`
  وبقاء `maintenance.emergency` (MFA).
- الحدود: لا واجهة (P09-03)، لا تغيير لقواعد P05، لا OTA ولا مال.
