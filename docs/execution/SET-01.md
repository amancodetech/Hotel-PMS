# SET-01 — نموذج تفاعلي للمعالج والإعدادات

الحالة: **VERIFIED_LOCAL (نموذج مراجعة؛ ليس ميزة منفذة)**.
التاريخ: 21 سبتمبر 2026.
التبعية: SET-00 VERIFIED_LOCAL.

## التفويض والحدود

- ضمن تفويض الجلسة: تنفيذ الحزم المحلية؛ SET-01 مخرجه **نموذج تفاعلي للمراجعة** وليس API منفذاً (docs/95:107).
- النموذج للعرض المحلي فقط: لا يكتب خلفياً، ولا ينشئ منشأة، ولا يوحي بحفظ خادمي. حفظ المسودة في هذا النموذج محلي بالمتصفح ويُعلن ذلك في الواجهة.
- لا تغيير على خدمات المجال أو العقود أو الهجرات في هذه الحزمة.

## السلوك المطلوب

- مصطلحات تشغيلية واضحة (docs/94 §2) بثلاث لغات ar/id-ID/en-US مع RTL.
- رحلة بسيطة (فندق غرف) ورحلة مركبة (فيلا كاملة/أجزاء، أسرة، جناح متصل، موقع) بحيث تظهر الأسئلة ذات الصلة فقط.
- حالات: تحميل، فراغ، خطأ، منع، حفظ/تعذر حفظ، تعارض نسخة، استئناف مسودة، فشل شبكة محاكى، إعادة محاولة.
- معاينة أرقام الوحدات مع استثناءات وتكرار، ومراجعة أثر البيع (محاكاة) دون إنشاء حجز.
- موبايل 390px بلا قص إجراءات، ولوحة مفاتيح/تركيز ظاهر.

## معايير النجاح/الرفض/الفشل

- نجاح: سيناريوهات المراجعة الأربعة قابلة للتنفيذ في النموذج: إضافة فندق بسيط، فيلا خاصة، فيلا أجزاء، استئناف مسودة — مع تحقق بصري بثلاث لغات وRTL و390px.
- رفض: منع إتمام خطوة ناقصة (اسم/رمز/وحدات/طريقة تأجير/إقرار خصوصية) برسائل خطأ بجوار الحقول وملخص.
- فشل: حفظ محاكى يفشل → حالة «تعذر الحفظ» + إعادة محاولة، ولا رسالة نجاح كاذبة.
- تعارض: تبديل حالة التعارض يُظهر مقارنة ويسمح بالاحتفاظ بنسختي أو تحميل المحفوظ، بلا سحق صامت.

## خطة التحقق

## findings وملاحظات مرحلة إلى SET-02

1. **لا مسودة خادمية**: النموذج يحفظ محلياً فقط. SET-02/03 يحتاجان كيان مسودة بنطاق tenant/property، خطوة، رقم نسخة، وحفظ idempotent.
2. **تعارض النسخ**: يلزم `If-Match`/version و`409` مفهوم مع مقارنة، لا آخر حفظ يفوز.
3. **المعاينة**: توسيع النطاق/الاستثناءات/التكرار يجب أن يُحسب خادمياً في `preview` بلا كتابة، والتنفيذ يعيد التحقق داخل معاملة.
4. **الجاهزية**: قائمة نواقص خادمية مستقلة عن «الاكتمال» وعن فتح البيع وتفعيل القنوات.
5. **طريقة التأجير**: تحتاج كياناً/حقولاً معلنة (EXCLUSIVE / WHOLE_OR_PARTS / BEDS) وإقرار خصوصية ونطاق مشاركة وعدد أسرة وتجهيز مضمون — دون محرك مخزون موازٍ (تُبنى على Resource/Product/Composition/Exposure الحالية).
6. **القوالب**: catalog خادمي (قالب→نوع مورد/افتراضيات) بدل تثبيت الواجهة، مع ترقيم دفعات واستثناءات.
7. **المحاكاة**: في التنفيذ الحقيقي تُحسب خادمياً ولا تنشئ حجزاً؛ حد النموذج الحالي أنه حساب عميل.
8. **حدود النموذج**: لا API، ولا قيم افتراضية صامتة للتوقيت/العملة، وعدّادات الفيلا تعرض 3 أجزاء ثابتة للتوضيح فقط.
