## السلوك المنفذ وحدوده

- استهلاك حدثي `STAY_CHECKED_OUT` و`STAY_MOVED` من P07-03: مهمة تجهيز واحدة لكل حدث
  (`ops_task.source_event_id` بفهرس فريد جزئي) والمغادرة المكررة/إعادة العامل لا تضاعفان
  المهمة؛ التحقق عبر `runOperationsIntake` أيضاً.
- دورة المهمة: PENDING → ASSIGNED → IN_PROGRESS → CLEAN → INSPECTED (وINSPECTED نهائية)،
  مع إعادة تعيين أثناء IN_PROGRESS تترك المورد `CLEANING` بلا جاهزية.
- housekeeping_state للمورد صار يشمل CLEANING: StartTask يضبط CLEANING، CompleteTask يضبط
  CLEAN، InspectTask يضبط INSPECTED عبر عقد property (لا كتابة SQL من operations).
- سياسة منشأة (`property_operations_policy`): `inspection_required` يمنع الجاهزية قبل
  INSPECTED (AT-O02)، و`long_stay_clean_interval_days` يمنع تنظيف الإقامة يومياً؛ بلا سياسة
  لا تنظيف دوري (fail-closed) ومع نسخة (`policy_version` snapshot).
- DND (`ops_dnd_log`): تسجيل وقت/ملاحظة ومحاولة متابعة؛ لا يغير housekeeping (AT-O04).
- الفحص الذاتي مرفوض عندما تشترط السياسة فحصاً (`SELF_INSPECTION_DENIED`).
- الحدود: لا واجهة (P09-03)، لا Work Orders/OOO/OOS/Disruption (P09-02)، لا OTA،
  لا مال، لا PAN/CVV، لا قرار D جديد.
