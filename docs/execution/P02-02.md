# P02-02: المحاكي deterministic

الحزمة / التاريخ / المنفذ: P02-02، 13 سبتمبر 2026، Asia/Makassar، نموذج التنفيذ المفوَّض.

الحالة: VERIFIED آلياً (طبقة نقل، لا شاشة).

السلوك المنفذ وحدوده: `SimulatorEngine` حتمي بالكامل: seed مخزّن، ساعة افتراضية قابلة للتقدم صريحاً، ترتيب تسليم مخصص، تكرار تسليم، خطط فشل لكل عملية (timeout قبل/بعد الإرسال، 429، 5xx، رفض تحقق، فشل مصادقة، partial)، cursor معتم base64url، ونتائج قدرات/إحصاءات قناة صريحة. `SimulatorAdapter` ينفذ `ChannelAdapter` ويمرر كل مدخل/مخرج عبر تحقق Zod ويمرر بوابات القدرات؛ لا شبكة. خمس وصفات قنوات اصطناعية (new→modified→cancelled) عبر `lifecycleSeeds`، وملف قناة سادسة اصطناعية `test-sixth-channel` غير مدرج في كتالوج الإنتاج، وfixtures خرائط. استدعاء `inspectCapabilities` قد يفشل بحسب الخطة، بينما بوابات الدفع تقرأ لقطة القدرات دون استهلاك خطط الفشل.

المراجع: CAP-13، DIST-001..004، P02-02 في docs/32، docs/33، AT-17..21.

الاعتمادات والبوابات السابقة: P02-01 (العقد والتحقق والبوابات) مغلقة، G-01 مغلقة.

الملفات المعدلة: `packages/backend/src/modules/distribution/adapters/simulator/{engine,fixtures,simulator-adapter,index}.ts`؛ تصدير المحاكي من `modules/distribution/index.ts`؛ `tests/distribution/simulator.test.mjs`.

الاختبارات: `NODE_OPTIONS=--experimental-vm-modules pnpm exec jest --runInBand tests/distribution` → 29/29 عبر 3 suites (تتضمن 13 اختبار محاكي). تثبت: دورة حياة كاملة بصفحات وcursor غير قابل للاستنتاج، تطابق إعادة التشغيل لنفس seed، تكرار التسليم لا يطبق مرتين، إعادة الترتيب لا تحيي ملغى، غياب Mapping يظهر كقائمة فارغة بلا تخمين، خمس قنوات تمر من Adapter واحد، 429 يحفظ retry_after ثم ينجح، timeout بعد الإرسال UNKNOWN ثم ينجح، partial ليست نجاحاً ولا ترفع دليل القناة، رفض التحقق REJECTED، بوابة قدرة تمنع الدفع عند ملف مجهول، ورفض cursor/limit/snapshot غير المتطابق.
