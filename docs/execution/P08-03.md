# P08-03: التحصيل النقدي والتحويل وPOS وتسويات OTA وحالات الدفع ومطابقة Unknown

التاريخ: 15 سبتمبر 2026. الحالة: **IMPLEMENTED / VERIFIED محلياً** (الأدلة أدناه). G-08 تبقى
REVIEW_PENDING؛ لا قبول بالنيابة.

## السلوك المنفذ وحدوده

- **RecordPayment**: تحصيل موثق بطريقة `CASH/BANK_TRANSFER/OTA_SETTLEMENT/EXTERNAL_POS`
  ومرجع خارجي إلزامي و`evidence_ref` إلزامي لغير النقد (POS/تحويل/OTA) ومصدر فريد؛ كل تحصيل
  مؤكد يرحّل Journal متوازناً مرة واحدة: مدين حساب الطريقة (`CASH/BANK/POS_CLEARING`) ودائن
  `FOLIO_GUEST`، فوق Idempotency-Key.
- **فصل gross/net/commission (F-08)**: تسوية OTA تحمل `gross_money` و`commission_money` مع
  `gross = net + commission` بقيد قاعدة بيانات؛ القيد: مدين `BANK` بالصافي، مدين
  `COMMISSION_EXPENSE` بالعمولة، دائن `OTA_CLEARING` بالإجمالي — **بلا سطر إيراد جديد** ولا
  تغيير صامت لإيراد الحجز.
- **حالات الدفع ومطابقة Unknown (F-03/AT-F03)**: `certainty=UNKNOWN` ينشئ سجلاً بلا أي قيد؛
  `ReconcilePayment` يحسم مرة واحدة فقط (`SUCCEEDED` يرحّل القيد الوحيد، `FAILED` بلا قيد)،
  وtrigger الانتقال يمنع تغيير حالة محلولة أو تعديل هوية الدفعة، وإعادة التحصيل بنفس المصدر
  ترفض `SOURCE_ALREADY_POSTED`، وإعادة المطابقة `INVALID_STATE_TRANSITION`.
- **AT-F01/AT-F02**: تكرار طلب بنفس المصدر أو نفس مفتاح idempotency بنفس المحتوى لا ينتج
  تحصيلاً ثانياً؛ نفس المفتاح بمبلغ مختلف يرفض (`idempotency_key_reused`).
- **AT-R06**: مسار الدفع لا يلمس المخزون إطلاقاً — لا كتابة على `commitment`/`plan_allocation`
  ولا استيلاء على Hold منتهٍ (المثبت بأثر DB).
- **الإجماليات**: `GetFolio` يضيف `payments` و`payments_total` (المؤكدة فقط) ويخصمها من
  `balance_due`.
- **حدود**: الاسترداد والعكس والتسوية P08-04، الفاتورة/الصندوق P08-05، لا PAN/CVV ولا مزود
  دفع حقيقي (تحصيل محلي يدوي موثق synthetic فقط).
