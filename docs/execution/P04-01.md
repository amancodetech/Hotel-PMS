## السلوك المطلوب وحدوده

- مجموعة منشآت (PropertyGroup) داخل Tenant: code فريد محلياً، دورة ACTIVE/ARCHIVED.
- Property: code فريد داخل Tenant، timezone إندونيسي (Asia/Jakarta|Asia/Makassar|Asia/Jayapura)،
  عملة أساس IDR/USD، مجموعة اختيارية، ملف حدود PERF-01 المؤرخ، `inventory_version` يزداد عند
  تغير مورد، ودورة SETUP→ACTIVE↔SUSPENDED→ARCHIVED بلا حذف.
- Location داخل Property: code فريد داخل المنشأة، ACTIVE/INACTIVE.
- ResourceType كتالوج ثابت بالأنواع الثمانية (ROOM/BED/VILLA/APARTMENT/HOUSE/SITE/TENT/CABIN).
- Resource داخل Property: code فريد داخل المنشأة، نوع من الكتالوج، سعة 1..100، موقع اختياري من
  نفس المنشأة، دورة ACTIVE↔INACTIVE→RETIRED (RETIRED نهائية وتحفظ السجل).
- الرفض: علاقة عابرة Tenant/Property (FK مركبة)، code مكرر، timezone/عملة غير مدعومة، انتقال حالة
  غير صالح، تعديل/حذف سجل RETIRED، تعديل propertyId في المسار لا يطابق المورد.
- الصلاحيات: `property.read` و`property.manage` و`property.resource.manage` من الكتالوج المركزي؛
  owner/admin يملكانها، auditor يقرأ. كل قراءة/كتابة تمر بـ`evaluatePolicy` وRLS بدور التشغيل.
- كل طفرة داخل `runScopedTransaction` + قفل صف Property، مع Audit في المعاملة نفسها.
- حدود صريحة: لا مخزون/توفر/Holds/أسعار (5)، لا منتجات/تركيبات (P04-02/03)، لا قنوات مفعلة
  (P04-04 مسودات فقط)، لا حذف فيزيائي.
