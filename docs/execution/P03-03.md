## سياسات RLS — الجرد الفعلي

- 20 جدولاً بتمكين RLS وFORCE RLS: identity (tenant, membership, role, role_permission, role_grant, grant_property, invitation, approval_request, audit_event) + distribution (11 جدولاً).
- الجداول المعفاة موثقة: `app_user`, `auth_session`, `auth_flow` (هوية/جلسة عالمية قبل سياق العميل) و`permission` (كتالوج عام) و`mikro_orm_migrations`.
- سياسة مباشرة للجداول التي تحمل `tenant_id` (`tenant_id = current_setting('app.tenant_id', true)::uuid`) مع `WITH CHECK` للكتابة.
- جداول distribution بلا `tenant_id` معزولة عبر الأب: capability/mapping/external_booking/inbox/checkpoint عبر `distribution_connection`، attempt عبر `distribution_outbox_event`، dedup عبر inbox→connection. جرد الفهرسة: فهارس tenant على direct tables وفهارس FK قائمة للجداول التابعة.
- `tenant` يسمح للمستخدم بقراءة العملاء الذين لديه عضوية نشطة فيهم (`app.user_id`), و`membership` يسمح بقراءة العضويات الذاتية لاختيار العميل. `invitation` يسمح بقراءة صف واحد فقط عند تطابق `app.invitation_hash` (قدرة التوكن) ويشترط سياق Tenant للكتابة.
- Trigger `prevent_tenant_id_change` على كل جدول يحمل عمود `tenant_id` يمنع تغيير ملكية السجل.
- `distribution_work_tenants()` دالة SECURITY DEFINER ضيقة تعيد معرّفات العملاء الذين لديهم عمل مستحق فقط (لا صفوف)، وهي نقطة اكتشاف Worker؛ عند غيابها (قاعدة أقدم) يعود العامل بلا عمل بدل تخمين نطاق.

## سياق المعاملة

- `set_config('app.tenant_id'/'app.user_id'/'app.invitation_hash', value, true)` داخل `runScopedTransaction` فقط؛ لا GUC بمستوى الجلسة مع pooling.
- API: كل طلب محمي بتفويض يفتح معاملة scoped؛ Worker: `DistributionRuntime.tick` يكتشف العملاء ثم يعالج كل عميل بمعاملة سياق مستقلة، وكل repositories التوزيع تعمل داخل هذا السياق (dispatch, ACK, pull, work discovery).
- اختبارات: نفس اتصال pool بين عميلين، rollback ثم استعلام بلا سياق، عميلان متزامنان، ودور محدود فعلي لكل العمليات أعلاه.

## الاختبارات (tests/identity/rls.pg.test.mjs)

- الجرد: 20 جدولاً FORCE RLS + الإعفاءات + عدم ملكية runtime للأدوار والجداول + غياب superuser/BYPASSRLS.
- عميل A لا يقرأ/يعدل/يحذف بيانات B، وINSERT بمعرف Tenant آخر مرفوض، وتغيير `tenant_id` مرفوض.
- بلا سياق: صفر صفوف ورفض الكتابة.
- تسريب pool: بعد rollback/commit لا يبقى سياق؛ اتصال pool واحد بتتابع عميلين.
- تزامن: جلستان متوازيتان لا تتبادلان الصفوف.
- distribution: عزل الأب، رفض الإدراج عبر أب عميل آخر، دالة العمل، و`leaseDueOutbox` بعامل محدود بعميل واحد فقط.
- audit إضافة فقط: UPDATE/DELETE مرفوضة لدور API، وWorker لا يكتب audit.
- أدوار: `hotel_api`/`hotel_worker` هما المستخدمان فعلاً في الاتصال.
