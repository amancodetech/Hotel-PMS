## جلسة 24 سبتمبر 2026 — التنفيذ والتحقق الجاري

تفويض المستخدم: «حسنا اكمل على PSR-03» ثم «اكمل». أضيفت هجرة جديدة للشجرة وتفاصيل الوحدة فقط؛ لا استنتاج غرف من عدد غرف النوم، ولا إعادة ترقيم أو تغيير نموذج الحجز/المال. الاختبار الأول 9/9 ناجح على قاعدة مؤقتة؛ التحقق الموسع والطقم الكامل لم ينتهيا بعد.

- `parent_id/kind/display_order` على location مع FK مركب وفهرس أطفال وقفل المنشأة ومنع دورات وعمق32. المواقع السابقة جذور غير مصنفة.
- قراءة `tree=true` مرقمة مع المسار؛ مؤشرات موقعة مرتبطة بالشركة والمنشأة والأب وإصدار الشجرة. تغيير الشجرة أو إعادة تشغيل API يبطل المؤشر؛ يرجع العميل لأول صفحة. المؤشر محلي للعملية الحالية (دعم مشاركة المفتاح بين عدة عمليات مؤجل ولا يدعى).
- إنشاء الشجرة يتطلب Idempotency-Key؛ المسار القديم يبقى متوافقاً. PATCH يحفظ الأب عند الإغفال ويفصله عندnull؛ code غير قابل لإعادة الترقيم.
- `display_label` اختياري قابل للتكرار، `unit_details` بيانات وصفية مضبوطة فقط. تصحيح تمرير location_id في PATCH المورد إلى الخدمة، مع اختبار انتقال فعلي.
- الاستيراد القديم يبقى بأعمدته: location هو الكود الفريد للمكان حتى داخل الشجرة. LOCATION_UNKNOWN لا يكشف مواقع خارج النطاق؛ LOCATION_INACTIVE للموقع أو سلفه غير النشط. APPLY ينفذ الصفوف المقبولة معاً داخل معاملة؛ المرفوضة تظهر بالتقرير كما كان السلوك السابق.
- منع إسناد جديد إلى مكان غير نشط أو تحته في مواردAPI/استيراد/تنفيذSET القديم. تعطيل مكان لا يغير موارد وحجوزات قائمة خفية.
- حماية الرجوع قبل أولDDL؛ وجود أي parent/kind/order أو label/details يمنعdown. تفاصيل خطة الاستعادة ستسلم مع التقرير النهائي.

المستهلكون: عقودPhase4/الأنواع المولدة/DTO/client محدثة. واجهة الشجرة الجديدة فيPSR-05؛ صفحات التشغيل فيPSR-07. لا ادعاء أن تغيير المخطط وحده أكمل الواجهة.
