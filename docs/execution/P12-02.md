## السلوك المنفذ وحدوده

- **Onboarding**: `OnboardPlatformTenant` ينشئ Tenant جديداً + أدوار النظام + عضوية المالك (اختيارية
  ببريد مستخدم موجود) + اشتراكاً مثبتاً على أحدث إصدار سياسة ساري + استحقاقات مُبثوقة + عدّادات
  حدود، في **معاملة واحدة** مع سجل دورة حياة ومفتاح idempotency. slug فريد عبر جدول المنصة
  (`platform_subscription.tenant_slug`): إعادة نفس المفتاح تعيد النتيجة المخزنة `replayed=true`،
  ومفتاح مختلف بنفس slug → `409`، وسباق الإنشاء يُعالج بالتقاط `23505` وإعادة القراءة.
  إنشاء سجل `tenant` نفسه يمر بدالة `platform_create_tenant` (security definer تتحقق من فاعل
  منصة نشط) لأن `hotel_api` بلا صلاحية INSERT على `tenant` (أقل صلاحية).
- **التعليق** `SuspendPlatformTenant` (If-Match + Idempotency-Key + سبب إلزامي، `subscription.manage`
  وMFA): يُلتقط **snapshot تجميعي** (writer=PMS، properties/resources، connections_total/active،
  exposures_active/unknown، commitments_active، reservations_open، stays_in_house، journal_rows،
  folios) بلا أي صف عميل أو ضيف، ثم **وقف الزيادات** بإدراج Stop Sell لكل تعرض نشط قابل للبيع
  (`sale_restriction.platform_stop=true`، عبر دالة محكومة)، ثم `tenant.status=SUSPENDED` واشتراك
  SUSPENDED بإصدار +1، ثم حدث `SUSPENDED` append-only وتدقيق منصة ومرآة تدقيق مستأجر.
  **لا يتغير أي مسار استقبال**: الالتزامات والاتصالات لا تُلمس، والاختبار يثبت استمرار معالجة
  revision قناة بعد التعليق (reservation أُنشئ، connection status كما هو، لا حذف/إلغاء).
  حد V1 معلن: **سحب الحصة الخارجية ومطابقتها** يتطلب دليل مزود حي (D-20/P13)؛ P12 يوقف الزيادات
  ويسجل عدّاد التعرضات النشطة/UNKNOWN ليتمكن المشغل من إتمام السحب والمطابقة، ولا يدعي سحباً موثقاً.
- **إعادة التفعيل** `ReactivatePlatformTenant`: تشترط الحالة SUSPENDED؛ إن ظهر إصدار سياسة ساري
  أحدث من المثبت → `409 POLICY_VERSION_STALE` حتى يُرسل `acknowledge_policy_version=true` (حينها
  تُعاد التثبيت مع تدقيق)، ولا تُفعّل استحقاقاً منتهياً بصمت: الاستحقاقات المنتهية تبقى
  `active=false` وتُعلن أسماؤها في `expired_entitlements`. `resume_sales=true` يعيد فتح قيود
  Stop Sell التي أنشأتها المنصة فقط (`platform_stop=true`).
- **الإغلاق** `ClosePlatformTenant`: من ACTIVE/SUSPENDED فقط، `tenant.status=CLOSED` واشتراك CLOSED،
  وبلا أي حذف: الاختبار يقارن عدّادات journal/folio/reservation/commitment/audit قبل/بعد ويثبت
  أن الزيادة الوحيدة هي سطر تدقيق الإغلاق. الانتقالات بعد الإغلاق تفشل مغلقة
  (`TENANT_STATE_CONFLICT`)، وإعادة نفس المفتاح تعيد النتيجة المخزنة.
- **fail-closed**: حالة غير مطابقة أو إصدار قديم → `TENANT_STATE_CONFLICT`/`STALE_VERSION`؛ سبب أو
  If-Match أو مفتاح ناقص → 400؛ صلاحية منشأة لا تدير اشتراكاً (403)؛ دعم/مسؤول بلا MFA → 403.
- **إصلاح أمني مرتبط**: `selectTenant` صار يرفض اختيار منشأة غير ACTIVE بـ`409 TENANT_STATE_CONFLICT`
  (كان يفحص العضوية فقط، وهو خلاف مقصود مع `auth-service` الذي يستبعد غير ACTIVE عند الدخول).
- **سجل append-only** `platform_lifecycle_event` (trigger جمود + منع تغيير tenant + RLS منصة، وقراءة
  مستأجر لسجله) مع `snapshot` يحتوي نتيجة العملية والسلامة، و`response` لإعادة الإنتاج الحرفي.
