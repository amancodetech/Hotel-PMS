# P10-02: حاجز CLOSING ورسوم الليالي مرة واحدة والإغلاق والاستئناف

التاريخ: 16 سبتمبر 2026. الحالة: **IMPLEMENTED / VERIFIED محلياً** (قتل/استئناف عامل فعلي).
G-10 تبقى `REVIEW_PENDING`.

## السلوك المنفذ وحدوده

- **حاجز CLOSING (AT-F07/D-13)**: `CLOSING_BARRIER` ينقل اليوم إلى `CLOSING` ثم `CLOSE_DAY`
  ينقله إلى `CLOSED` ويفتح اليوم التالي `OPEN` في المعاملة نفسها. كل كتابة خارج نافذة
  `OPEN/AUDIT_PREPARING/AUDIT_VALIDATION` ترفض: `CLOSING` ⇒ `409 BUSINESS_DAY_BUSY`
  (قابل لإعادة المحاولة) و`CLOSED` ⇒ `409 BUSINESS_DAY_CLOSED`؛ ولا يُنشأ قيد في يوم مغلق
  (الحاجز في القاعدة `journal_postable_guard` + قفل property + قفل صف اليوم).
- **رسوم الليالي مرة واحدة (AT-F06)**: لكل إقامة مقيمة تلامس ليلة العمل تُرحّل واقعة واحدة
  `source_kind='STAY_NIGHT'` و`source_ref='<item_id>:<business_date>'` عبر finance
  (قيود P08، `journal` متوازن لكل عملة، `posted` غير قابل للتعديل). المفتاح الفريد في
  `folio_charge_source_unique` + فحص المصدر يعيدان الواقعة نفسها عند إعادة التشغيل بدل قيد ثانٍ.
- **خطوات/checkpoints قابلة للاستئناف**: كل خطوة معاملة مستقلة تُثبت `checkpoint` وتحدّث
  qlease؛ إعادة تشغيل worker أو API تستأنف من أول خطوة غير `DONE` وتعيد تشغيل الخطوة
  المتقطعة بأمان idempotent. `night_audit_step` فريد لكل `(tenant, property, business_date,
  step_key)` و`night_audit_run` فريد لكل `(tenant, property, business_date)`.
- **قفل property أولاً**: المحرك يأخذ قفل المنشأة قبل run/اليوم/الدفتر (نفس ترتيب كل كتّاب
  المخزون/المال)، ما يمنع الجمود مع ترحيل متزامن ويجعل الفائز واحداً. منح العامل `update` على
  `property` لهذا الغرض فقط (مهاجرة `…180000`)، ويبقى الدفتر insert-only بلا update/delete.
- **استئناف العامل**: `startNightAuditScheduler` يستطلع كل `NIGHT_AUDIT_POLL_MS`، يطالب
  بالتشغيلات المستحقة عبر دالة `night_audit_work_tenants()` (security definer) بعقد
  qlease `NIGHT_AUDIT_LEASE_MS`، وينفذ حتى `FINALIZE`؛ `NIGHT_AUDIT_STEP_DELAY_MS` مهاد محلي
  فقط لتوليد نوافذ القتل (لا إنتاج، والتهيئة ترفض production).
- **إعادة التشغيل بعد الاكتمال**: تشغيل مكتمل `SUCCEEDED` يعيد نتيجته المخزنة مع
  `replayed=true` بلا قيد ثانٍ ولا فتح يوم جديد.
- **الواجهة الخلفية للعامل**: `StartNightAudit` (202، قائمة بانتظار العامل)،
  `GetNightAuditOverview`، `ListNightAuditRuns`، `RetryNightAudit` (يعيد الإدراج ثم يستأنف)،
  `ResolveNightAuditException`. `RunNightAudit` التزامني من P08 تطوّر ليشغّل السلسلة الكاملة
  مع بقاء شكل الاستجابة متوافقاً (`closed/opened/business_day/replayed`).
- **حدود**: لا مال جديد خارج رسوم الليالي؛ لا reopen (D-13)؛ لا قنوات ولا مزود.

## الأمان

- العامل: `update` على `property` (قفل الصف فقط) و`insert` على `business_day/journal/
  journal_line/folio_charge/audit_event`، وبلا `update/delete` على أي جدول مالي منشور
  (مثبت في `finance-core` بفحص `has_table_privilege`).
