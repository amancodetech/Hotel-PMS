# استقبال Webhook في تجربة Channex

12 أكتوبر 2026 — تأكد وجود `cloudflared` محلياً، لكن **لا نفق مشغّل أو Callback عام منشأ**. طلب المستخدم الأخير يركز على إثبات الإغلاق والفتح التلقائيين؛ الأولوية في [NP-channex-auto-sync](NP-channex-auto-sync.md). Webhook يسرع اكتشاف الأحداث، ولا يثبت تحديث توفر Channex من الحجز. لم يُنفذ مستقبل API؛ التعديلات الجزئية أزالها المنفذ وعاد المصدر الذي اجتاز check-final-4.

إذا احتجنا الرابط التجريبي لاحقاً، يصف [دليل Cloudflare الرسمي](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) نفقاً مؤقتاً بلا نطاق أو حساب. نجهز أولاً مستقبلاً وموجهاً محلياً على `127.0.0.1:4200` يسمحان بمسار Webhook وحده، ثم نشغّل `cloudflared tunnel --url http://127.0.0.1:4200`. يُستخدم الرابط الناتج فعلياً في Callback؛ لا تعرّض API4100 أو Web3000 مباشرة. المنفذ4200 غير مجهز الآن، والرابط يتغير عند تشغيل نفق جديد ويتوقف عند إيقاف عمليته.

يمكن تنفيذ المصادقة المحلية الموثقة بترويسة سرية مستقلة `X-Channex-Webhook-Secret` وفق [وثيقة Channex](https://docs.channex.io/api-v.1-documentation/webhook-collection)، مع بقاء HMAC UNVERIFIED. لا يُطبع السر أو يوضع في الوثائق، ولا تسمى المصادقة بالترويسة توقيعاً. `Send Data=false` يعطي event/property_id/user_id/timestamp دون payload؛ ينبغي ألا يشترط المستقبل booking_id/revision_id في هذه الحالة، ويجلب feed الرسمي ضمن النطاق بدلاً من اعتبار الإشعار حجزاً مؤكداً. خطة تنفيذ المستقبل لم تُنفذ؛ الخطوات التاريخية أدناه لا تعني اكتمالها.

11 أكتوبر2026 — **PLAN_PREPARED / RECEIVER_NOT_IMPLEMENTED / PUBLIC_CALLBACK_NOT_AVAILABLE**. طلب المستخدم توضيح التفعيل، وأكد عدم وجود رابط HTTPS. لم يُنشأ Webhook، ولم يُفتح نفق أو رابط عام. تشغيل السحب الحالي مستقل عن هذه الخطوة.

## النتيجة المطلوبة للمستخدم

وصول إشعار الحجز أو تعديله أو إلغائه إلى نسخة الاختبار تلقائياً، ثم جلب المراجعة الرسمية وحفظها مرة واحدة في المنشأة الصحيحة. إشعار Webhook وحده ليس حجزاً مؤكداً ولا دليلاً على المخزون؛ لا تحرير للحصة عند UNKNOWN أو غياب دليل السحب.

## التنفيذ المتتابع

1. توثيق عقد التوقيع الحالي قبل كتابة معالج يقبل الرسائل. واجهة staging الحالية تعرض HMAC-SHA256 وحقلي `is_signed` و`signing_key_id`، بينما وثيقة Webhook الرسمية التي قُرئت تقول إنه لا يوجد HMAC مدمج. هذا تعارض موثق؛ أسماء الترويسات وصيغة الرسالة الموقعة ونافذة إعادة التشغيل **UNVERIFIED**. لا اختراع توقيع أو الاكتفاء بوجود خيار الواجهة كاختبار تحقق.
2. إضافة استقبال محلي داخل API القائم، مع حد لحجم الجسم ومهلة ومعدل، وسياق ربط خادمي بين المعرف الخارجي والشركة والمنشأة؛ رفض المنشآت غير المصرح بها. التحقق من التوقيع يتم قبل تحليل الحدث، والأسرار من الإعداد الخاص فقط. إشعار الحجز يشغّل جلب feed الرسمي المحصور؛ الحفظ وإزالة التكرار يسبقان ACK. لا نجاح شكلي أو اعتماد توقيت وصول Webhook لترتيب الحجوزات.
3. اختبار محلي مستقل: توقيع صحيح وخاطئ وجسم معدل ورسالة متكررة وقديمة، نطاق خاطئ وفقد الرد وإعادة المحاولة، وعدم ACK بعد فشل الحفظ. مراجعة Astra وإصلاح الموانع قبل إتاحة الرابط.
4. إتاحة HTTPS تجريبي مؤقت لمسار الاستقبال وحده مع نسخة الاختبار؛ واجهة الإدارة وhotel الأصلي لا يُتاحان عبره. اختيار وسيلة الوصول وتفويضها يسبقان تشغيلها. لم يُحجز نطاق أو تُشتر استضافة أو يُنشأ نفق حالياً.
5. إنشاء Webhook **للمنشأة التجريبية Villa4 فقط** أولاً، لا Global لجميع المنشآت. Trigger=`booking`، Is Active=false عند الإنشاء، Sign deliveries بعد إثبات العقد، Send Data=false كبداية لإشعار يشغّل الجلب الرسمي، Headers/Request Params فارغة ما لم يتطلب العقد وسيلة مصادقة مستقلة. Callback URL هو الرابط الفعلي المختبر؛ لا قيمة افتراضية مخترعة.
6. اختبار زر Test والتسليم الفعلي وإعادة المحاولة والحفظ مرة واحدة، ثم تفعيل النطاق التجريبي المحدد بعد المراجعة. الإيقاف يعطل Webhook ويغلق الوصول العام ويحفظ الأدلة؛ لا يمحو حجوزات أو تاريخاً. التوسع إلى Global يتطلب ربطاً صحيحاً لجميع المنشآت واختبارات العزل، وليس تغيير خانة واحداً.

[الوثيقة الرسمية](https://docs.channex.io/api-v.1-documentation/webhook-collection) تسمح بترويسات مصادقة مخصصة؛ اختيار بديل بسر مستقل له عقد واختبارات خاصة، ولا يسمى تحقق HMAC.
- [عقد Webhook الرسمي](https://docs.channex.io/api-v.1-documentation/webhook-collection) يصف Global كأحداث جميع منشآت الحساب، و`booking` كتحديثات الحجز الجديدة والمعدلة والملغاة، ويؤكد احتمال وصول الأحداث بترتيب مختلف ويوصي بالجلب الرسمي.
- النسخة المقروءة محفوظة في `.local/verification/NP-channex-pms-20261011/webhook-official.md`؛ أمر `webhook-official-docs-1` exit0 يثبت التنزيل، لا اكتمال العقد أو تنفيذ الاستقبال.
