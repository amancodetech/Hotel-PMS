# مسودة دليل تشغيل new pratama

الحالة: DRAFT / غير مسلمة كإثبات إدخال. يعتمد المنسق النسخة النهائية بعد إيصال الجرد والواجهة. لا يعني وجود هذا الدليل أن المنشأة أو الغرف أنشئت فيhotel الفعلي.

1. ادخل إلى الشركة الجديدة والمنشأة **new pratama** من الواجهة الحالية. تحقق من اسم الشركة واسم المنشأة قبل أي إجراء. الموقع Cisarua، West Java، Indonesia؛ التوقيتAsia/Jakarta، والعملةIDR.
2. بعد اكتمال الإدخال المتوقع تظهر24 فيلا و6 غرف مستقلة. الغرف الذرية72؛96 مورد النظام تشمل24 حاوية فيلا إضافية غير قابلة للبيع كذرات مستقلة. لا تعتبر96 عدد الغرف.
3. كل غرفة تقبل للمبيت بالغين وطفلاً واحداً. كامل الفيلا يأخذ2n بالغين وn أطفال عندn غرف. حد20 زائراً نهارياً سياسة منفصلة موثقة فقط؛ التطبيق الحالي لا يفرضها آلياً، فلا تدخلها في سعة المبيت.
4. كل فيلا لها بيع الكل وبيع الغرف. Villa23/24 لهما أيضاً منتجا الكل والغرفة، مع استهلاك الغرفة نفسها؛ وجود منتجين لا يضاعف المخزون. لا تعدل التركيبة لتفصل ذرة جديدة للكل.
5. الإعداد الأولي14:00 للدخول و12:00 للخروج. نافذة التركيبات2026-10-08 إلى2031-10-08؛ التجديد يحتاج مراجعة وتغييراً معتمداً قبل انتهائها، وليس تمديداً تلقائياً من هذا الدليل.
6. الأسعار مؤجلة والبيع مغلق. المنتجات والتركيبات قد تعرضACTIVE لأنSET يفعّل الهيكل؛ هذا لا يعني فتح بيع المنشأة. شرط التسليم property=SETUP، بلا خطط أسعار أو اتصالات قنوات أو معاملات بيع جديدة. لا تختبر ذلك بحجز فعلي أوفتح قناة.
7. عند خطأ في اسم أو سعة أو علاقة غرفة، سجل اسم الوحدة ورمزها وصف المشكلة ووقت UTC؛ لا تعيد استيراد Excel أو تحذف الفيلا لإصلاح العرض. الرموز مشتقة للنظام والأسماء الأصلية محفوظة.
8. إذا انقطع إدخال جزئي، المنسق يستأنف checkpoint المرحلةA/B/C نفسها بعد قراءة حالة الخادم. لا يكرر المستخدم إنشاء المنشأة أو جميع الوحدات. رفض413 القديم لا يبرر رفعlimit16KB.

قائمة التسليم المستقبلية: إيصال96 مورداً و96 منتجاً و24 تركيبة و66 ورقة، تحقق سعات72 غرفة و24 كامل فيلا، parent links الفعلية، قراءةpropertySETUP وغياب الأسعار والقنوات والمعاملات، ثم صور الواجهة بثلاث لغات وعرض390/1440. حتى وصول هذه الأدلة تبقى المسودة غير معتمدة كدليل اكتمال.
