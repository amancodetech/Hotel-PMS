### العقود الفعلية

كل المسارات التالية تتبع الجذر `/api/v1/tenants/{tenant_id}/properties/{property_id}`. لا ترسل tenant_id أو actor من body كبديل للسياق الموثوق. الجلسة و CSRF يطبقان بنمط التطبيق الحالي؛ لا تسجل tokens أو cookies أو .env.

| المسار | الطريقة والمدخلات | النسخة والتكرار |
| --- | --- | --- |
| `/setup-draft` | GET للقراءة؛ PUT بجسم SetupDraftInputV2 المعتمد | عند PUT: idempotency-key ؛ إذا كانت المسودة موجودة فإن if-match هو `"{draft_id}:{revision}"` من الخادم، لا رقم مخترع. |
| `/setup-draft/preview` | POST بعد حفظ المسودة، بلا مدخل جديد؛ قراءة المخطط فقط | احتفظ بـ preview_version ولا تستعمل نسخة قديمة بعد تغيّر الحالة. |
| `/setup-batches` | POST للبدء: mode=DRAFT و preview_version ، دون نسخ input للمسودة؛ mode=ADDITION يضيف input بصيغة الإضافة | idempotency-key و if-match ؛ نسخة DRAFT من draft ، ونسخة ADDITION من property_etag الفعلي. |
| `/setup-batches?id={batch_id}` | GET لقراءة الحالة والاستئناف | batch_id مثبت في checkpoint ؛ لا تبدأ عملية جديدة قبل معرفة القديمة. |
| `/setup-batches/{batch_id}/advance` | POST: index=completed_batches الحالي، preview_version الحالي للـ chunk | key الحالي في client: `batch-{batch.id}-{completed_batches}-{preview_version.slice(0,24)}`. لا تستعمل نسخة المعاينة الأولى لكل chunks. |
| `/setup-unit-additions/preview` | POST: schema_version/locations/unit_groups فقط | الرد يضم property_etag و preview_version ؛ لا property/pricing/operations في body. |
| `/setup-unit-additions` | POST: input بصيغة الإضافة و preview_version ؛ يستخدم فقط إذا كان preview ضمن inline وبلا blockers | idempotency-key و if-match=property_etag الحالي. في الخطة الكبيرة يستعمل ADDITION batch بدلاً من apply المباشر. |

الفعل POST لإنشاء المنشأة يتبع `/api/v1/tenants/{tenant_id}/properties` بعقد createProperty الحالي. لا تفترض أنه يملك نفس حماية التكرار الخاصة بـ SET. إذا فقد رد الإنشاء، ابحث عن رمز المنشأة داخل الشركة وأثبت معرفها قبل أي إعادة؛ لا تكرر POST عمياناً.

في المعالج، القيم الأولية 14:00 و 12:00 و inspection_required=false و postponed=true إعدادات واجهة، وليست موافقة المستخدم. لا تضغط حفظ/تنفيذ قبل استبدالها بالقيم المعتمدة. المسودة الناقصة قد تحفظ `null` في الحقول التي يدعمها schema ، لكنها ليست مدخلاً قابلاً للتنفيذ. `privacy_ack:null` و`postponed:null` ليسا boolean صالحاً في body ؛ ملف missing-inputs سجل تخطيط، لا payload. قبل حفظ مسودة ناقصة احذف الحقول Boolean غير المحسومة أو اترك pricing=null بحسب schema ؛ apply يبقى محجوباً حتى القرارات اللازمة.

## 7. الرفض وفقد الاستجابة والاستئناف

| الحدث | الإجراء الإلزامي |
| --- | --- |
| فقد رد حفظ أو apply يحتمل أنه التزم | سجل UNCERTAIN مع الطلب/key/etag/hash بلا أسرار. لا تغير المدخل أوالمفتاح؛ استعمل Retry الحقيقي واقرأ الحالة من الخادم. تحقق من IDs والعد قبل ادعاء النجاح. |
| reload أو تغيّر جلسة أثناء batch | اقرأ progress وثبّت tenant/property/batch IDs ، ثم GET لحالة batch المحددة. إذا completed لا advance ولا إنشاء جديد؛ وإلا استعمل المؤشر والنسخة الحالية بعد فحص blockers. |
| 409 أو index قديم أو نفس key مع body مختلف | احفظ الرفض وصالح حالة الخادم. لا تبدل المفتاح لإجبار الكتابة. |
| draft stale أو preview stale أو 412 | اقرأ النسخ الحديثة والمخزون واشرح الفرق، ثم معاينة جديدة بعد حسم أي UNCERTAIN. لا تتجاوز if-match. |
| LIMIT_EXCEEDED أو batch_plan=null | PAUSE ؛ راجع profile/cost والمجموعات المركبة والمواقع. لا رفع حدود ولا SQL fallback. |
| 403/404 أو cross scope | PAUSE ؛ تحقق من الجلسة والمعرفات والصلاحيات المفوضة. لا RLS bypass ولا حساب بديل غير مفوض. |
| فشل chunk | لا تدّع rollback للعملية كلها؛ الخادم يحفظ chunks السابقة. سجل created/total/index والرفض ولا تحذف المكتمل. |
| نقص أو تكرار أو ذرة جديدة للكل أو سعة مفترضة | PAUSE_QUALITY ؛ احفظ الأدلة ولا تكمل بإخفاء الفرق أو إعادة import. |
| حذف أو إغلاق G-13 أو تجربة خارجية | مسار منفصل بحدود تفويضه، لا ينفذ من خطة إدخال الهيكل. |

مفتاح التكرار يثبت **الطلب ذاته**. إذا تحرك الخادم بعد رد مفقود، قد تبين قراءة التقدم أن chunk نجح وتستأنف التالي؛ لا تعتبر ذلك فشل replay. احفظ جميع النتائج السابقة والفاشلة دون استبدالها. لا تتوقع UUID ثابتاً قبل الرد، ولا تعيد استخدام IDs من منتجع آخر. قاعدة checkpoint: قبل الكتابة احفظنية الطلب و key/hash ؛ بعد الرد أو القراءة احفظ نتيجته ومعرفاته والعدادات ووقت Evidence.

الحفظ المالي والحجوزات القائمة مستقلان عن التأسيس التشغيلي. لا تمس أي journal منشور، ولا تولد opening balance أو cash أو receipt من Excel. رؤوس Panduan التاريخية تختلف عن TEMPLATE الفعلي؛ المقبوض الفارغ الذي تحوله صيغة Excel لسعر الليلة **ليس دفعاً مثبتاً**. عمولات 15–18% أمثلة لا أسعار معتمدة. تكرار sheets اليومية لا يثبت سلسلة حجوزات أو تواريخها. الاستيراد المالي أوفتح أرصدة يحتاج خطة ومعطيات وتفويضاً مستقلاً، مع حفظ الدفتر والتاريخ كما هما.

طلب المستخدم الأحدث عن حساب Channex Developer الفارغ وتجربة رسمية ببيانات اصطناعية يخص مساراً منفصلاً يتحقق منه المنسق بمصادر Channex الرسمية. لا تدخل بيانات المنتجع إليه من هذه الخطة، ولا تعتبر تجربة Developer/Sandbox إثبات ربط حي بالقنوات الخمس أو قبولاً لإغلاق G-13. تعليمات المستخدم الحالية حسمت أن جميع البيانات السابقة تجارب قابلة للتنظيف؛ يتولى المنسق تحديث [cleanup-plan.md](cleanup-plan.md) وإيصال التنفيذ الخاص. لا يعتمد إدخال new pratama على اكتمال تجربة Channex.

## 8. سجل التنفيذ ومعايير الإغلاق

ملف [progress.md](progress.md) هو نقطة الاستئناف؛ تظل جميع مهام التطبيق NOT_STARTED الآن. سجّل لكل كتابة مقبلة: المهمة والمرحلة، وقت UTC، tenant_id و property_id من الخادم، active property في الواجهة، commit/version، بصمة المصدر والمدخل، draft_id/revision أو property_etag، batch_id الخاص بالمرحلة، index الحالي، preview_version، المفتاح، نية الطلب، ثم نتيجة الرد والعدادات والمعرفات. احتفظ بالطلب المنقح والأدلة الخاصة تحت مجلد محلي مخصص عند التنفيذ؛ لا تلصق أسرار الجلسة أو محتوى Excel اليومي. لا يحتاج الإغلاق إلى نشر IDs الحساسة في وثيقة عامة.

قبل كل عملية افحص تطابق active property مع checkpoint والطلب؛ تغيير المنشأة في المتصفح لا يغيّر property_id المسجل. إن انقطع السياق، اقرأ سجل التقدم ثم حالة الخادم المحددة، ولا تبدأ من NP-03 مجدداً. محاولات UNCERTAIN تبقى ظاهرة إلى أن تصالحها قراءة الخادم؛ تحديث الوثيقة وحده لا يحسمها.
