## التنفيذ المحدود

السكربت الخاص هو `.local/verification/new-pratama/apply-locations.mjs`. يستخدم عقود API الموجودة: GET لقراءة النطاق والجرد، POST للمواقع مع مفتاح idempotency ثابت لكل نية، وPATCH للمورد بجسم يحتوي `version` و`location_id` فقط. لا يوجد GET منفرد للمورد؛ إعادة القراءة تمر بالقائمة كاملة مع pagination. لا يستخدم SQL أو حذفاً أو إنشاء موارد أو تعديل المنتجات والتركيبات.

قبل أي كتابة يتحقق من الشركة والمنشأة الفعليتين، ومن بقاء المنشأة SETUP دون أسعار أو connections، والجرد الدقيق 96 مورداً، 96 منتجاً، 24 تركيباً و66 ورقة. البداية تتطلب شجرة فارغة و96 موقع مورد NULL. أي موقع سابق غير مملوك لسجل التنفيذ أو تغيير غير متوقع في الجرد يوقف التنفيذ. تحفظ القراءة الأولية IDs وجميع حقول الموارد التي يعرضها API؛ يعاد التحقق من ثباتها، باستثناء location_id وزيادة version مرة واحدة لكل ربط.

`parent_resource_id` لا يظهر في DTO الحالي؛ السكربت لا يزعم إثباته بواسطة API. لا يرسله في أي PATCH؛ يتحقق المنسق منه ومن حدود الحجوزات والتعرضات والقيود المالية باستقلالية من النسخة الاحتياطية وقراءة DB دون كتابة أعمال.

## متغيرات المنسق

- `NP_TARGET_DB`: حصراً `hotel_np_loc_oct8_backup` أو `hotel`.
- `IDENTITY_TEST_DB` و`NP_API_DB_CONFIRMED`: نفس قاعدة الهدف، بعد تأكيد خدمة API الفعلية.
- `NP_APPLY_LOCATIONS=CONFIRMED_43_NODES_78_ASSIGNMENTS`.
- `NP_PROPERTY_RECEIPT`: إيصال المنشأة الفعلية؛ الافتراضي `property-hotel.json` داخل مجلد الأدلة الخاص. النسخة المستنسخة تحافظ على نفس IDs.
- `NP_LOCATION_BACKUP_RECEIPT`: مسار إيصال backup/clone الذي راجعه المنسق داخل مجلد الأدلة الخاص.
- `NP_LOCATION_BACKUP_SHA256`: SHA256 الملف نفسه، مثبت بواسطة المنسق بعد إثبات صلاحية الاستعادة؛ مطابقة hash وحدها ليست إثبات استعادة.
- `NP_LOCATION_STATE`: سجل مستقل لكل هدف؛ الافتراضي `locations-${NP_TARGET_DB}-state.json` داخل مجلد الأدلة الخاص.

الأمر التالي توثيق تاريخي لإجراء نفذه المنسق؛ لا يُعاد تشغيله لمجرد الاستئناف. عند إعداد الخطة، كان المنسق يشغل `node --env-file=.env .local/verification/new-pratama/apply-locations.mjs` مع هذه المتغيرات. لا يشغل السكربت خدمات تلقائياً ولا يحوّل الهدف أو ينشئ fixtures.

## التوقف والاستئناف

يحفظ السجل الطلب والمسار والجسم والمفتاح قبل الاتصال، ثم حالة HTTP وجسم الرد أو خطأ الاتصال، ثم القراءة المستقلة. لا يحفظ أسرار المصادقة. عند الإخفاق يتوقف ولا يكمل العمليات التالية. يحتفظ المنسق بالسجل نفسه والنسخة الاحتياطية نفسها وبنفس hash للخطة؛ لا يمسح السجل ولا يستبدل المفتاح.

قبل استعادة النية المعلقة، يفحص السكربت بقية الموارد والمواقع والمنتجات والتركيبات. POST غير المؤكد يعاد بنفس المفتاح والجسم؛ لا تعتمد هوية موقع متشابه الاسم دون إعادة الطلب الموثقة. PATCH غير المؤكد يعاد قراءته أولاً: إن تحقق الربط وزادت version مرة واحدة يسجل النجاح؛ إن بقي NULL وبنفس النسخة يعيد PATCH الأصلي؛ أي قيمة أو نسخة أخرى توقف التنفيذ. HTTP 4xx محفوظ ويحتاج مراجعة السبب قبل إعادة التشغيل؛ لا يتحول تلقائياً إلى طلب جديد.

اكتمال السجل `VERIFIED` يعني اجتياز قراءة API: 43 عقدة، 78 ربطاً، 18 NULL، وثبات الجرد المحمي وبقاء SETUP والأسعار والاتصالات فارغة. لا يعني فحص المتصفح أو DB أو صلاحية التشغيل النهائي؛ هذه نتائج منفصلة يوثقها المنسق بعد التنفيذ.
