## PSR-01.1 — تثبيت قاموس الشاشة وأسئلة الأنماط دون مصطلحات تقنية

- الحالة: VERIFIED_LOCAL. تسبقها المهمة السابقة داخل البطاقة إن وجدت.
- نقاط القراءة/التعديل المرشحة: docs/99 §15 وapps/web/src/property/. تحقق من المستهلكين؛ لا تعدل الملفات لمجرد ورود اسمها.
- النتيجة المطلوبة: النص يفرق فئة/تركيبة وغرف نوم/وحدات؛ النطاق المؤجل لا يبدو متاحاً.
- التحقق المطلوب: PSR-E01/E02 تصميم. حالات الاختبارات وتوقعاتها في docs/101.
- الدليل الفعلي: اختبارات React 4/4، المتصفح 12/12، check 114/114؛ مسارات الأدلة وقيودها في سجل الدفعة أدناه.

## PSR-01.2 — نموذج أربع خطوات على بيانات اصطناعية موسوم بأنه نموذج

- الحالة: VERIFIED_LOCAL (نموذج فقط). تسبقها المهمة السابقة داخل البطاقة إن وجدت.
- نقاط القراءة/التعديل المرشحة: المكونات القائمة في apps/web/src/property/ وpackages/ui/. تحقق من المستهلكين؛ لا تعدل الملفات لمجرد ورود اسمها.
- النتيجة المطلوبة: الفندق والفيلا والمنتجع المختلط والهاتف والخطأ قابلون للمراجعة؛ لا نجاح API وهمي.
- التحقق المطلوب: PSR-E01/E02/E03/E06. حالات الاختبارات وتوقعاتها في docs/101.
- الدليل الفعلي: اختبارات React 4/4، المتصفح 12/12، check 114/114؛ مسارات الأدلة وقيودها في سجل الدفعة أدناه.

## شروط تسليم البطاقة

1. كل مهمة لها دليل، وخريطة أثر docs/95 §5 مكتملة بـDONE أوN/A مبرر.
2. لا تعديل D/حدود العزل/المحاسبة أو الهجرات المطبقة، ولا تنفيذ امتداد مؤجل.
3. فشل تابع لمهمة سابقة يمنع إغلاق هذه البطاقة؛ لا mock لإخفاء API ناقص.
4. اختبارات التطبيق ليست مطلوبة لوثائق فقط؛ العقود والكود يحتاجان الفحوص الملائمة ثم check لإغلاق الكود.
5. الحالة النهائية لا تتجاوز الأدلة؛ ACCEPTED_LOCAL قرار المستخدم وفق سير العمل.
