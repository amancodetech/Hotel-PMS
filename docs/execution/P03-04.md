# P03-04: محرك الصلاحيات والتدقيق

الحالة: IMPLEMENTED / VERIFIED محلياً. القبول النهائي ينتظر مراجعة G-03 المستقلة.

## محرك السياسة

`evaluatePolicy` في `packages/backend/src/modules/identity/application/policy-service.ts` يأخذ القرار من PostgreSQL لكل طلب:

1. العضوية: غيابها أو عدم نشاطها يرفض.
2. الصلاحيات الفعلية من `role_grant × role_permission` مع `revoked_at/expires_at` ونطاق TENANT/PROPERTIES.
3. المنع (DENY) يسبق المنح؛ المنح بنطاق PROPERTIES لا يطبق على عملية بلا property ref.
4. MFA: كل صلاحية حساسة (`tenant.manage`, `membership.manage`, `membership.revoke`, `role.manage`, `role.grant`, `approval.approve`) تتطلب إشارة `amr` حقيقية من Keycloak.
5. الاعتماد: `role.grant` بنطاق TENANT أو بأثر DENY يتطلب `x-approval-id` مع تطابق action وrequest_hash وversion/currency/amount، ومنع اعتماد الذات، وإعادة التحقق من صلاحيات المعتمدين عند التنفيذ.

## الربط بالنقل (apps/api/src/identity/guards.ts)

- SessionGuard: تحميل الجلسة من cookie وإرفاق actor؛ الرفض الافتراضي عند غياب الجلسة.
- CsrfGuard: `x-csrf-token` + Origin لكل POST/PATCH/DELETE غير العام، ورفض عند الغياب برسالة ثابتة.
- PolicyGuard: يقرأ `@RequirePermission`، يطابق `tenantId` في المسار مع `active_tenant_id` في الجلسة، ثم ينفذ `evaluatePolicy` داخل معاملة سياق. أي اختلاف = TENANT_CONTEXT_MISMATCH.
- استخدام `x-property-ref` يمرر لنطاق PROPERTIES في خدمات القراءة.

## التدقيق

- كتابة `audit_event` داخل نفس معاملة العمل: actor/action/resource/outcome/before_after منقّاة، reason إلزامي للعمليات الإدارية الحساسة (suspend/revoke)، correlation id.
- تنقية مركزية (`safeAuditFields`) تزيل المفاتيح الحساسة وتقص القيم الطويلة. `audit_event` للإضافة فقط (لا UPDATE/DELETE لدور API).

## الاختبارات

## القيود

- صلاحيات support المؤقتة المنصوص عليها في docs/32 تنفذ عبر grant مؤقت (`expires_at`) + تدقيق؛ لا bypass عام. اختبار SEC-006 الكامل مؤجل إلى P12-03.
- اعتماد عمليات مالية/مخزون فعلية يبقى لمراحلها؛ P03 يثبت العقد بسيناريوهات role.grant.
