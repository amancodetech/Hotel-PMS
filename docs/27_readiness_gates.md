## Runbook بدء منشأة

1. تأكيد المسؤول والنطاق والتفويض والتوقيت والعملة وملف الضرائب؛ تسجيل جرد الموارد والتركيبات والحصص المستقبلية.
2. تجميد تغييرات التهيئة أثناء cutover وإغلاق البيع الخارجي المقرر نقله مع دليل تحقق؛ إبقاء writer واحد مسؤولاً دون تنافس النظام القديم والجديد.
3. استيراد الحجوزات المستقبلية وBlocks وأرصدة البداية من مصادر المنشأة والقنوات؛ مطابقة IDs والفترات والمبالغ والعملات لا مجرد عد السجلات.
4. استكمال revisions خلال نافذة النقل حتى cutoff موثق؛ فحص D-20 وMapping والقيود. إذا لم تثبت سلامة القطع يبقى البيع مغلقاً وتستكمل المراجعة.
5. نشر snapshot مشتقة بالحصة المقررة، ثم إثبات القبول والتحقق لكل قناة، وفتح محدود مراقب. لا فتح كامل لأن health endpoint أخضر.
6. مقارنة حجز جديد وتعديله وإلغائه وفق برنامج اختبار المزود المصرح؛ توثيق النتيجة والمسؤول، دون إنشاء حجوزات ضيوف وهمية في الإنتاج خارج الاتفاق.

## Runbook تعطل واستعادة

عند lag أو ACK مجهول: منع زيادات التوفر المتأثرة، حفظ OUTBOX، تقليل النشر إن أمكن، إشعار المسؤول. إن كان المزود غير متاح لا ندعي نجاح Stop Sell؛ يتابع مسؤول المنشأة الإغلاق في القنوات الأصلية ويسجل الدليل. الحجوزات الواردة تستمر في الحفظ والاستثناءات.

عند استعادة DB: ابدأ بوضع RECOVERY، أوقف الإرسال الذي يفتح المخزون، استرجع revisions منذ ما قبل نقطة النسخة الاحتياطية، وطابق payment references وExposure/cutoffs وOutbox. فقد cursor لا يعني إعادة إنشاء جميع الحجوزات؛ مفاتيح المصدر محفوظة. لا يتحول Outbox قديم إلى writer أحدث بمجرد إعادة التشغيل.

rollback التطبيق فقط عند توافق البيانات. لا down migration يمحو حجوزات أو Journal. العودة إلى مزود سابق تتطلب سحباً ومطابقة وربطاً موثقاً، وليست تغيير connection_id. سحب صلاحية Tenant لا يترك اتصالات نشطة تبيع دون استقبال؛ suspend خطة منظّمة مع إيقاف البيع ومتابعة الالتزامات.

## مرحلة 1 المحددة

فحص حزمة 0.6 بتاريخ 12 سبتمبر 2026: قراءة JSON، فحص 43 operationId فريداً و47 تعريف schema و246 مرجعاً داخلياً، معاملات المسار ووسم الصلاحيات وCSRF، مطابقة كتالوج العمليات، UTF-8 وروابط الملفات. لم يظهر خطأ بهذه الفحوص البنيوية المخصصة. لم يشغل validator OpenAPI خارجي أو اختبارات تطبيق؛ لا يثبت ذلك صحة الأعمال أو توافق مزود، وتضاف مراجعة معيارية للعقد في CI عند التنفيذ.

عند تفويض البرمجة: معالجة Git الحالي دون استبدال دليل قائم، إنشاء المسارات داخل نفس المجلد، تثبيت Node LTS والمكتبات المتوافقة، Docker محلي للخدمات، إدارة إعدادات بلا أسرار، CI/build/typecheck، health/readiness، correlation IDs وواجهات العقود. اختبار G-01 يثبت بناء وتشغيل خدمات الأساس فقط؛ لا يعلن AT-T01 أو RLS أو منع حجز مزدوج قبل تنفيذها بالمراحل التابعة.
