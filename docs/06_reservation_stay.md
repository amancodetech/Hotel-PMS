# مواصفة الحجز والإقامة

حالة: مواصفة قبل البرمجة؛ سياسات V1 والدفع والمغادرة معتمدة في docs/23_v1_decisions.md. تعديل وإلغاء حجز OTA لا يعني القدرة على تغييره خارجياً؛ راجع docs/26_api_permissions_events.md.

## النموذج والحالات

Reservation تجميع تعاقدي داخل Property؛ Item إقامة فرعية لها استقلال التواريخ والحالة والنزلاء. حالة الإجمالي تجمع حالات البنود: مؤكد جزئياً/قيد التشغيل جزئياً/منتهٍ عند اللزوم، ولا يكتب موظف Checked-Out للإجمالي مع بقاء بند In-House.

Inquiry لا يستهلك. Tentative قد يكون عرضاً غير مضمون أو Hold مضمون؛ يظهر الفرق. Confirmed يملك التزاماً صالحاً ونسخة سعر وسياسة. Check-In حدث، وIn-House حالة؛ Checked-In في الواجهات تسمية لنجاح الحدث وليست حالة طويلة مكررة. Pre-Arrival مرحلة زمنية/مهام وليست بالضرورة حالة مستقلة. Completed يتطلب إغلاق البنود التشغيلية ومعالجة المال حسب السياسة، لا مجرد مغادرة.

Waitlist طلب بلا ضمان؛ لا يستهلك. Cancelled وNo-Show مساران للبند قبل بدء الإقامة؛ لا يحول النزيل المقيم إلى No-Show. الخروج المبكر إتمام إقامة فعلية بتقصير مستقبلها وليس إلغاء تاريخها.

## انتقالات البنود

| من → إلى | الشروط | الآثار والفشل |
|---|---|---|
| Inquiry→Tentative | طلب مفهوم وسعر مبدئي | Hold اختياري واضح المهلة |
| Tentative→Confirmed | تحقق مخزون وضمان تعاقدي وصلاحية | نسخة سعر وسياسة والتزام واحد؛ الفشل يحفظ الحالة |
| Confirmed→In-House | هوية لازمة وسياسة ضمان وتخصيص جاهز وتاريخ صالح | إشغال فعلي وأثر تدقيقي؛ التكرار يعيد نتيجة الأصل |
| Confirmed→Cancelled | سياسة إلغاء وصلاحية | تحرير المستقبل ورسوم/استرداد بطلب مستقل |
| Confirmed→No-Show | تجاوز cutoff المعتمد بلا دخول | قرار موثق وRelease وفق السياسة ورسوم مستقلة |
| In-House→In-House | نقل/تمديد/تغيير متفق | إقفال قطاع وإنشاء قطاع جديد دون محو |
| In-House→Checked-Out | تحقق البنود والاستخدام والأرصدة | تسجيل مغادرة وتنظيف؛ الاستحقاق المالي يعالج صراحة |
| Checked-Out→Completed | لا عمليات أو التزامات مالية غير معالجة وفق السياسة | إتمام؛ تصحيحات لاحقة بأحداث لا إعادة كتابة |

لا إعادة Cancelled إلى Confirmed مباشرة؛ طلب إعادة تفعيل موثق يتحقق من المخزون والسعر والشروط مجدداً. تصحيح دخول خاطئ إجراء عكسي مصرح يراجع مفاتيح الدخول والرسوم والإشغال؛ لا زر يمحو الحدث.

## حالات الاستخدام

| ID | الحالة | قواعد الأعمال والقبول |
|---|---|---|
| RS-01 | Walk-In | يمر بتحقق المخزون والسعر والهوية والتخصيص كأي حجز؛ لا اختصار أمني |
| RS-02 | عدة غرف | إنشاء Items واضحة؛ خيار نجاح جميع البنود أو موافقة صريحة على جزئي قبل العقد |
| RS-03 | Group | Allotment مضمون يستهلك؛ Pick-up نقل التزام؛ Cutoff يحرر غير المستخدم فقط |
| RS-04 | تمديد | تحقق كامل للفترة الجديدة؛ لا تمديد للسعر السابق دون سياسة |
| RS-05 | نقل | تأمين البديل ثم تحويل الإشغال؛ المورد القديم يصبح بحاجة لتجهيز |
| RS-06 | Split Stay | موافقة وقطاعات مؤمنة معاً؛ لا فرض نقل لاحق صامت |
| RS-07 | تغيير النزلاء | تحقق السعة والتوافق والرسوم والوثائق المطلوبة دون إعادة ضبط التاريخ |
| RS-08 | خروج مبكر | حفظ ليالي الاستخدام؛ إعادة حساب المستقبل وفق نسخة السياسة وإظهار الفروقات |
| RS-09 | مغادرة جزئية | إنهاء Item دون إغلاق بقية المجموعة أو حسابها بالكامل |
| RS-10 | دفع بعد انتهاء Hold | لا حجز تلقائي على مورد محرر؛ مطابقة ثم إعادة حجز إن أمكن أو معالجة التحصيل |
| RS-11 | وصول بعد No-Show | تحقق جديد وإجراء إعادة استقبال موثق؛ لا محو الرسوم دون تصحيح |
| RS-12 | حجز خارجي متعارض | حفظ المرجع والالتزام الخارجي والاستثناء؛ لا اختلاق غرفة |

## ضمان المال والمغادرة

D-13 المعتمد: يُسمح بالمغادرة التشغيلية مع رصيد فقط إذا حُوّل إلى جهة مدينة أو حساب مصرح وخطة تحصيل موثقة؛ وإلا يمنع الإغلاق المالي. لا يجوز حبس حالة الإشغال إلى الأبد لأن فاتورة تحتاج متابعة. المغادرة التشغيلية منفصلة عن التسوية المالية وفق D-13. واجهة المستخدم تميز «غادر» و«تمت تسوية الحساب».

يُحفظ سعر كل ليلة واستحقاق وبالغ/طفل وخصم وضريبة وسياسة إلغاء بمرجع النسخة عند الاتفاق. تعديل عام لخطة سعر لا يعيد تسعير الحجز القديم تلقائياً. فرق السعر قبل/بعد التعديل يظهر للمستخدم وللموافقة اللازمة.
