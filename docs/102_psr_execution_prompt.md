# رسالة تنفيذ PSR للموديل

هذه رسالة جاهزة يرسلها المستخدم عندما يريد بدء التنفيذ. وجودها في المستودع ليس تفويضاً ذاتياً. تعليمات المستخدم الأحدث تتقدم على النص.

```text
نفّذ تحسين إعداد المنشآت PSR محلياً في المستودع الحالي، بالتتابع وفق الدليل والبطاقات. هذا طلب تنفيذ للدفعة الأولى المحددة في docs/100؛ لا يشمل التوسعات المؤجلة أو النشر والشراء والقنوات الحية أو حذف بيانات مستخدمة.

ابدأ بقراءة AGENTS.md وREADME.md ثم docs/01_baseline.md وdocs/17_decisions_readiness.md وdocs/18_cli_handoff.md.
اقرأ docs/99_property_structure_and_setup_redesign_plan.md ثم docs/100_psr_implementation_spec.md ثم docs/101_psr_acceptance_cases.md ثم docs/execution/PSR-progress.md. استخدم docs/95_set_ai_implementation_playbook.md لضوابط الباك إند والاختبارات.

ابدأ بأول مهمة غير مكتملة ذات تبعيات ناجحة؛ نقطة البداية المتوقعة PSR-00.1. تحقق من الملفات والحالة الحالية، فقد تكون جلسة أخرى عدلتها. لا تتراجع عن تعديلات الآخرين، ولا تنشئ مشروعاً أو محرك مخزون موازياً.

التزم بالنطاق المثبت في docs/100. الفئة ليست تركيبة، وغرف النوم الوصفية ليست موارد، والجناح المستقل لا يحتاج تركيباً. لا تفترض أن نوع المنتجع يفرض ربط كل وحداته. لا تدّع دعم السيناريوهات المؤجلة؛ امنع طلبها من API برسالة واضحة.

لكل مهمة افتح docs/execution/PSR-XX.md وسجل:
1. السلوك الحالي ودليل المسار من الواجهة حتى البيانات والمستهلكين.
2. السيناريوهات PSR-S والثوابت PSR-INV واختبارات PSR-T/E/P/UX المتأثرة.
3. خريطة أثر docs/95 §5 مع DONE أو N/A مبرر لكل طبقة.
4. العقد وDTO والقيود والصلاحيات وIdempotency وIf-Match والأحداث والعميل واللغة.
5. الفحص المناسب، أمره وexit code ومسار أدلته والنتيجة الفعلية.

نفذ مهمة صغيرة في كل مرة. لا تغيير enum قائم بمعنى جديد ولا تعديل generated يدوياً. لا تعديل هجرة مطبقة. اختبر الترقية والرجوع أو الرفض الصريح على قاعدة معزولة، واحفظ IDs والحجوزات والحصص والحالات التاريخية. لا تستخدم update جماعياً لإحياء RETIRED ولا تزيل قيداً لتنجح الاختبارات.

مسودات SET المكتملة لا تفتح للتحرير كإنشاء؛ إضافة وحدات لاحقة عملية مستقلة. كل apply يعيد التحقق تحت القفل، ويطابق المعاينة، ويحفظ نتيجته للتكرار. لا نجاح وهمي في الواجهة ولا حساب توفر من cache.

قبل اختبار PostgreSQL اقرأ المشغل، ابنِ dist الحديثة، وتحقق من قاعدة الاختبار والمنافذ. أوقف dev عند التعارض وفق سكربت المشروع وأعده إن كان يعمل قبل الاختبار. لا تستخدم pkill node ولا PID من محادثة سابقة. اتبع صلاحيات البيئة ولا تتجاوز رفضها.

أصلح فشل الكود داخل النطاق وأعد الاختبار المتأثر. إذا احتاج جزء قراراً يغير D أو قدرة مؤجلة، سجل العائق وأكمل المستقل المصرح. لا تطلب إذناً جديداً لتنفيذ إجراء سبق تفويضه.

بعد كل مهمة حدّث البطاقة وPSR-progress بخطوة استئناف دقيقة. لا تنقل أرقام SET القديمة إلى PSR. لا تحول NOT_TESTED إلى PASS بلا دليل. عند نهاية الدفعة قدم الملفات المتغيرة والسلوك والفحوص والقيود والنتائج المفتوحة؛ تبقى REVIEW_PENDING حتى المراجعة المستقلة. جهز حزمة مراجعة منفصلة، ولا تكتب أنك مستقل عن عملك. إذا لم تتوفر أداة/جلسة مراجعة مستقلة، سلّم برومبتها وأدلتها للمستخدم وصرح بالحد.
```

## رسالة المراجعة المستقلة بعد التنفيذ

```text
راجع دفعة PSR المنفذة دون الاعتماد على حكم المنفذ. اقرأ docs/99 و100 و101 وبطاقات PSR وسجلها. قارن النطاق المعلن بالكود والعقود والهجرات، واختبر حالات عدم الربط، الكامل/الأجزاء، الأسرة، العزل، السباق، replay، stale preview، ترقية بيانات قديمة، ورفض التحويل بين مورد واحد وأجزاء.

راجع أن الحجز المحلي لا يتجاوز D-20، وأن الشركة/المنشأة/الموقع محفوظة، وأن الأربع خطوات سهلة ولا تعرض خيارات غير مفروضة. افصل تحقق المتصفح الآلي عن اختبار المستخدمين البشر.

اكتب docs/execution/PSR-independent-review.md: حكم GO/NEEDS_FIXES، findings بمعرف PSR-Rxx وشدة ودليل إعادة إنتاج وملف/سطر وحل مقترح، الفحوص التي نفذتها، ما لم تختبره، وحدود القبول. لا تقبل أو تغير حالة G-13 ولا تدع اختبار قناة حية. لا تصلح التطبيق أثناء كتابة الحكم إلا إذا كلفك المستخدم بذلك، وبيّن حدود استقلال المراجعة إن حدث.
```
