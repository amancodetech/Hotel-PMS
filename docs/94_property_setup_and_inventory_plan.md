# خطة توحيد إعداد المنشآت والوحدات وطرق التأجير

دليل التنفيذ التفصيلي: [قواعد النموذج المنفذ](95_set_ai_implementation_playbook.md)، [رسالة البداية](96_set_ai_start_prompt.md)، [سجل تقدم SET](execution/SET-progress.md). ويضيف [التصميم الموسع لهيكلة العقارات](99_property_structure_and_setup_redesign_plan.md) نموذج الشركة/المنشأة/الموقع/الوحدة/المساحة وطرق البيع والسيناريوهات العالمية. هذه المرفقات تضبط التنفيذ والاستئناف ولا تعني بدءه.

التاريخ: 20 سبتمبر 2026. الحالة: خطة مقترحة بطلب المستخدم، وليست تنفيذاً أو قبولاً إنتاجياً. التفويض الحالي إعداد الخطة وتحسين التصور؛ لا يعد تفويضاً لتغيير قاعدة البيانات أو تشغيل قناة حية.

## 1. النتيجة المطلوبة

يضيف المالك منشأة صغيرة في رحلة قصيرة، ويستطيع تشغيل منتجع مركب من الرحلة نفسها بإظهار الخيارات المطلوبة فقط. يصف المستخدم ما يملكه وما يريد بيعه، ويترجم النظام ذلك إلى المواقع والموارد والمنتجات والتركيبات دون مطالبته بإنشائها يدوياً في تبويبات متفرقة.

المبدأ: **وحدة فعلية واحدة، طرق بيع متعددة، والتزام واحد متسق على مخزونها**. لا نعد كل نوع عقار مدعوماً حتى تنجح دورة إعداد وحجز وتعديل وتشغيل وتقارير خاصة به.

هذه الوثيقة تكمل [تحليل بدء الشركة](93_new_company_onboarding_analysis.md) و[خطة التصميم](91_classic_pms_design_plan.md)، ولا تستبدل [الأساس](01_baseline.md) أو [قرارات النطاق](23_v1_decisions.md). معرفات SET أدناه محلية لهذه الخطة، وليست مراحل P جديدة ولا بديلاً عن CAP/AT/D.

## 2. تحسين التصور قبل التنفيذ

### لغة الواجهة

| المصطلح للمستخدم | المقصود |
| --- | --- |
| الشركة | الحساب الإداري والتجاري وحد العزل |
| المنشأة | الفندق أو المنتجع أو المجمع الذي له سياق تشغيل |
| تنظيم الموقع | مبانٍ ومناطق وأدوار اختيارية |
| الوحدات | الغرف والفلل والشقق والخيام والمواقع والأسرة القابلة للحجز |
| المساحات الداخلية | غرف نوم وصالات وحمامات للتجهيز؛ لا تصبح مخزوناً للبيع تلقائياً |
| طريقة التأجير | كاملة، أجزاء، كاملة أو أجزاء، أو سرير مشترك |
| فئة الإقامة | وحدات متكافئة في الوعود الأساسية للضيف |
| الأسعار والشروط | خطط السعر والإلغاء ومدة الإقامة |

لا نظهر Resource/Composition/Exposure في المسار الاعتيادي. تبقى شاشة متقدمة للمتخصصين مرتبطة بالكيانات نفسها، وليست نظاماً موازياً.

### الفصل الضروري

1. الاحتواء والموقع: أين توجد الوحدة؟
2. المخزون والحصرية: ماذا يمنع الحجز بيعه لغيره؟
3. التشغيل: ماذا ننظف ونفحص ونسلم؟
4. الوعد التجاري: هل يشتري الضيف فئة أم وحدة بعينها، وما المواصفات المضمونة؟
5. التسعير: ما الذي يحسب عليه السعر؟ لا ينشئ السعر مخزوناً جديداً.
6. الملكية: من يملك الوحدة ومتى يحق إدارتها؟ مستقلة عن عضوية الشركة وعن المكان.

الشجرة مناسبة للموقع والاحتواء. التركيبات والتعارضات علاقات مقيدة خارج الشجرة؛ يمنع الدوران وتكرار المورد داخل الخطة. لا نسمح بتركيب اعتباطي غير مفحوص.

### سياسات قوالب بسيطة

| القالب | الافتراضي المقترح | خيارات متقدمة |
| --- | --- | --- |
| غرفة / كوخ / خيمة ثابتة | تأجير حصري لوحدة | تجهيز King/Twin، فئة أو رقم محدد |
| فيلا / شقة | كاملة فقط؛ المساحات الداخلية للتشغيل | أجزاء مستقلة أو كامل/أجزاء بعد فحص الخصوصية والوصول |
| غرفة مشتركة | بيع الأسرة مع نطاق مشاركة للغرفة | بيع الغرفة كاملة عبر الأسرة نفسها |
| موقع تخييم / كرفان محدد | موقع واحد حصري | أبعاد وتوصيلات وشروط أهلية |
| جناح متصل | تركيبة من وحدات محددة | بدائل محدودة مثبتة، لا مجرد تجاور |
| منطقة / منشأة كاملة | عرض مركب معرف ومؤرخ | مجموعة حجوزات بأوقات وصول مختلفة |

الفيلا الخاصة التي تفتح غرفتين من أربع تحجز نطاق الفيلا كله. عدد الغرف المفتوحة يحدد الخدمة أو السعر ولا يحرر الغرف الأخرى.

## 3. ما راجعناه في التطبيق وما يحتاج تدقيقاً

| الدليل | الملاحظة | العمل المطلوب |
| --- | --- | --- |
| `apps/web/src/property/PropertiesPage.tsx` | إنشاء منشأة من نموذج يتضمن التوقيت والعملة، ونداء createProperty | تحويل الدخول إلى معالج دون افتراض أن كل منشأة في التوقيت الافتراضي |

| `apps/web/src/api/property.ts` | نقطة تكامل الواجهة مع المجال | جرد العقود وإعادة استخدامها ثم إضافة عقود المعالج عند الحاجة |
| docs/93 | تحليل سابق لفجوات إنشاء الشركة والمالك والجاهزية | إعادة التحقق من كل finding قبل اعتباره مفتوحاً في التنفيذ |
| docs/23 وdocs/24 | ضمان ذري وتركيبات مؤرخة وحدود بحث وحصص قنوات | الحفاظ عليها وعدم استبدالها بعدادات واجهة |

هذا فحص تخطيطي للملفات وليس تدقيقاً كاملاً أو نتيجة اختبارات. التعديلات المحلية غير المكتملة، ومنها المكتب الأمامي للمركبات، يجب جردها في SET-00 وعدم افتراض نجاحها من ملخص محادثة.

## 4. رحلة إنشاء المنشأة الجديدة

### المدخل

- داخل شركة مخول لها: زر «إضافة منشأة».
- من مسودة: «استكمال الإعداد» يفتح آخر خطوة محفوظة.
- بلا شركة/عضوية: رحلة حساب ودعوة منفصلة وفق docs/93؛ لا ننشئ شركة ضمنياً مع كل منشأة.
- النسخ من منشأة موجودة ينسخ إعدادات مختارة فقط؛ لا نزلاء ولا حجوزات ولا أرصدة ولا مفاتيح قنوات أو منح أعضاء.

### الخطوات

| الخطوة | البيانات الأساسية | السلوك ومعيار الخروج |
| --- | --- | --- |
| 1 — تعريف المنشأة | الاسم، البلد/الموقع، نوع أو عدة أنواع، التوقيت، العملة | اقتراحات قابلة للتأكيد؛ لا تخمين صامت للتوقيت أو العملة |
| 2 — الوحدات | قالب، أسماء/أرقام، عدد، سعة، موقع اختياري | إنشاء منفرد أو دفعة، استثناء أرقام، كشف التكرار ومعاينة |
| 3 — طريقة التأجير | الحصرية، مشاركة الأجزاء، فئة/وحدة محددة، المواصفات المضمونة | ملخص واضح لكل قالب؛ تظهر فقط الأسئلة ذات الصلة |
| 4 — التشغيل | الوصول والمغادرة، التجهيز والفحص، جاهزية الوحدات، إغلاقات معروفة | تنظيف وصيانة وتوفر حالات منفصلة؛ لا تعيين CLEAN جماعياً بلا اختيار صريح |
| 5 — الأسعار والإعداد المالي | خطة سعر وفترة قابلة للبيع وسياسة أساسية، وإعدادات مالية لازمة | النواقص المتقدمة تحفظ كمهمات؛ لا ملف ضريبي مزيف أو قيم مالية مفترضة |
| 6 — المراجعة | الشجرة والأعداد والعروض والتعارضات ومحاكاة البيع | مراجعة المخزون والأسعار والصلاحيات والنواقص قبل طلب الجاهزية |

للمنشأة البسيطة تدمج الخطوتان 2 و3 بصرياً، وتظهر الإعدادات المعقدة في «خيارات إضافية». يدعم المعالج الحفظ والخروج والرجوع دون فقد البيانات. السعر يمكن تأجيله أثناء الإعداد، لكنه مطلوب للمنتج والفترة المراد فتحهما للبيع.

النتيجة لا تكون زر «تفعيل الكل». الإجراءات المنفصلة: حفظ الإعداد، التحقق من الجاهزية، فتح نطاق بيع محلي مصرح، وربط/تفعيل قناة بعد أدلتها. جاهزية التهيئة ليست قبول إنتاج ولا تتجاوز EX/G-13.

### الحالات وتجربة الفشل

- حالات المعالج المقترحة: مسودة، قيد التحقق، يحتاج معالجة، مكتمل الإعداد. لا تستبدل آلياً lifecycle الخاص بالمنشأة.
- الحفظ التلقائي يبين «جارٍ الحفظ / حُفظ / تعذر الحفظ»؛ لا يوحي بنجاح عند انقطاع الشبكة.
- لا تأكيد مخزون offline. إعادة الإرسال تستخدم مفتاح تكرار ثابت للعملية.
- إذا عدّل مستخدم آخر المسودة، يظهر تعارض نسخة مع مقارنة؛ لا يفوز آخر حفظ بصمت.
- خطأ الحقول يظهر بجانبها ومع ملخص ينتقل إليه تركيز لوحة المفاتيح.
- الصلاحيات يعاد فحصها في الخادم عند كل حفظ وتنفيذ؛ فقد العضوية لا تلتف عليه مسودة قديمة.

## 5. معالج إضافة الوحدات داخل منشأة قائمة

1. اختيار قالب أو نسخ نموذج.
2. الأسماء والأرقام والدفعة والموقع.
3. السعة والتجهيز والوعد التجاري.
4. طريقة التأجير ونطاق الخصوصية.
5. معاينة الإنشاء وأثره في المخزون والتقارير.
6. تنفيذ وحالة نتيجة قابلة للاستئناف.

أمثلة إلزامية: غرف 101–116 باستثناء 113؛ ثماني فلل ثلاث غرف مع تعديل واحدة؛ شقة خاصة بغرف مغلقة؛ غرفة نُزل ستة أسرة؛ خيمة ثابتة؛ جناح من غرفتين متصلتين.

الإضافة الجماعية الصغيرة تنفذ بمعاملة واحدة ضمن حدود مقاسة. الدفعات الكبيرة تستخدم مهمة موثقة قابلة للاستئناف؛ يظهر نجاح/فشل كل مجموعة، ولا تصبح الكيانات الناقصة قابلة للبيع. لا محاولات تنظيف تلقائي تحذف سجلات ارتبطت بحجز أثناء التنفيذ.

محاكاة المراجعة لا تنشئ حجزاً حقيقياً: «بيع فيلا 1 كاملة يمنع الغرف أ/ب/ج؛ بيع أ يمنع الكامل ويبقي ب/ج حسب سياسة المشاركة». الاستيراد يستخدم dry-run مع تحقق كامل ونسب صفوف إلى مصدرها قبل apply.

## 6. صفحة الإعدادات بعد الإنشاء

| القسم | المحتوى |
| --- | --- |
| نظرة عامة | حالة الإعداد، النواقص، تغييرات مجدولة، إجراء متابعة |
| الوحدات والموقع | شجرة وبحث وجدول/بطاقات، دفعات، ترتيب مخصص |
| طرق التأجير | فئات وتركيبات وخصوصية ومعاينة أثر الحجز |
| التشغيل | التوقيت وأوقات الدخول والخروج والتنظيف والصيانة |
| الأسعار والسياسات | فترات البيع وخطط السعر والسعة والشروط |
| المالية | إعدادات المنشأة الضرورية، بحدود النموذج المالي الحالي |
| الفريق والوصول | نطاقات صلاحيات المنشأة، مع إدارة العضوية على مستوى الشركة |
| القنوات | جاهزية كل اتصال ومطابقته وأدلته، بلا أسرار في العرض |
| سجل التغييرات | من غيّر ماذا، تاريخ السريان، والنتائج |

يظل سياق المنشأة المختارة واضحاً عند دخول صفحات إدارة الشركة. بيانات المنشأة لا تعرض على أنها بيانات الشركة. مفاتيح التخزين المؤقت تشمل tenant/property، وتغيير السياق يلغي/يتجاهل الردود المتأخرة للسياق السابق.

## 7. قواعد التصميم والتفاعل

- الحفاظ على النظام البصري القائم مع تحسين الوضوح: سطح هادئ، كحلي للعناوين، تمييز محدود، حالات مكتوبة مع رموز؛ اللون وحده غير كافٍ.
- إجراء رئيسي واحد لكل خطوة: «متابعة»؛ حفظ وخروج كإجراء ثانوي، والرجوع منفصل. الأفعال الخطرة في قائمة مع أثر واضح.
- شجرة الموقع تتحول إلى اختيار متدرج على الهاتف؛ لا جدول عريض مصغر.
- الجدول يبدأ بالاسم والموقع وطريقة التأجير والسعة والحالة؛ المعرّفات التقنية في التفاصيل.
- حجم صفحة افتراضي مقترح 25 صفاً، مع بحث وفرز وتصفية خادمية عند الحاجة؛ لا تحميل جميع الغرف والتراكيب عند فتح الصفحة.
- ارتفاع صف أساسي مقترح 48–56px، قابل لزيادة المحتوى وتكبير الخط؛ لا قص معلومات حاسمة.
- RTL حقيقي، تواريخ وأكواد باتجاه مناسب، أسماء طويلة، لوحة مفاتيح وقارئ شاشة وتركيز ظاهر؛ هدف WCAG 2.2 AA يحتاج تحققاً ولا يعتبر شهادة.
- تحميل تدريجي لكل قسم، عدم تكرار جلب بيانات ثابتة، وإظهار تقدم الدفعات. لا مؤشرات اكتمال وهمية.
- عدادات منفصلة للوحدات/غرف النوم/الأسرة؛ لا جمع فيلا وأجزائها في مخزون إجمالي واحد.

## 8. التعديل والترحيل والحذف

| نوع التغيير | القاعدة |
| --- | --- |
| تسمية أو وصف | معرّف ثابت وتدقيق؛ تفاصيل الحجز التاريخية محفوظة |
| رقم أو موقع | تحقق من التكرار ومعاينة أثر التشغيل؛ لا تعديل التركيبة ضمنياً |
| سعة أو فئة أو خصوصية | تاريخ سريان وفحص الحجوزات والوعود المتأثرة |
| تركيب أو تقسيم/دمج | نسخة جديدة؛ فحص كل الالتزامات والتعرض الخارجي؛ لا تعديل الماضي |
| توقيت أو عملة أساسية بعد بدء التشغيل | ليس حقلاً عادياً؛ مسار تغيير متخصص أو رفض مع تفسير ضمن القيود الحالية |
| صيانة | Block/Disruption وفق المجال، دون محو حجز أو تحرير غير مثبت |
| أرشفة | تمنع البيع الجديد وتحفظ التاريخ؛ معالجة الالتزامات المستقبلية أولاً |
| حذف | مسودة خالية فعلاً من العلاقات فقط، بفحص خادمي؛ لا حذف بحسب الاسم أو غياب حجوزات ظاهرة |

ترحيل الموجود: جرد read-only → اقتراح تصنيف دون استنتاج الخصوصية من الاسم → مراجعة أثر → dry-run → نسخة احتياطية وخطة رجوع مجربة → تحويل على دفعات بإصدارات ثابتة → مطابقة قبل/بعد. ممنوع إعادة توليد IDs أو إنشاء مخزون مزدوج. المنشأة ذات الإعداد الناقص تعرض نواقصها؛ لا يعطل تشغيلها الجاري تلقائياً بمجرد إطلاق الواجهة.

الرجوع يعيد الواجهة/القراءة المتوافقة. لا يحذف حجوزات أو قيوداً جديدة ولا يعيد قاعدة قديمة فوق تشغيل لاحق؛ تغييرات البيانات تعالج بتصحيحات موثقة عند وجود نشاط.

## 9. حزم التنفيذ والتبعيات

كل الحزم أدناه NOT_STARTED؛ وجود الخطة ليس بدء تنفيذ. هي حزم تحسين مرتبطة بالمراحل الحالية، ولا تعيد ترتيب P0..P14.

| الحزمة | الناتج وحدود العمل | تعتمد على | بوابة التسليم |
| --- | --- | --- | --- |
| SET-00 | جرد الكود والتعديلات المحلية والاختبارات، مصفوفة موجود/ناقص لكل قالب | لا شيء | تقرير أدلة، سيناريوهات خط أساس، قائمة فجوات بلا ادعاء دعم |
| SET-01 | نموذج تفاعلي للمعالج والإعدادات، مع رحلة بسيطة وأخرى مركبة | SET-00 | مراجعة مهام: إضافة فندق، فيلا خاصة، فيلا أجزاء، استئناف مسودة |
| SET-02 | عقود المسودة والتحقق والمعاينة والجاهزية وحدود الدفعات والعزل | SET-00/01 | عقد API وأخطاء وصلاحيات وخطة ترحيل؛ توثيق القرارات التي تتجاوز الحالي |
| SET-03 | رحلة إنشاء المنشأة الأساسية وحفظ/استئناف، وإعادة استخدام الخدمات | SET-02 | فشل الشبكة والتكرار وتعارض النسخ لا تنشئ منشآت مكررة |
| SET-04 | قوالب غرف/فلل خاصة/شقق/خيام ومواقع محددة، ودفعات | SET-03 | نتائج الإنشاء توافق المعاينة؛ غير المكتمل غير قابل للبيع |
| SET-05 | الكامل/الأجزاء والأسرة والجناح المتصل مع محاكاة حصرية | SET-02/04 | اختبارات التداخل والاستمرارية والتزامن ونسخ التركيب |
| SET-06 | تنظيم الإعدادات والتغييرات المؤرخة والترحيل التدريجي | SET-04/05 | مطابقة IDs/التزامات/حصص قبل وبعد، ورفض التغيير غير الآمن |
| SET-07 | إكمال المكتب الأمامي والتدبير والتقارير لكل قالب مدعوم | SET-05/06 | دخول/خروج جميع مكونات الحجز، وأثر النقل/التمديد واضح ومختبر |
| SET-08 | جاهزية خادمية وأداء وإتاحة ولغات ومراجعة مستقلة | SET-03..07 | أدلة قبول محلية، لا ادعاء إنتاج أو قناة حية |
| SET-09 | دليل مستخدم وتدريب وتجربة pilot ونشر تدريجي عند التفويض | SET-08 والبوابات الخارجية اللازمة | سيناريوهات تشغيل واقعية وقرار قبول منفصل |

في SET-07: أي عملية مركبة غير مدعومة تظهر بسبب واضح ومسار معالجة؛ لا زر يغيّر مكوناً واحداً ويوحي بتعديل الفيلا كلها. لا نعلن القالب مكتملاً إذا كانت عملياته الأساسية محجوبة.

الأدوار المطلوبة في التنفيذ: مسؤول منتج يراجع سير العمل، مصمم يختبر قابلية الاستخدام، مطور واجهة، مطور مجال/بيانات، ومراجع مستقل للمخزون والعزل. يمكن للشخص نفسه أداء أدوار تنفيذ متعددة؛ المراجعة المستقلة لا تعتمد فقط على أدلة المنفذ. لا تقدير زمني ملزم قبل SET-00/02؛ تحسب التقديرات لكل حزمة بعد معرفة الهجرات والفجوات.

يبقى بعد الإطلاق وفق النطاق الحالي: بالساعة والنهاري (D-07)، تسويات الملاك والأنشطة (D-09)، المراسلات (D-15)، وأي نموذج جديد للتخييم الحر أو إيجار سكني متخصص. يمكن حفظ احتياجاتها في backlog، دون إظهارها قدرات عاملة. تحويل D-20 إلى عرض متزامن متنافس ليس تحسين واجهة ويحتاج قراراً مستقلاً.

## 12. بوابة الإنجاز والتسليم

- وثائق وعقود ومهاجرات متوافقة بحسب الحزمة؛ لا تكرار خفي لمحرك المخزون.
- اختبارات مخزون وعزل وتزامن ملائمة للتغييرات؛ لا إعادة كل الأطقم بلا سبب ولا قبول ببصريات وحدها.
- اختبارات واجهة فعلية للمسارات الأساسية والمركبة وفشل الشبكة.
- قياس الأداء واستعلاماته، وفحص إمكانية الرجوع وخريطة البيانات القديمة.
- دليل عربي مختصر لكل قالب مع صور وشرح أثر طرق البيع.
- تقرير بما نجح وما بقي غير مدعوم. البوابات الخارجية وG-13 لا تتغير بنتائج محلية.
- قبل التنفيذ يقرأ المنفذ هذه الخطة والمراجع الحاكمة، يبدأ SET-00، ويسجل الحزمة والأدلة والقرارات، ولا ينفذ كل الميزات المتخصصة تحت اسم «دعم جميع العقارات».
