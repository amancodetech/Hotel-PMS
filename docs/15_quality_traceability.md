# ضمان الجودة والتتبع

حالة: خطة تحقق للمنتج مع اختبارات أساس المرحلة 1 المنفذة فقط وفق docs/29_phase1_verification.md. ملفات tests/foundation وtests/api وtests/dependencies وtests/web تغطي G-01، وscripts/integration وscripts/testcontainers تختبر الخدمات المحلية. لا تتحول AT للمخزون أو الهوية أو المال أو القنوات إلى PASS بسبب نجاح هذه الاختبارات. Computer Use غير منفذ؛ JSDOM ليس بديلاً بصرياً.

## مستويات التحقق

Unit/Domain للحسابات والحالات، Integration على PostgreSQL حقيقي للعزل والمعاملات، API للهوية والأخطاء، E2E للمسار الفعلي، Concurrency بحواجز بدء متزامنة، Security للملفات والJobs والتصديرات، Recovery بعد فشل وإعادة تشغيل، Performance ضمن أحمال معلنة.

لا يكفي Mock لإثبات RLS أو التزام مركب متزامن. استخدم Fixtures synthetic تمثل Tenants متشابهة IDs نسبياً، Property متعددة، فيلا وغرف وأسرّة ومجموعة، ليلة انتقال زمنية، فاتورة بعملة لا تفترض منزلتين دائماً.

## أدلة القبول

تفصيل ربط التنفيذ بالأدلة موجود في [حزم العمل](32_execution_work_packages.md)؛ كل صف يحدد اختبارات AT التابعة وشرط الفشل والبوابة. لكل حالة: البيئة والنسخة والبيانات التجريبية وGiven/When/Then والنتيجة وأثر DB/الأحداث ومرجع العيب. يجب أن يثبت اختبار التعارض الحالة النهائية لا مجرد HTTP status. يثبت retry عدم تكرار المورد والرسوم والإرسال الفعّال معاً. تقارير المقارنة تستخدم نفس النطاق والوقت.

Performance يعلن عدد الموارد والمركبات وعمق وتداخل التركيب وعدد الحجوزات والمستخدمين ونافذة البحث؛ لا تعميم نتيجة فندق بسيط على آلاف الموارد. توضع حدود المنتج بناء على الاختبار لا اختراع أرقام معتمدة.

بوابة الإنتاج: عزل/مال/تزامن/Restore/تشغيل/UX حرجة ناجحة ولا عيب حرج غير معالج. كل Module يحقق Definition of Done في baseline.
