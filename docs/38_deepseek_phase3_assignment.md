### 2. أغلق عيوب المرحلة 2 أولاً

نفذ R1..R6 وفق تفاصيل السبب والأثر وقبول الإصلاح في docs/37، دون إعادة تصميم المشروع:

- R1: fencing وملكية ذرية للمحاولة، وانتهاء lease أثناء الإرسال أو انتظار الدفعة؛ امنع نتائج العامل القديم من الكتابة.
- R2: حجز ACK دائم، recovery للمحاولة المهجورة، retry/backoff/Retry-After، واستثناء دائم عند الاستنفاد، دون إعادة أثر revision.
- R3: UNKNOWN بعد الإرسال أو احتماله؛ NOT_SENT فقط بدليل قبل الإرسال، بما يشمل invalid JSON/oversize/reset.
- R4: local-only افتراضياً ومنع أي مضيف خارجي حتى إن كان allowlisted؛ لا تفعل live ضمن هذا التكليف.
- R5: لا تحفظ تحذيرات المزود الحرة أو PII أو PAN في response_safe/logs/DLQ؛ استخدم أكواد وحقولاً مسموحة.
- R6: أخطاء التحضير الدائمة تحفظ وتعزل، والمؤقتة تعاد بحد؛ لا poison دائم بلا عداد أو تشخيص ولا تجويع لاتصال سليم.

اكتب regression يفشل على النسخة السابقة ويتحقق من السلوك الصحيح، لا من تفاصيل تنفيذ مكررة. ملف `.local/verification/review-p02/reproduce.mjs` إن وجد يثبت العيوب القديمة؛ لا تجعل نجاح assertions التي تتوقع العيب شرط نجاح الإصلاح.

استخدم PostgreSQL حقيقياً لقفل وتزامن ودوام الرسائل، وخادماً محلياً لحالات HTTP. لا تعطل اختبارات موجودة لتنجح النتيجة. أضف migrations جديدة للترقية عند تغيير مخطط مطبق، واختبر قاعدة جديدة وأخرى ببيانات اصطناعية من المرحلة السابقة. لا تمس قاعدة التطوير بـTRUNCATE أو قواعد ثابتة غير مثبتة الملكية؛ استخدم قواعد مؤقتة فريدة يملكها الاختبار.

### 3. نفذ المرحلة 3 بالترتيب بعد استيفاء الشرط

التفويض يشمل P03-01..06 كاملة، فلا تعاود طلبه بين الحزم. اعمل حزمة واحدة في كل دورة؛ اكتب قبلها نطاق الملفات والعقود واختبارات النجاح والرفض والتبعيات، ثم نفذ واختبر ووثق قبل التالية.

**P03-01: المصادقة والجلسات.** OIDC عبر API مع Keycloak المحلي وجلسة خادمية، login/logout، state/nonce/PKCE عند انطباق التدفق وredirect allowlist، تحقق issuer/audience/التوقيع/الانتهاء بمكتبة مدعومة. لا tokens في localStorage. حماية cookie/CSRF/CORS وانتهاء وإبطال وتدوير الجلسة؛ وثق فرق localhost HTTP عن إعداد HTTPS الآمن دون إضعاف قواعد الإنتاج. أثبت MFA بإشارة موثوقة من موفر الهوية للأفعال الحساسة، لا بقيمة يرسلها المتصفح. تشغيل Keycloak وحده ليس اكتمال المصادقة.

**P03-02: العضويات والأدوار.** User/Tenant/Membership/Role/Grant/Approval والدعوات والإبطال وحماية آخر مسؤول مؤهل، وكتالوج أكواد صلاحيات ثابت. المنع افتراضياً والرفض الصريح يسبق السماح. لا role-name checks ولا دمج صلاحية مالية في A مع نطاق دور تشغيلي في B. تحقق من سلطة التفويض لا مجرد امتلاك المستخدم للصلاحية. حسم TENANT scope صريح وعدم الثقة بـtenant_id من المتصفح.

**P03-03: عزل قاعدة البيانات.** دور migrations منفصل عن API/worker، أدوار تشغيل لا تملك الجداول ولا SUPERUSER/BYPASSRLS، RLS فعلي وسياسات read/write وWITH CHECK وFORCE RLS حيث يفرض التصميم. سياق موثوق transaction-local وتنظيفه مع pool والrollback. اجرد جميع جداول distribution الاثني عشر والجداول الجديدة؛ إن كان النطاق غير مباشر عبر علاقة فوثق مسار السياسة واختبره، ولا تترك جدولاً تابعاً خارج العزل. أكمل مراجع Tenant الآن؛ Property/Product/GrantProperty في P04-04، RatePlan في P05-01، Reservation في P06 وفق سجل التبعيات. لا تنشئ جداول أعمال وهمية لتسهيل FK.

**P03-04: التفويض والتدقيق.** policy evaluator في Application يغطي العضوية والمنح والنطاق والمورد والحالة؛ هوية خدمة محدودة للاتصال مستقلة عن منشئه، وJob بشري يعاد التحقق من صلاحيات صاحبه عند التنفيذ. منع اعتماد الذات ولو بدور آخر، وربط الاعتماد بـhash/version/عملة عند انطباقها، ودعم مؤقت مسبب محدد المدة والصلاحيات دون bypass عام. نفذ أساس الاعتمادات دون بناء المال أو المخزون، واستخدم حالات اصطناعية لاختبار العقود المستقبلية.

**P03-05: الواجهة وعقودها.** دخول واختيار Tenant وإدارة عضويات وأدوار ومصفوفة منح ونطاق، مرتبطة بـAPI فعلي. تغيير العميل يمسح query cache المتعلق به. ar/id-ID/en-US وRTL/LTR، ورسائل أخطاء وحالات انتظار وانقطاع ومنع وصول واضحة. لا شاشات حجوزات أو غرف أو قنوات وهمية، ولا تعرض أسماء أدوار بوصفها بديلاً عن الإذن الفعلي. اختبارات نطاق Property اصطناعية حتى المرحلة 4 ولا تقدم إدارة منشآت مكتملة.

**P03-06: القبول.** اختبارات عزل read/write/bulk/jobs/cache/audit، الجلسات وMFA وCSRF والإبطال والتصعيد والدعم المؤقت، وفحص الواجهة، وتقرير G-03. اختبارات ملفات/export/search والوحدات غير المنفذة تبقى DEFERRED مع الحزمة التي ستعيد اختبارها؛ لا تسجل نجاحاً مسبقاً.

### 4. ثوابت التنفيذ

حافظ على Stack D-12 وModular Monolith وحدود Application/Domain/Persistence وعلى العقد المحايد للمزود وD-20. لا Redis لضمان المخزون ولا منطق أعمال في Controllers ولا استبدال نظام الهوية بمصادقة منزلية. PostgreSQL مصدر دوام الرسائل وBullMQ قابل لإعادة البناء. UNKNOWN وPARTIAL ليسا نجاحاً، وقبول المزود ليس إثبات القناة.

قبل كل endpoint أكمل عقد request/response/errors/permissions/CSRF/idempotency حيث يلزم؛ حافظ على operationIds ولا تقدم ردود نجاح شكلية. لا تضف abstractions أو تبعيات غير لازمة. لا تنقل خطأ مرحلة 2 إلى مرحلة لاحقة لمجرد قرب نهاية الجلسة. كل استثناء أو عائق له سبب ودليل وخطوة إزالة واضحة.

لا أسرار أو بيانات حقيقية في الكود أو screenshots أو logs. الدعوات محلية ضمن اختبار بلا إرسال بريد خارجي. لا تفعل هوية مؤسسة خارجية أو خدمات سحابية. امتثل لموافقات البيئة التقنية ولا تتجاوز sandbox.

### 5. التحقق الملزم

أعد build/typecheck/lint/format/contracts/tests عبر `pnpm check`، واختبارات التوزيع والمهاجرات والتكامل المتأثرة. اختبر جداول P02 بعد RLS بدور التشغيل المحدود، ولا تستخدم bootstrap أو superuser دليلاً على العزل. يجوز لدور إعداد الاختبار تجهيز البيانات فقط؛ الاستعلام محل القبول يجب أن يعمل بدور التطبيق.

أثبت عميلين ومنشأتين: قراءة وكتابة ونطاق ID متغير وbulk وJob، اتصال pool نفسه بالتتابع وبعد rollback، غياب السياق، إبطال عضوية قبل الطلب التالي وقبل Job، مستخدم مالي في A وتشغيلي في B، دعوة منتهية ومعاد استخدامها، وآخر مسؤول، وMFA/CSRF الغائبين أو غير الصالحين. اجعل تأمين auth نفسه قابلاً للاختبار دون كشف أسرار عند فشل Keycloak/Redis/DB.

فحص الواجهة: المستخدم اعتمد Playwright + Chromium بديلاً عن Computer Use غير المتاح. استخدم المتصفح المحلي فعلياً بالنقر والكتابة والتنقل، وصوراً للغات الثلاث وأحجام 1440x900 و1280x800 و390x844 و320x740، مع keyboard/focus وعدم تداخل أو تمرير أفقي غير مقصود. اختبر الدخول والخروج وMFA وحالات الرفض وتبديل العميل وحفظ اللغة بعد reload. لا تسجل ما لم تنفذه، ومحاكاة الجوال ليست جهازاً حقيقياً. لا تضع كلمات مرور أو QR/TOTP أو tokens في الصور.
